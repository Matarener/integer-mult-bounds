# Positive-hint soundness and the exact trust boundary

Let F be the parsed DIMACS conjunction. Every live database clause initially belongs to F, with its one-based file ID. Maintain the invariant that F entails each live clause. To add C, assume every literal of C false. At each indicated live clause, reject a satisfied clause or two or more unassigned literals. A unit reason forces its sole open literal true. A zero-open-literal reason is a conflict and must be the last hint. Induction over this list shows that every model of F falsifying C would satisfy an impossible final clause. Thus F entails C. Deletion only weakens the available database and preserves the invariant. A successfully derived empty clause implies F is unsatisfiable.

This implementation accepts a strict positive-hint subset: RAT negative hints, binary formats and tautological additions are unsupported and rejected. Duplicate literals have set semantics. Addition IDs are strictly increasing beyond the initial clause count; each hint must refer to a live clause, so no circular or future dependency is possible. All records are consumed, including records after the empty addition (only legal deletions are allowed), and finite limits apply to source bytes, decompressed bytes, lines, variables, live clauses, additions and hints. The empty derivation remains valid if its clause is subsequently deleted.

The conversion program and original proof producer can be entirely wrong without defeating this implication: successful replay uses only the pinned CNF and the actual checked hint file. Container hashes bind exact bytes; no success string, generator count or retained execution receipt substitutes for replay. Independent tiny tests evaluate CNF truth tables and decisive malformed/semantic cases. These tests and this argument do not formally verify Python or the checker.

The original paid-word semantics, lossless free-mixing normalization and support pruning are separate credited dependencies. A full minimum-nine statement must additionally assemble padding and the nine-call positive witness under exactly those premises. No physical compiler, caller, cleanup, routing, precision, stock, supplier or outer multiplication theorem follows here, and selected kappa is unchanged.
