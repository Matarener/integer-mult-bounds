# Scope and engineering inspection

Build the Lever led to machine.py, a rerunnable sequential cell interpreter, and checks.py's separately derived exact operation/cell invoice. Prove It Works required real optimized CLI corruption controls and final committed Git-free replay. Separate Before Serializing Shared State led to one private package/output directory, process-held worker ownership and short shared Git/task-selection advisory locks.

The changed call graph is verify.main -> checks.receipt -> authenticated predecessor loading, generic/header/wide/boundary checks -> machine.encode/execute -> initialize/interpret/clear_private/rewind -> Tape.read/write/move. The predecessor compiler/evaluator is a pinned, unchanged premise and comparison. No other runtime research source is imported. The complete proof premise is pinned separately in SOURCES.json. No frozen input is edited.

All ten Power of Ten inspections were applied:

1. The machine and verification paths use structured loops, returns and exceptions without recursion. A valid admitted run cannot reach an exhaustion exception. Malformed input rejects before allocation. Unexpected interrupted/corrupted execution has no rollback guarantee and is outside the successful-return theorem. No resource or process persists after verification.
2. The entry boundary caps A at 4,094, B at 4,096, encoded program length at 2,000,000, and compiler gate/output lists at 4,096. Each execution loop is capped by one allocated tape extent. Unary parsing is capped by the current wire count. The scientific fixture loops have fixed explicit ranges and seeds. Boundary controls exercise oversized program/address and exhausted wire capacity. Actual CLI children have 120-second timeouts; VERIFY bounds the complete commands at 120/300 seconds.
3. Tape storage is allocated before initialization with exact extents L, A+2, B+2, Q+3. The cells never grow during execution. The managed Python runtime allocates integers, temporary strings and instrumentation objects while simulating primitives. This is a deviation from a no-allocation runtime, bounded by admitted L/B/Q and four tapes. The written finite-control algorithm, rather than Python heap storage, defines the physical model. Follow-up for an actual caller is the production fixed-tape library join, with measured owned buffers and supplied control construction.
4. Every changed function is below 60 physical lines. test_controls.main is the largest at 48 lines. No helper exists merely to hide a long expression or mutable ownership.
5. Normal exceptions enforce argument, topology, exact length, arithmetic, return-state and operation-count invariants even under optimization. No Python assert is used. Ten original malformed inputs and three resource exhaustion controls reject; generic truth tables and real CLI semantic mutations exercise nontrivial checks.
6. Execution state is local to one invocation. Borrowed Tape objects reject writes. Only the primitive cell interface uses indexed storage during execution; the rest of the algorithm reads tape symbols and moves one cell. Host extent/cost observations and loop exhaustion guards are explicitly outside the simulated instruction tally. The final result observer reads the completed tape and does not produce machine output.
7. Every subprocess return status and diagnostic is checked, with no shell. Copies use exclusive regular byte files and check complete writes, UID and inode disjointness. All borrowed heads and private blankness are checked. The trusted predecessor module is authenticated before loading. Source reads are capped at 8 MB; exact pins constrain their valid contents. Python standard-library allocation/read failures propagate.
8. No eval, generated Python or reflection controls execution. Dataclass construction and one importlib load of the authenticated fixed predecessor module are bounded runtime-mechanism deviations. The module name/path/hash and all possible call targets are explicit. Follow-up is a static module binding if the repository packages the predecessor as an importable library.
9. Runtime data access is shallow and direct. Imported predecessor methods and standard Python constructors are the bounded dispatch targets; no plugin or unbounded callback registration is present. The control tests invoke only the copied verify.py using the active interpreter. Temporary copies contain only known package/input bytes and deliberately defined mutations.
10. Verification uses CPython 3.12, -I -Werror -B, explicit -O controls, scoped Ruff E4/E7/E9/F, AST function-length inspection and whitespace checks. Repository-wide formatting/type changes are outside this package. The registered commands rerun the scientific and actual optimized control gates. Final committed-byte/history and official Git-free integrity checks are separate publication gates.

The host compiler/admission parser and Python emulator are not a bit-costed production shape-to-header implementation. Their allocations, hashing, compilation and output observation do not enter the exact executed tape-primitive tally. The proof charges supplied unary program space and gives a separate written construction bound. No stronger binary-index storage result, physical consumer, supplier, exact-recovery theorem or kappa follows from this module.
