# Engineering scope

Engineering-mode uses the investigation playbook. The explicit assignment allows
one kept research package. Separate Before Serializing Shared State gives this
worker its own branch, status, claim and cache. The common Git, semantic and
heavy-replay transactions use the prescribed OS locks. Prove It Works requires
actual committed read-only Git-free replay before evidence-ready. Unslop applies
to the prose. The same five workers provide scoped review; no extra agent,
thread, worktree or research round is created.

Power-of-ten inspection covers intervals.py, finite.py and verify.py. Control
flow is structured and nonrecursive. Log reduction uses at most seven steps,
atanh uses96 terms, exponential uses24 terms, profiles have at most16 ranks,
source/evidence inventories have at most16 entries, source inputs are capped
at16MiB, providers/orientations each have exactlytwo entries and the finite
symplectic product has36 factors. Functions remain below60 physical lines.
Explicit ValueError contracts survive optimization and reject Boolean counts
and nonboolean finite guards. The verifier writes no files or shared state,
uses no network or subprocess, and exposes no mutation capability to inputs.
Exact rational arithmetic supplies all acceptance signs. Source hash checks
precede source execution; canonical JSON comparison preserves type distinctions.

Rule3 managed-runtime deviation applies to Python/Fraction allocation. The
bounded domains above bound live data. A fixed-allocation arithmetic runtime
would expand this bounded audit. Normal/optimized and second-interpreter runs
check the same complete workload. There is no long-lived steady-state service.

Rule8/9 deviation is confined to compile/exec of one existing selected outer
engine with its exact source SHA256 authenticated first. This explicitly reuses
that engine rather than claiming independent analytic verification. No source
module chosen by an input is loaded, no bytecode cache is read for it and no
new generated code is introduced. Replacing it is justified only for a separate
independent outer proof, outside this package's claim.

Rule10 uses AST parsing and Python warnings as errors. No linter is installed in
the existing runtime, so no linter success is claimed and no shared installation
is changed. All commands and observed outcomes are recorded with committed and
export evidence. Read-only inherited construction code is retained unchanged.

The scoped source-authentication correction binds the fixed source-manifest
bytes and an integer-only version before following its rows. The outer engine
receives immutable authenticated bytes rather than a path to reread. The new
test_source_auth.py uses three actual optimized CLI rejection controls. Each
creates only regular writable private copies, bounded by64 package files and16
external inputs of at most16MiB each. Each subprocess has a15-second timeout,
and its private temporary root is removed on every structured exit. The default
needs no environment variable; --work selects an existing private scratch parent.
This test-only subprocess/tempfile use is separate from the read-only verifier.
The original scientific freeze and first review receipt remain preserved.
