## Power of Ten inspection

1. Control flow is iterative, without recursive or callback call cycles.
   Failures propagate. Temporary CLI copies have a scoped lifetime.
2. The selector bounds e by 2^32-1, w by 32, dimension by 64 and rank strictly
   below dimension. Depth has at most 2048 steps. For the slowest contraction,
   every m steps reduce width by more than half; 64*32 steps suffice.
   Bisection permits at most e.bit_length()+1 steps. Sources/receipts are
   capped at 1 MiB/256 KiB. The exact input set has seven files. Selected
   digit certificates have at most 128 levels; generic stock certificates
   have at most 8192 bits. Independent thresholds permit 2048 steps and
   radix scans 8193. Census loops have 8*256*4=8192 cases. Brute k scans
   have at most 128 trials per case and 256 forward-depth steps. Each CLI
   has a 30-second timeout. Original width, atom width and digit-table caps
   are independent; their simultaneous maxima need not be admissible.
3. Python allocation requires the managed-runtime deviation below. Integers,
   lists and temporary copies have the preceding bounds. No payload,
   GL64 table or huge selected reserve is allocated.
4. Every function is below 60 physical lines. The function-length receipt
   records actual counts. Responsibilities remain separate and explicit.
5. ValueError contracts survive -O. They enforce capacities, integer types,
   table length/monotonicity, fit, stock and source/receipt invariants. The
   selector cannot prove a supplied digit table correct; its docstring states
   that caller obligation. Toy tables use exact powers. Selected tables use
   strict lower/upper product certificates.
6. Algorithm state is local and Plan is immutable. The only path setup is
   the resolved package directory required for isolated standalone Python.
7. Invalid input, source or receipt rejects explicitly. CLI status and success
   prefix are both checked. Digest updates intentionally return no value.
   Test file writes use complete Path writes; failures propagate. No public
   receipt-repair or overwrite option exists.
8. There is no generated code, dynamic evaluation or runtime registration.
   The dataclass decorator defines one fixed immutable result shape.
9. Imports name fixed local modules after inserting the resolved package
   directory. No predecessor executable is imported. There is no extensible
   dispatch registry. Standard-library calls have visible fixed ownership.
10. Validation uses -W error, -B, normal/optimized Python, scoped Ruff
    E,F,B,PLE,PLW,RUF at line length 100, and formatting checks. E402
    annotations document the fixed local imports after isolated-mode path
    setup. No repository-wide diagnostic configuration changes are made.

The initial combined maximum-e/maximum-w fixture exceeded the separate digit
capacity. initial-capacity-diagnostic.log retains the failure in the session
directory. Corrected controls exercise those maxima separately and reject
oversized digit tables. The scientific examples and receipt were unchanged.

## Explicit deviations

Rule: 3, fix memory capacity before steady operation.
Location: the four package Python files and their standard-library calls.
Reason: Python integers, JSON, dataclasses and tempfile allocate dynamically.
Scope: bounded host research replay, not the physical tape theorem.
Compensating control: enforced integer/table/file/case bounds, one fixture tree
and one synchronous CLI at a time, context cleanup, no payload materialization.
Verification: capacity success/rejections, normal/optimized replay, malformed
CLI failures and committed-export replay. Generic logarithm intermediates are
bounded by 8192*127 bits; other integer limits are explicit in code.
Follow-up: a Count-tape selector needs fixed roles, scan bounds and a complete
physical setup invoice before integration. These host bounds do not supply it.

Rule: 10, enable maximum diagnostics on every build.
Location: standalone replay and VERIFY.json.
Reason: this isolated package does not control repository-wide CI or lint
policy. Registered commands guarantee Python warnings as errors; Ruff
availability is an external development environment property.
Scope: scoped validation. No global recurring Ruff enforcement is claimed.
Compensating control: exact scoped Ruff checks, -O CLI controls and registered
warning-as-error commands.
Verification: diagnostic and registered/cold-replay logs retained in the session.
Follow-up: a shared recurring research lint policy requires a separate
repository-wide impact review.
