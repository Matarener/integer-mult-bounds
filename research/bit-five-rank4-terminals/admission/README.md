# Portable five-terminal chart and arithmetic supplement

Run with Python 3.11 or later and the standard library:

```sh
python3 -I -B verify.py
python3 -I -O -B verify.py
```

The script resolves every input relative to itself. It needs no old run,
repository checkout, Git, generated bytecode, third-party modules, or network.
`--write` deliberately replaces the local result receipt; normal runs compare
the recomputation against the shipped receipt. Run from any working directory.

The mathematical inputs are four files in `inputs/`: the five-terminal literal
word, its three terminal charts, the original R438 geometry, and the E8 root
skeleton. `source-context/` contains only five literal historical files used
to bind the envelope/invoice interpretation; they are hashed but never imported
or executed. Their dependency directories were not copied.

The checker authenticates all files listed in `INPUT-MANIFEST.json`, replays
the three coordinate charts and their inverses, computes the signed-word
positive envelopes and additive-defect bounds in both orientations, checks
the precision inequalities and retains the original negative controls. It
does not duplicate the independent full 660-column BIT operator audit.

## Mathematical result and domain

Each saved Q is orthogonal over Z[1/2], and its first four columns span the
specified actual rank-four terminal frame E. The literal programs prove

    D_E = diag(Q,Q) D_coordinate4 diag(Q^T,Q^T).

Q programs use 24,70,70 invertible coordinate primitives for frames506,508,509.
The complete 16-coordinate residual programs use 100,284,284 primitives. Their
alphabet is unit signed ADD, NEGATE, DOUBLE, HALF and SWAP. Every coordinate
input is arbitrary; no extra field element is used. The programs and their
exact inverses work over any Z[1/2]-module and hence every odd field. These are
coordinate-arithmetic costs, not recursive payload or physical tape tariffs.

The chart programs have maximum prefix denominators2 and infinity norms4,8,8.
The complete residual programs have maximum prefix denominators2,4,4 and
infinity norms4,10,10. These exact matrix bounds give reachable dyadic-grid
statements when the input is dyadic; they do not license approximate rounding.

The scalar word gives F=8402567, R=630744. The historical five-/nine-stage
expressions need114/211bits and fail104/192-bit caps. New multiples-of-64 charges
would be128/256. For the historical depth-two formula, writing C=P9+B and paid
child count E, the explicit sufficient premises B<2^210 and E<2^20 give a
two-level quantity with at most463bits, below512. No missing compiler invoice
is supplied by these sufficient bounds.

For the defect calculation, gauges are exact isometries of bounded functions,
scalar ADDs are exact, and each MOVE/COPY/ERASE may introduce an independent
destination error of norm at most delta. COPY and ERASE are extended as source
shears; private errors are never reset. Starting from zero errors, propagate

    ADD d += c s: e_d <- e_d + |c| e_s
    MOVE d:       e_d <- e_d + 1
    COPY/ERASE:   e_private <- e_private + e_source + 1.

The triangle inequality proves the resulting bound by induction. Maximum
prefix errors are at most662069 delta forward and47917 delta inverse; private
endpoint errors are bounded by3762 delta and36 delta. This compares with the
signed integer lift, whose clean BIT public endpoint is obtained only modulo2.
It is not a rounded implementation of the Boolean supplier. A nonzero COPY
defect survives exact source subtraction, so finite accuracy alone cannot
prove an exact ERASE. Actual rounded-child cleanup remains open.

## Provenance and adaptation

`provenance/` retains the authenticated transfer manifests, ownership receipt,
original checker and result, source-context pins and the copy authentication
record. Their absolute paths are historical metadata only; no runtime path is
taken from them. This preserves the original run's provenance without requiring
live ownership files to rerun the mathematics. Hash integrity is not a digital
signature or a proof of mathematical truth.

See `ADAPTATION.patch` for the complete eight exact text replacements and
`ADAPTATION-CHECK.json` for the source comparison. The original checker is
unchanged in `provenance/verify_admission.original.py.txt`. The 13 non-main
functions have identical ASTs; the main chart, defect, precision, invoice and
negative-control section is byte-identical. Only bundle-root discovery,
manifest authentication and four input locations changed. Provenance file count
and executing-script hash consequently differ from the old result; mathematical
result fields must agree exactly.

This supplement establishes finite exact coordinate programs and bounded
arithmetic diagnostics. Chronological owners, native routes, exact rounded
cleanup, storage/tape accounting, all-size dispatch and compatible joint moments
remain separate. No new kappa, formal-kernel replay, or native supplier admission.
