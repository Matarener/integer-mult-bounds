# Fresh carrier request to an executed completed child

This is a source-bound regional caller result, not production GL64 execution or
an admitted improvement in selected kappa. The new connection consumes the
**actual serialized child Program copied by preparation**. It executes both
coordinates of a complete rank-two child, protects its owned return, passes that
computed return to the carrier's literal next SOURCE87 consumer, then disposes
all newly owned metadata, payload and numerical work. The finite execution and
the full-parent address proof are distinct evidence layers.

## Produced-program bridge and proof

The existing `SelectedBinding.child_program` constructs the actual two-step
serialized child Program (root 2048 -> 64 -> 2). Preparation copies that Program,
the complete two-field directory, prefix count, unused-row count and all three
full-parent spectator extents. The candidate constructs `IncomingWeights` from
**the copied Program**, and `packet_engine.run` consumes **the copied directory**.
The copies are therefore used by execution, not merely compared and discarded.
A corruption control changes the second produced STEP rank from 2 to 3 and is
rejected as `actual selected rank` before a child payload result is produced.

The canonical internal `peel.run` rejects widths below 64. We preserve that
guard. The new completed-child bridge instead composes its unchanged `trace.leaf`
and `packet_engine.run` with the consumed child's incoming coefficient interface.
For the emitted GOOD child, the source, field 0, no-reverse/no-half tags and
current parent are fixed for all coordinates. Child-program construction
therefore does not depend on the coordinate. Converting a typed child coefficient
request to an incoming request against that produced Program is exactly the
same extension followed by the same whole-history callback. The finite bridge
checks the field and adapter tags, performs a charged encoded coordinate bound
check, and uses the original parent coefficient evaluator when that eligibility
check fails. Source Program and directory bytes and heads are verified immutable
through the whole child. This argument is restricted to this GOOD context; it is
not a theorem about general COPY/nonfixed ancestor histories.

There are **six fresh coefficient evaluations per coordinate**, twelve in all.
The values are `[2,2,1,1,2,2]` per coordinate, including negative inverses. All
incoming callbacks validate the full two-step ancestry. No three-call reduction
or fixed-PAIR CSE is used. The actual generated ancestry fails the fixed-PAIR
premise, so #4059 is deferred at this site.

Each coordinate uses the canonical eight-stage swap/ADD/sign word. For any
admitted unit lambda it realizes the weighted swap; here lambda=2 modulo 3 and
its inverse is also 2. Consequently the complete child pullback is

```
(x0,x1,g,y0,y1) -> (2*y1,2*y0,g,2*x1,2*x0) mod 3.
```

All 972 bits of the complete child with before/gap/suffix extents 2,3,2 are
executed through the real packet engine, including both coordinates and all
finite spectators. The expected permutation is independently evaluated at
every position. The map is a composition of permutations/XOR primitives, so its
correctness is pointwise for arbitrary dirty bit assignments; the particular
nonconstant fixture is execution evidence, not a basis for that universal claim.
The child emits an owned packet inside the protected `enter`/`return` interval.
For D forward, actual `episode.xor_packet` sends it to helper467 at literal event
22398; in reverse the next consumer is helper188 at event4738. The consumer sees
the computed packet, never an opaque declared child output. All outputs, copied
metadata, released numeric words and borrowed heads are checked on cleanup.

## Full parent geometry and the unexecuted lift

Actual `Layout.child_extents` on the source rank-two plan computes

```
B_child=2, G_child=3*3^124, S_child=2, U_parent=9475,
V_parent=9475*12*3^128 = U_parent*B_child*G_child*S_child*3^4.
```

Thus neither the 124 omitted atom coordinates nor the 9475 unused rows vanish
from the physical geometry. Complete encoded extents and unused-row metadata
are prepared and copied. The executed child uses one row and gap 3; it does not
allocate the enormous parent or pretend that metadata volume is payload volume.
For each fixed spectator/unused-row tuple the same leaf permutation acts on its
four coordinates. A tensor/direct-product lift therefore preserves every other
coordinate and arbitrary spectator data. That algebraic lift does not itself
prove fixed-tape gather or routing refinement or its scan cost.

`residual_algebra.py` independently composes the actual 128-address residual:
4346 adapter commands, the two weighted coordinate swaps, and the inverse 4346
commands. At the fixture's zero high fields their coefficients happen to vanish;
all commands remain paid. Its separate modulus-9/nonzero-high case has 374
nonzero coefficients per sweep and rejects an omitted command and stale high
form. This supplies the full-parent source/operator connection, not a claim to
have physically executed those production adapter scans. A full residual has
8692 adapter passes plus 16 child passes and 17384 adapter coefficient invocations
plus the child's 12. All high-prefix and unused-row multiplicities still apply.

## Compatible bills and controls

`PHYSICAL-RESULT.json` is the exact ledger. Every phase records **record tape,
residue Word and index Word reads/writes/moves separately**. Those counters are
not mixed with scalar ADD counts, recursive rank tariffs, host time, finite
control or stock. The entry guard is host validation, not a zero-cost encoded
scan. Retained cleared backing and peak stock remain separate from live ownership.

There are three comparisons:

1. C versus D uses the same complete preparation and returned-child boundary.
   All corresponding phase invoices are exactly equal at the chosen source
   charts. D's literal consumer interval is separately shown, because C has no
   immediate helper467 consumer. It already belongs to the carrier's paid local
   word: do not add it a second time to the three-extra-ADD local charge (864 over
   288 calls). Equal local fixtures do not imply all catalogue/setup costs equal.
   The compiler reports one extra distinct basis, fresh codebook identities and
   unchanged code field width; its extra construction/table cost is still due.
2. Raw versus adapted complete preparation has identical produced Program and
   directory bytes. #4025's shared radix is applied only to the actual Context
   and directory work; #4062's monotone admission retains all source validation;
   #4077's shared spectator method uses the actual Layout and pays its added
   counters. All setup, copying, validation and disposal in this boundary are
   measured. The raw and adapted preparations are each also equal C versus D. The adapted
   path adds 34 record writes while reducing the other recorded components; this
   is a vector invoice, not an unconditional improvement under arbitrary action
   weights. Its sufficient weighted inequality must retain those added writes.
3. For the same D source, packet and required consumer, the **original coefficient

   handoff or incoming wrapper. The candidate pays one constructor, the complete

   produce identical consumer output. The receipt checks no read/write/move lane
   increases. A second genuinely losing control redundantly constructs and
   disposes another identical child Program, with identical final output and a
