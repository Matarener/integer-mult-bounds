# Verification scope and implementation limits

The exit predicate is one useful, reproducible adapter result with a published
focused PR, exact evidence, a clean reusable worker and released ownership.
The autonomous-run playbook supplies bounded process waits and a local decision
trail. No child reviewers, extra threads or checkouts were created.

Build the Lever changed the result into a rerunnable synthesis and certificate.
Prove It Works required exact requested maps, signed phases, dense payloads,
inverse restoration, failure controls and committed source-only replay.
Separate Before Serializing Shared State kept all scratch in one session-owned
external directory and serialized shared Git and reservation writes. Unslop
shaped the mathematical scope and prose. Power of Ten was applied as follows.

1. New code has no recursion or unstructured control flow. CLI failures propagate
   with a nonzero exit; temporary copies are released by their context manager.
   No shared interpreter or file mode is changed.
2. The authenticated word has 5,398 events, 358 public banks and eight private
   lifetimes. The projection closure is capped at 367 rounds, each scanning at
   most eight cleanups and 358 banks. Selected events and ports are bounded by
   the word length. Synthesis visits 93 banks and at most 53 distinct recipes.
   Native ranks and frame widths are at most nine; vectors have 512 entries;
   rank elimination handles at most 18 columns and 18 pivots. JSON source files
   are capped at 4 MB; the authenticated decompressed native source at 8 MB.
   SOURCE pins are exactly five, with exactly three live inputs. CLI controls
   copy at most 32 package paths and three inputs; each child has a 60-second
   timeout. The small rank oracle has exactly 8^3 = 512 matrices.
3. Python and its standard library allocate dynamically. This is an explicit
   managed-runtime deviation. The limits above bound live data. History bitsets
   have at most 5,756 meaningful bits and 5,398 retained values. Two synthesis
   and checker modules are loaded from explicit hash-checked files. There are
   at most 53 adapter records and 93 bank rows. The kernel's monomial cache is
   capped at 5,000 maps of 512 address/phase entries. There is no concurrency
   within a replay, retained process or persistent runtime cache in the checkout.
4. New production functions are at most 57 physical lines after formatting.
   Test helpers separate source-copy ownership from bounded subprocess execution.
   Immutable predecessor code is not reformatted to satisfy a new style rule.
5. Active require checks cover source identity, counts, closure digest, exact
   chronology, native occurrence binding, endpoint shape, profile, signed Pauli
   action, exact phase, dense payloads and inverse restoration. They remain
   enabled under optimized Python. The rank oracle tests invalid capacities.
6. New mutable state stays inside the closure, certificate or test fixture.
   Outputs are local; no source, selected record or frozen predecessor is edited.
   Shared Git operations and task reservations use the authorized advisory locks.
7. Required subprocess return codes, CLI output, hashes and certificate fields
   are checked. The compiler's returned execution object is intentionally
   discarded because a separate checker validates its explicit recipe. File
   operations propagate failures. Standard write_bytes return counts are not
   scientific evidence; the subsequent complete receipt comparison and committed
   byte checks establish the written result.
8. runpy is an explicit bounded source-loader deviation. It executes only the
   canonical pinned compiler and a byte-identical retained checker. There is
   no generated code, dynamic eval string, network import or plugin discovery.
9. Dictionary function lookup is limited to these two inspectable modules and
   named functions. Compiler objects have their original direct then/adjoint
   methods. A separate signed Pauli/global-phase checker verifies the output.
10. Normal and optimized warnings-as-errors replay, behavioral fault controls,
    scoped Ruff checks and whitespace inspection are the applicable checks.
    The exact publication commit is checked for bytes and source ancestry, then
    exported and replayed without Git. Hosted acceptance is separate.

The unchanged retained compiler uses assertions, compact functions, allocation,
finite integer-elimination loops and a dynamic operation representation. Its
parameters are fixed at nine axes. The independent checker requires the actual
output identities and rank, so disabled compiler assertions in optimized Python
cannot make a wrong recipe pass. The immutable checker has its original
loop/capacity guards and require contracts. Neither general compiler correctness
nor every unused predecessor path is established here. Refactoring those frozen
sources would change the source audit and exceed this adapter task.

The selected baseline orientation command was attempted and rejected an omitted
sparse package, research/complex-sw4-frame8. No baseline or full selected cold
replay success is claimed. Lean, Docker, the scalar completion, numerical/native
physical realization, full caller/consumer invoice and outer transfer were not
run. The finite exact counts are algebraic quantities, not benchmark numbers.
