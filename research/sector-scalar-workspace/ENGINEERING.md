# Verifier boundaries

The autonomous local run playbook stopped at the first proved improvement:
the workspace theorem for an enlarged ordinary alphabet. Build the Lever
produced the standalone exact checker. Prove It Works required its normal,
optimized, registered and portable export execution. Unslop shaped the claim
and the separation of new lower bound from cited upper bound.

Power of Ten inspection applies only to the new verifier. There is no recursion,
subprocess, network call, mutation of inputs or generated runtime file. Matrix
dimensions are bounded by 64; the independent permutation oracle is bounded
by four. Projector axes are bounded by six, blocks by sixteen, ordinary-matrix
enumeration by 8^4, and word checks by 5*80*24 cuts. Every function is below
60 physical lines. Explicit contracts stay active under optimization.

Python's fractions, lists and interpreter allocate dynamically. This is a
managed-runtime deviation from fixed steady-state allocation, bounded here by
the stated finite dimensions and loop counts. File reads and SHA256 hashing
also allocate; at most sixteen top-level package files are accepted. Standard
library allocation internals are not instrumented. There are no callbacks
from external input, reflection or dynamic evaluation in the checker. Its
four direct internal check functions are the finite dispatch list in main.
Read-only package bytes and Python's standard library are the runtime trust
boundary. Warning-strict normal and optimized execution supplies the available
interpreted-code diagnostics; no separate static type checker is configured.
