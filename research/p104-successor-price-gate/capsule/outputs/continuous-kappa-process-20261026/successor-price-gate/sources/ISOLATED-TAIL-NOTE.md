## Reused published theorem and precise limitation

Matthew Amy, Martin Roetteler and Krysta M. Svore, *Verified Compilation of Space-Efficient Reversible Circuits*, CAV2017, LNCS10427, pp.3–21, DOI [10.1007/978-3-319-63390-9_1](https://doi.org/10.1007/978-3-319-63390-9_1). The [author proceedings version](https://arxiv.org/pdf/1603.01635v2) is already retained locally. Its original pp.14–15 were reread for this screen; earlier definitions and visual inspection remain documented in the existing5428 record. No proof-assistant replay is claimed.

Lemma1 on p.14 considers a well-formed reversible Boolean circuit C and a set A of retained changed bits. If no bit in A is used as a control of C, executing C and its restricted reverse restores every bit outside A for every initial state. The restricted reverse omits operations targeting A. Section3.3 p.8 and Section4.1 p.9 define the gate model and this operation. Theorem2 on p.15 specializes the result to Boolean-expression compilation with pairwise disjoint expression variables, ancilla heap and target. Zero ancillas are additionally needed for the separate intended-output theorem.

This is a sufficient version-preservation certificate. Failure of the control condition does not prove cleanup impossible. It does not supply native Gaussian inverses, field-operation costs, chart compatibility, source-owned erasure semantics, or a cheaper handoff. It is useful here because it states precisely why retaining a changed source while blindly reversing an earlier read can fail. The native forward program needs its own much simpler instruction-level proof below; there is no reason to compile it into Boolean gates merely to invoke this result.

## Exact forward native implication

Fix one actual cut, all live owner values and charts, and a proposed handoff that changes only h. Initially every other owner, including scratch s, therefore agrees with the original execution. Any subsequent identical deterministic operation whose inputs avoid h preserves this agreement, by induction. Consequently, if the retired h has no later reads into other owners and all its remaining old writes are removed or correctly replaced, the other owners' entire suffix—including scratch uses and its original owned CLEAR—remains unchanged.

This statement permits s to contain the helper symbol. It does not assert that s supplies the required residual, or that the proposed cancellation leaves h's own coefficient equal to1. Those are separate all-input row identities. A last direct read of h is also not a license to remove unrelated operations; every changed event and its operands must be recorded.

If the suffix reads changed h, syntactic noninterference is unavailable but algebraic cancellation can still work. For an otherwise unchanged linear segment, let the change at its entry be `e_h*delta(x)` and let A_t be the exact prefix of that segment. A protected read R_t changes by

    R_t A_t e_h delta(x).

Require this to vanish on every allowed original-input column at each protected observation, and require the analogous final-output residual to vanish. For several event edits, use the exact accumulated defect; a single initial rank-one expression is insufficient. These are derived elementary identities, not a new published theorem or an executed test.

Source-legal charged owned CLEAR may discard a scratch value after its final authorized use. It need not be replaced by reversible uncomputation, and this screen does not require the scratch to be zero before that CLEAR. Conversely, an attempted inverse-COPY cleanup needs the correct original read version; a register name alone does not establish it. An owned dependent scratch earns no new independent productive target. No raw-dual audit is imposed here: the retained P104 assembly is forward-only, and any different consumer must state its own obligation.

Common-frame scalar operations and the literal native MOVE identities must hold at every positive width. In the P104 chart invariant, scalar coefficients act once outside tensor powers. ## Complete cost screen for one isolated terminal-tail change

Suppose the actual change is only this template: nested frames with dimensions

    initial e <= current a <= new final f < old final b <=9.

One original monotone terminal paid job `H_(b-a)` becomes `H_(f-a)`, and the one helper target `H_(b-e)` becomes `H_(f-e)`. Let `H_r=r^(1-C)` for positive r and `H_0=0`. Before holder transport, cleanup, ordinary work or other changes, the exact local gain is

    G = H_(b-a)-H_(f-a)-H_(b-e)+H_(f-e).

Every additional debit and every lost target must then be included. This formula reproduces the already implemented706 control, `H2-H1-H9+H8`; it does not confer that saving on omitted scratch points.

For integer ranks, `H_u-H_v <= u-v` when `u>=v>=0`, and `H_v<=v`. Putting `n=b-e` gives

    G <= n-H_n <=9-H9 <=9 C log9.

The first inequality allows either zero or positive current rank; the second uses the increasing function `x-x^(1-C)` on x>=1. The last is `1-exp(-z)<=z`. For `0<C<=.0034` and `log9<2.2`, this is strictly below `.06732`. Thus one additional uncompensated H1 costs more than the entire optimistic gain of this isolated endpoint-tail change.
