## Exact three-coordinate identity and legal gathering

An ADD `(destination,source,c)` means
`x_destination <- x_destination + c*x_source`. A chronological list acts in
listed order, so its matrix product has the last event on the left.
For three distinct registers `x,y,z`, put

```
S(a): y += a*z       T(b): x += b*y       U(c): x += c*z.
```

The two relevant chronological identities, valid over the rationals, are

```
[S(a), T(b), U(-ab)] = [T(b), S(a)]
[U(ab), T(b), S(a)]  = [S(a), T(b)].
```

In the first identity both sides end at
`(x+b*y, y+a*z, z)` in terms of the initial coordinates. In the second both end
at `(x+b*y+ab*z, y+a*z, z)`. Thus these equalities preserve arbitrary dirty
inputs, rather than assuming any operand is zero. The primary checker compares
exact rational matrices; `independent.py` separately propagates the three
independent coordinate columns with `Fraction` arithmetic. Equality of these
three columns proves equality of the entire three-coordinate linear operator.

At every selected site the three ADDs use one common frame. Every intervening
unselected scalar event reads and writes registers outside the entire selected
three-register support. Such an event commutes with every selected ADD as an
operator on the full register space. The selected triple can therefore be
gathered at its first old position, contracted by one of the identities above,
and followed by the unchanged intervening events. The checker includes both
reads and writes in the disjointness test; write-only independence would be
insufficient.

All eight supports are pairwise disjoint. This also permits the overlapping
index windows of different sites to be contracted simultaneously. No selected
window crosses the A prelude, a section boundary, the target cut or a B native
warp cut. Reconstructed B warp indices change only to locate the same native
event after the same surviving source events. Native lender registers, map
columns, ordered entry/exit frames and native order remain identical.

Each local identity embeds as that exact operator on its three registers and
the identity on every other live or buffer coordinate. Composing these
equalities with unchanged surrounding operators proves full operator equality
on all 632 live coordinates plus 91 independent dirty buffers. This argument
does not inspect or simplify a native map, commute across a native event, or
assume a native phase convention. It holds with any common linear realization
of the unchanged surrounding operators. Native realizability and their inherited
signed phases are separate obligations.

## Projected inverse cleanup

The word contract's ordinary forward sequence is A after `prelude_events`,
then B with its interleaved native events, then restore. No non-target scalar
instruction reads a target. This hygiene rule makes the non-target subsystem
autonomous: deleting target-writing events leaves its invertible operator
`F_N`. Literal cleanup reverses that projected program, negating ADD
coefficients, reciprocating nonzero scales and inverting native symbols.
For each protected helper `r`, the fixed renaming `r -> r+704` applies to both
sources and destinations of this inverse. It names the inherited private dirty
buffer; it is not a new allocation by this construction.

Equal full forward operators have equal autonomous non-target blocks.
Consequently their projected inverses, under the same buffer renaming, are
equal. Regenerating literal cleanup from the edited ordinary sequence therefore
preserves its buffer action and every endpoint. The checker compares the entire
regenerated cleanup list and its canonical digest, rather than retaining an old
cleanup solely because the forward endpoint matches.

For both new B sites, the first two original ADDs write a target, while the
third writes a helper. Their contraction changes the target part but retains
the same single helper ADD in the projection. These sites save two forward
ADD records and no cleanup records. Each of the five restore sites is wholly
non-target, saving one forward and one cleanup ADD record. Thus the new saving
is exactly `7+5=12` scalar ADD records versus PR3998. The old A1858 site adds
the separately credited `1+1`; against raw PR3734 the combined saving is
`8+6=14` records.

These are rational scalar ADD records. Some coefficients are `2` or `1/2`.
The count is not an asserted unit-native instruction saving or physical tariff.
No zero buffer, unchanged helper or caller-boundary assumption is introduced
by the local identities.

## Complete chronological frame bill

Algebraic equality alone does not establish a legal or favorable framed
program. The primary auditor recomputes the entire chronological bill and
hygiene for each source, credited-only and final word. The independent checker
implements a second binary trace using explicit immutable point sets in
`F_2^9`, without importing the primary or retained executable. It authenticates
the two compressed input byte strings before loading either provider.

A frame is the XOR closure of its listed vectors. A scalar event requires
every touched register's current frame to be contained in the event frame.
Each positive dimension difference contributes one recursive child of that
rank. The trace includes initial frames, the fixed target-cut levels, center
entry and nested borrowed descents, every native entry and binary frame image,
the restore stage, and all final successor climbs. Center descent views do
not replace the persistent main register state. Native frame images are
checked by enumerating all 512 binary vectors; this is a binary-frame check,
not signed Clifford verification.

The independent checker compares 149 complete live-register frame states for
each source/credited/final word: entrance, A exit, both sides of all 72 B native
events, B exit, restore exit and terminal. All agree. It separately recomputes
every charge, including intermediate charges that those boundary comparisons
alone would not determine. The full profile for both providers is

```
{1:2440, 2:725, 3:224, 4:102, 5:20, 8:8}.
```

There are 3,519 recursive children and rank mass 5,134. Helper widths remain
`{4:26,5:2,6:18,7:53,8:96,9:213}`. No rank count changes, so the recursive
moment agrees identically at every exponent where the inherited profile price
is defined; no numerical optimization is required. Unchanged cleanup widths
and native descriptors do not certify physical scheduling, finite precision,
stock/tape, all-size compilation or outer/BIT obligations. Those remain
inherited or unknown, rather than being assigned cost zero.
