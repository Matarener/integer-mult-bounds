# Engineering decisions and verification limits

The exit predicate is one focused published consumer composition, with exact
source closure, a conditional endpoint proof, successful registered and committed
Git-free checks, useful failure controls, and a clean released worktree. The
autonomous-run playbook uses process-completion events and an external append-only
decisions.tsv. No extra agents, threads or checkouts are used.

Build the Lever produced verify.py and its complete typed receipt. Prove It Works
requires execution of both actual source toy calls and the final committed export.
Separate Before Serializing Shared State assigns private output/receipt paths and
uses OS advisory locks only for shared Git and short task reservations. These
principles shaped the implementation, rather than supplying mathematical premises.

## Scope and changed data flow

The only new runtime behavior is strict_outer.py. It reuses PR2808's shape,
ordered primitives and ownership operations, and passes each completed call through
the unchanged PR3503 adapter. There is no mutation of a predecessor runtime module
or installed default. The explicit call order and genuine high-field gap are the
reviewable change. Loader state and checker instrumentation have scoped restoration.

catalogue/selected-record provenance. The canonical loader additionally checks the

commands use those retained bytes without Git or network. Published source history
and committed-byte checks are separate from scientific acceptance.

The first source-bound baseline orientation command failed because the sparse

1. New functions use structured control flow with no recursive calls. Finally
   blocks release wrapper-owned intermediates, doubled Counts and shape resources.
   The managed inherited caller remains unchanged. Its recursive Node descent is
   an explicit inherited deviation, with the finite toy n<=3 and frozen depth
   giving bounded replay. General physical stack refinement remains open.

   canonical Counts, with at most 4096 input bits. Checker digit domains are
   q in {2,3}, w<=2, n<=3, k<=3, ell<w and spectators<=2; the inherited fixture
   additionally rejects volume>60000 and padded volume>120000. The ten-case list,
   two source toys, two injected failure positions and three-entry borrowing table
   are explicit finite bounds. Source inventory has at most 64 rows and exactly
   thirteen live paths, each at most 200000 bytes. Manifest size is at most 1 MiB.
3. Rule 3 deviation, Python managed allocation. Tape/counter/checker objects allocate
   during execution, so allocation-free operation is not claimed. Source extents,
   Count bit caps and fixture volume bounds limit live logical storage. The complete
   Count-tape auditor checks release and erasure through success and both call
   failures. Tracker checks only borrowed source plus final output survive success,
   and only borrowed source survives failed calls. Fixed physical banks and backing
   capacity are follow-up obligations before supplier admission. Python/library heap
   allocation is not measured by these logical-content observations.
4. Every new function is at most 60 physical lines in normal Ruff formatting.
   Inherited complete-origin fixture constructors and source functions retain their
   existing size. Splitting those frozen files would violate the source-retention
   boundary and is outside this local composition. The external function-length
   receipt records every new function.
5. Explicit need/require contracts check strict admission, original-volume body
   inputs, genuine D_hi gap, immediate restriction, both per-call endpoints, full
   Boolean columns, arbitrary payload, borrowed byte/head preservation, Count
   erasure, pass invoice and exact chronology. They remain active under -O.
6. Runtime owned state is local to each invocation. It clears only its own payloads.
   The original source/Counts are borrowed. Loader module/path/cache changes and
   checker patches last only for their context managers. Parallel execution in one
   Python process is outside the checker contract. Five workers use separate
   worktrees and session directories; shared Git/reservations are OS-serialized.
7. Returned payload ownership is checked before replacement. Failed runtime checks
   propagate after owned cleanup. The checker owns a transform output until its
   volume predicate passes and clears it on predicate failure. Each mutated control
   must fail at its named observation. Callee-internal allocation/cleanup failures
   beyond the completed contract are explicitly unclaimed.
8. No eval, generated runtime code or preprocessing is introduced. Rule 8 deviation,

9. Data access is shallow and new runtime calls are direct, except the completed

   callbacks are checker-only, finite and restored. Physical callee binding remains
   a follow-up gate.
10. Ruff E4,E7,E9,F,B,I,UP checks and formatting run on every final validation, along

    Generic registered commands provide future CI replay, without claiming hosted
    success. No type checker proves the dynamic frozen-tape API.
