# Implementation limits

Investigation playbook. Build the Lever shaped the choice to retain a runnable
certificate producer/checker. Prove It Works shaped the explicit-word and
literal rectangular matrix oracles. The Power of Ten inspections are scoped
to the three new Python files; predecessor files are read-only provenance.

All control flow is structured and nonrecursive. Public inputs limit roles
to 16, types to 8, arrows to 16 and each program to 128 instructions. The
combined state dimension is at most 288. The basis accepts at most D rows;
there are at most 16D arrow successor candidates. Each path has fewer than D
letters. Echelon and coordinate loops have at most D rows or entries. The
finite test loops have explicit bounds. No solver, subprocess or unbounded
queue is used. All functions are shorter than sixty lines.

Rule 3, fixed allocation, requires a managed-runtime deviation in these three
files. Python lists, dictionaries and Fraction allocate during elimination.
Live rational-cell storage is polynomial in the enforced finite input sizes;
exact rational bit growth can still be large. Certificate encodings are capped
and refused explicitly. The implementation makes no practical space or runtime
promise for every capped problem. No fixed-size real-time allocator is supplied.
The bounded small fixtures and registered 120-second timeout cover this replay.
A deployment requiring a hard memory budget must use an external process
memory limit or a bounded exact-arithmetic backend before accepting untrusted
workloads. The tool is intended for local research input, not a service.

Rule 9, indirect calls, has a narrow test-only deviation: must_reject receives
one of the locally defined validation/checker lambdas. There are fourteen
enumerated controls. Production compilation and certificate checking call
named functions directly. No runtime registration or generated executable code
is used. File resources use context managers; CLI writes are exclusive-create.

Externally supplied arguments use ordinary rejecting checks. Internal compiler
state-count and basis-dimension invariants use assertions; every scientific
acceptance condition uses require and remains active under Python -O. Both
registered commands enable warning errors. No external linter or type checker
is installed in the declared standard-library environment. Repository metadata,
publication-byte/source-history checks and literal CLI examples supplement the
normal/optimized scientific replay. No repository-wide diagnostics are changed.
