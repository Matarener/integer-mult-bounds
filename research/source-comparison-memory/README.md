# Lower-memory exact research-source validation

This contribution was produced by Nick Petalas.

The shared package validator now compares each working source with its pinned
Git bytes using a reusable buffer of at most 1 MiB. It keeps exact byte equality,
blob/SHA256 checks, source-drift diagnostics and file/reader cleanup. The change
adds one helper and replaces one comparison in `scripts/research_package.py`.
[PROOF.md](PROOF.md) proves equivalence under the existing stable regular-file
checkout contract. This is a verifier-engineering result with a scoped proof
and finite tests. It is not a new multiplication theorem or kappa improvement.

On the complete `research/physical-gaussian-core` metadata/pin validation,
peak traced Python allocation falls from 127,510,623 bytes to a median
74,011,826 bytes, about 42%. Five alternating fresh-process pairs all return
the same complete task/manifest result. There are zero failed validations.
The fixture includes the unchanged 54,548,480-byte `word-export.tar` live
input; its scientific verifier is not run or audited.

The memory saving has a time cost. Baseline validation takes a median
0.232871 seconds, range 0.225368 to 0.253928. The changed validation takes
0.330213 seconds, range 0.329083 to 0.340037. These are warm-cache local
measurements on macOS arm64 with CPython 3.12.15. They are traced runs,
not ordinary uninstrumented runtime measurements, cold-cache timings,
RSS measurements or a claim about whole scientific replay speed.
[BENCHMARK.json](BENCHMARK.json) retains every sample, environment, exact
source hash and complete-output hash. The file was generated by the benchmark.

## Reproduce

From the repository root, use CPython 3.12 and the standard library:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/source-comparison-memory/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -O -W error -B research/source-comparison-memory/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/source-comparison-memory
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/source-comparison-memory --check-source-history
```

Set `TMPDIR` to an external scratch directory for the temporary fixture
repositories. Elsewhere substitute the local Python 3.12 path. The marker is
`PASS_SOURCE_COMPARISON_MEMORY`. Each direct run generates a receipt on stdout
with the current validator/test/verifier hashes; it writes no receipt file.
Seven tests cover binary/empty/chunk-boundary files, same-size changes,
truncation and append, open errors, late I/O failure after an earlier mismatch,
closure, restored live inputs and unchanged blob/SHA rejection. Assertions in
the test framework remain active under optimized Python.

For the optional historical benchmark, first materialize its input paths in
a sparse checkout, then use a new external output directory:

```sh
git sparse-checkout add research/physical-gaussian-core references/semantic-bulk/rad20
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/source-comparison-memory/benchmark.py --work /absolute/new/scratch --pairs 5
```

The benchmark reads the baseline validator from canonical main
`721c03822c421b7f7fcbb2598993b947c4d88419`, imports the working candidate,
and times the complete `validate` call inside each fresh child process.
Every result must have the same full-output SHA256. The benchmark is opt-in;
CI replays the behavioral contracts and does not enforce host timing numbers.
The normal research-tooling test command also discovers the new tests:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B -m unittest discover -s tests -p 'test_research_*.py' -v
```

## Scope and implementation limits

The retained pinned Git blob is still allocated in full. Traced peak allocation
for complete validation includes that blob and other validator state. Only
the working-file comparison's added data buffer is bounded by 1 MiB. Managed
Python allocation remains a Power-of-Ten rule-3 deviation; no fixed-allocation
runtime is claimed. Each comparison has `ceil(N/q)` iterations for the opened
file's initial size N and buffer capacity q. It reads the initial extent even
after a mismatch. Context managers retain file and Git-reader cleanup.
Functions added here remain under 60 physical lines.

The source loader used by the benchmark and verifier imports fixed local Python
files through the standard import machinery. This bounded test infrastructure
is a documented dynamic-dispatch deviation; the production comparison has no
dynamic code, recursion, subprocesses or mutable shared state. The benchmark
uses the existing Git history and at most 20 bounded child processes. It does
not create another project checkout. Its temporary baseline file and outputs
must stay outside the repository.

Concurrent file mutation remains outside the stable-checkout contract. Native
Windows execution, whole-process RSS, scientific package replay and selected
frontier replay are unrun. Every inherited mathematical and physical obligation
remains separate. Shared-runner changes select every registered research
package in the existing CI planner; no historical scientific suites are run
locally for this change.

## Open next questions

Can the pinned Git blob also be streamed while preserving exact provenance,
SHA256, response framing, final process status and cleanup on early failure?
That could remove the remaining whole-blob allocation. First specify a bounded
chunk interface and every existing consumer. The current `git_blobs` contract
yields complete bytes, so changing only the working comparison does not settle
that question.
