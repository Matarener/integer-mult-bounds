## Four physical boundaries

1. **Producer fence.** The active parent has completed every owner in its
   designated whole-cover event. Its bank is closed, all productive roles and
   ancestor state remain live. Paid acquisition supplies 224 immutable fields
   in order `prefix, cover, U row, complete physical row`.
2. **Service entry.** `ServiceBank.assemble` constructs a new bank in order
   `prefix, family, cover, U row, complete physical row`. Families 0–111 are X,
   112–223 Y, 224–335 owned Z, and 336–447 owned W. It copies every borrowed
   bit and writes every bit of the newly owned zero fields. Source lengths
   and outer-prefix counts remain encoded `Count` objects.
3. **Completed service.** A distinct physical `Machine` executes the compiled
   full D and current endpoint reconstruction. The borrowed X/Y families have
   their original values and frames. All 224 Z/W families are complete. The
   source `finish_group` checks and retires the sixteen private roles after
   each private word. Every native output has already been consumed.
4. **Continuation exit.** `extract` compares every returned borrowed bit with
   the original acquired field and copies each owned family to its fixed
   output field, then consumes both service-bank copies. The lifecycle module
   performs the separately charged publication into the immutable parent bank
   and continues the actual source schedule. Extraction is not publication.

The implementation supports arbitrary positive encoded prefix count. Appending
224 complete field tapes would give family-major order and would be incorrect
when the prefix count exceeds one. The implemented outer loop is the encoded
prefix countdown, with a fixed inner loop over all 448 families.

## Compiler and cover barriers

`DecoderBinding` accepts only authenticated finite word, port labels and map
records. It never reads payloads or decodes variable-sized descriptors. Every
public scalar, native line and map is one complete cover barrier. The two
`begin`/`end` words are grouped so all private scalar instructions run at one
owner before advancing to the next owner. Moving the global acquisition or a
map into that private word is rejected by the compiler grammar.

Public clears lower to the retained `ScalarProgram('scale',0,1)` because source
`zero_step` only accepts private ports. A private clear uses that source
`zero_step`; its zero backing is explicitly written. All addition literals are
among signed one and signed one-quarter and use source exact scalar programs.
Only Z/W/F/G can be destinations; X/Y remain immutable.

Each signed q line lowers in chronological order to

`owner inverse; right(q); original C child; left(q,sign); owner`.

Thus the physical invoice has **four monomial calls per native occurrence**.
The two extra owner-basis calls are not included in the logical two-wrapper
census. Negative left wrappers contain the q XOR. All 224 frozen D occurrences
and all 112 negative reconstruction occurrences use this lowering, including
frozen event 4 W0/q11/+ and event1705 Z10/port76/q448/−.

`finite_maps` reconstructs the exact stage-one F17 alignment and stage-two
bridge shift from the retained source routes. Inverse maps transform the shift
by g, as required for these authenticated involutive routes. `map_group` uses
paid whole-owner cycles: each cycle of h owners needs h−1 physical exchanges,
h−1 sign corrections, and its nonzero output-owner translations. The source
bank acquisition/scatter of every participating packet remains charged.

## Cost and cleanup boundary

For P prefixes and B=Gamma U row_bits bits per family per prefix, assembly
writes 448PB bits and reads all 224PB borrowed bits, in addition to all encoded
countdown and head-return actions. Extraction checks 224PB borrowed bits,
reads/copies all 224PB output bits, then clears both 448PB bank tapes. These
are operation descriptions, not a replacement for the control-inclusive
source primitive bill. Descriptor construction, source Machine input copy,
all group gathers/scatters, four monomials per line, child execution, scalar
scratch, output preflight, fixed-bank return and retirement remain distinct
cost terms in the central ledger. Unknown costs are never cancelled.

The service owns its bank; all fields, returned output and bank must have
pairwise distinct physical tape identities. On malformed assembly/extraction,
borrowed heads are restored. Partial owned bank/output contents remain in the
service's exclusive inventory and must be cleared by the orchestrator's error
cleanup. Such rejection is not reported as a completed closed service. A
successful extraction consumes both the input service bank and returned bank.
