# Exact native GF(2) for the frozen H25 side verifier

The complete frozen H=25 **complex-side verification segment** runs in
**24.807329 rather than 35.075541 seconds median wall time (29.2746% less)**
and **24.76 rather than 35.01 seconds median CPU (29.2773% less)** on the
recorded Linux host. All six fresh cold processes retain identical complete
results, structural/basis/role witnesses, every Gram-rank observation and every
ordered complement input/output. Compilation, linking, loading and every added
finite/binding/fallback check are paid in each candidate command. Both arms pay
the same complete witness serialization and complement-stream hashing.

This is a scoped verification implementation improvement. It is **not the full
complex-network certificate**, a PR5864 speedup, a hosted performance factor,
a new mathematical construction, or a kappa/selected-frontier claim. Percentages
from these different workloads cannot be added. The further PR5864 target is
not established by this package.

## Frozen workload and change

Canonical base is `de5ec2e7a6074068452f45b1a191b5c72832df4a`. The unchanged
caller `scripts/complex_network.py:certificate` fixes H=25. The isolated scope
constructs `ComplexSideCircuit(25)`, initializes `Checks`, compiles physical
roles and performs **all** of `verify_map`, `verify_labels` and
`verify_role_frames`, in the caller's original order. No parameter is searched
and no source instruction is deleted or weakened. The two complete original
source files are copied byte-for-byte and pinned in SOURCES.json.

The opt-in C backend changes only `Label.complement_in` and
`Label.nondegenerate`. It uses packed unsigned 64-bit GF(2) elimination and
Gram construction. Checked input widths and augmentation bounds precede all
shifts and array accesses. Unsupported widths, negative/nonexact values and
container cases use the original Python path rather than truncating. The
complete H25 workload takes 238,685 native complements and 59,959 native Gram
calls, with zero fallback. The reference `echelon`, `reduce`, `contains`, source
construction and all verification predicates remain active.

The complement kernel preserves the source's pivot selection, all-row
elimination, insertion order and returned-vector order. The Gram path retains
the exact GF(2) field and all packed rows/ranks. This is unrelated to using a
modular lower bound as an exact rational-rank certificate.

## Reproduction

Tested on Linux x86-64, CPython 3.12.3 and GCC 13.3. Existing `cc` and Python
development headers are required. No third-party dependency is installed and
no compiled binary is committed. This uses the tested CPython 3.12 C ABI;
abi3, free-threaded and subinterpreter support are not claimed.

Fresh registered finite/source/native checks, about two seconds per mode here:

```sh
python3.12 -B scripts/research_package.py --package research/gf2-side-verification
```

One complete guarded candidate replay, with a new external evidence directory:

```sh
python3.12 -B research/gf2-side-verification/replay.py C /tmp/gf2-side-new-evidence
```

Use arm B for the complete unchanged baseline. The portable guard applies one
serial runner, 180 seconds per command, 1 GiB sampled process-group RSS and
zero automatic retries; the recorded round used 600 seconds initial feasibility
and a 1,500-second shared cap. New evidence directories prevent overwriting
retained runs. Parent source-inventory/transport checks are separate from the
timed cold scientific process, as documented by the raw guard receipts.
Metadata, committed bytes/modes, export, readonly replay and exact-head hosted
correctness CI are publication checks, not hosted performance evidence.
