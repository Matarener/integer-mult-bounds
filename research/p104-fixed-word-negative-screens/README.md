## Reproduce

From the repository root, with Python 3.12 and its standard library:

```sh
python3.12 -B scripts/research_package.py --package research/p104-fixed-word-negative-screens --check-only
python3.12 -B scripts/research_package.py --package research/p104-fixed-word-negative-screens
```

The registered replay runs both normal and optimized isolated interpreters,
with a 300-second limit per command. All new guards use explicit exceptions.
It checks the complete arbitrary-input scalar boundary, actual frames and
owned lifetimes, baseline kernel premises, scientific positive/negative controls,
and an independently computed terminal certificate. No full historical
supplier/native replay is required or claimed for these necessary exclusions.

For a source export containing this package and its declared word input:

```sh
python3.12 -I -B research/p104-fixed-word-negative-screens/verify.py
python3.12 -I -O -B research/p104-fixed-word-negative-screens/verify.py
```

Direct runs also isolate bytecode caches before loading research dependencies.
`--output NEW_FILE.json` optionally writes the checked semantic receipt. Neither
command overwrites scientific inputs or silently regenerates `EXPECTED.json`.
The optional full-Git-history publication audit is separate from the source
export replay; it cannot be claimed from a shallow checkout.

The registered checks passed on CPython 3.12.3 under Linux, including normal
and optimized replay, 27 module controls, independently implemented terminal
and dual certificates, a clean exported-package replay, and rejection of
altered word/vendor bytes and a forged receipt. Both ordinary replays produced
the same semantic SHA-256. Exact coverage and unrun obligations are recorded
in [VALIDATION.json](VALIDATION.json).
