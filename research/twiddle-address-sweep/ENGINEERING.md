# Engineering decisions and bounded code

The autonomous-run exit predicate is one useful source-closed contribution, actual committed scientific/control replay, publication-byte/source-history verification and a clean/released worker. The external session decisions.tsv preserves choices and original diagnostics. No delegated agent or extra checkout is used.

Build the Lever produced sweep.py and independent.py rather than relying on a hand-computed invoice. Prove It Works required every actual tape count, source circuit output, final blank return, optimized mutant gate and committed Git-free command. Separate Before Serializing Shared State kept this package and control outputs private and serialized only shared Git/reservation mutations. Unslop kept claims tied to the changed input contract. Power of Ten shaped the following code constraints.

1. Control flow is structured without recursion. run's finally owns every data-tape cleanup. CLI control copies are deleted in finally; only explicitly created paths are removed.
2. Runtime shape limits are ell<=256, axes<=64, A<=16384, P<=A, n<=256 and M<=4096. Each address increment has at most A flips; each addition has n positions. Science uses 480 prescribed complete fixtures and three wide shapes with seven seeds each. CLI controls use seven mutations and one valid retry, each child bounded by 30 seconds; registered commands each have 120 seconds. No service or watcher is introduced.
3. Mathematical data tapes have fixed extent before the stream. Managed Python object/diagnostic allocation is a deviation from allocation-free steady operation. Shape limits and the nonretaining observer bound live data by O(A+ell), plus host/program/diagnostic objects. Code never claims Python object memory equals the mathematical Boolean capacity. The control export has a fixed manifest and owned lifetime. Follow-up for a full machine is an encoded scheduler with its actual storage/counter bill, not an unmeasured object-memory assertion.
4. All functions are at most 60 physical lines. The two separate oracle responsibilities are named arithmetic and a shape-only access invoice; there is no forwarding framework.
5. Invariants use require exceptions and remain active with -O. The address/cache bit check and final blank/head checks are runtime contracts. Independent per-field count comparisons, complete source arithmetic and meaningful arithmetic/movement/cleanup mutants check distinct failure modes.
6. Data state belongs to each single-use Sweep. Shape scheduling data are immutable; no global mutable scientific cache exists. Machine/oracle modules are loaded into distinct names to avoid accidental stale module sharing.
7. CLI inputs are validated before a stream. Exceptions propagate after cleanup. Every subprocess exit, stdout/stderr and expected failure marker is checked. Source bytes and copy inodes are checked before/after controls. Diagnostic output writes are checked by the Python I/O contract. A second failure during cleanup is outside the assumed reliable-primitive contract.
8. No conditional compilation or macros exist. Source-authenticated compile/exec is a bounded deviation for loading standalone modules without stale .pyc reads. Only the four package files and the exact pinned canonical circuit can be loaded, with explicit paths and source hashes. There is no user-supplied code path. Metadata still validates the complete declared closure separately.
9. A single observer callback is a bounded dispatch deviation needed for a nonretaining paused-consumer test boundary. It may inspect one header; its costs and physical realization are excluded. A raised callback exception triggers owned cleanup. The full caller must supply its exact read/head-return contract. No pointer arithmetic or callback chain is present.
10. Verification runs CPython3.12 with -W error and -B, normally and with -O. Scoped Ruff E4,E7,E9,F and AST parsing/function-length checks cover the new files. No project-wide configuration or historical suite is changed. Static type checking of the existing untyped Python dependencies is unrun; no type-completeness claim is made.

Source exports use exclusive regular-byte creation and require owner, regular-file status, source equality and distinct device/inode identities. They never copy modes, chmod shared runtimes, follow symlinks during cleanup or normalize uv scratch. Final session receipts separately record the actual executed commit for every command and before/after source/export/runtime identities. Package metadata does not assert independent mathematical acceptance or retrospective coverage of a later commit.
