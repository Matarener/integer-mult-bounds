# Kappa continuation: endpoint closure, native releases, and exact prices

**This continuation does not establish a new kappa.** It follows the previous
report's unfinished native-consumer task through actual boundary geometry,
literal helper releases, and the complete retained allocation. The main
new result is a correction to the optimistic common-chart route: closing
its productive endpoint consumes its remaining raw saving. We also construct
and price all 31 combinations of five partial helper retimings, including a
real shared-donor saving. Every one loses against the retained bound even
if its missing native restoration is free.

The work is confined to this directory. The earlier
[`kappa-global-continuation`](../kappa-global-continuation/README.md) and
all attached source evidence are retained unchanged. This package is local
research, not a selected-frontier update, a claim of novelty against current
upstream work, or a completed multiplication theorem.

## 2. The common-chart route pays at the productive endpoint

The previous unfinished consumer suggests using common native charts so
the eight scalar query coordinates can pass through the geometry. We
implemented the full version: nine common 9-dimensional blocks in m81,
with exact affine native phases and all 128 ports. The code follows the
literal controller's local, idle, bridge and terminal event order.

The original port entrance is asymmetric. Normalized X initially carries
`C_q0^-1`, while after the last local stage the Y hole sits on the current
normal. A productive terminal word has to close against the **initial**
normal q0. Closing against only the last normal q8 leaves a nontrivial
native multiplier. The verifier includes an explicit character that detects
this omission.

This changes the four old-port final Y idle ranks from the X values
`54,36,18,0` to **`56,38,20,2`**. The two additional orthogonal directions
are fused into the actual final idle children. The bill does not assume
they must be paid as 896 separate rank 1 calls, but their 896 units of raw
rank cannot be omitted.

| Complete optimistic m81 item | Raw rank mass |
|---|---:|
| Nine local words | 45,630 |
| Ordinary-port common-chart boundary work | 1,792 |
| Original-port idle work, 112 times 488 | 54,656 |
| Additional-port idle work, 16 times 486 | 7,776 |
| Maximum retained helper-width credit | -26,910 |
| **Total before a residual consumer** | **82,944** |
| **Productive normalization, 81 times 1024** | **82,944** |

Even giving the residual inverse for free leaves zero raw saving. For
each positive child rank r<81 and saving exponent a>0,
`(r/81)^(1-a) > r/81`. Applied to the remaining positive child list, this
makes every positive saving exponent fail in this emitted geometry.
This is a scoped exclusion of the stated initial/terminal chart family,
not of every possible common-chart construction.

**This corrects the earlier optimistic m81 cost assessment.** It is not
merely a failed numerical search. The native phase check verifies actual
orthonormal axes, affine translations, equal gauges at bridges, and
productive endpoints conditional on the separately stated scalar residual
cancellation. Evidence: [uniform81 receipt](native-boundary/evidence/UNIFORM81-RESULT.json)
and [geometry explanation](native-boundary/README.md).

We also enumerated all 256 partial common-chart choices across the eight
boundaries. This census uses the actual ten idle intervals, 224 H1 for a
common entrance,112 H2 plus the required translation for a return to the
fixed chart, and 32 H1 for a fixed-stage zero-port catch-down. The exact

**All 255 nonempty choices fail the ideal target.** The best nonempty case
uses stages 7 and 8 in m75 and already has a negative extra-H8 allowance of

and [independent partial pricing](invoice-experiments/PARTIAL-TARIFFS.json).

## 3. Why eight scalar queries cannot simply be gathered earlier

The actual query interface is

\[
T=R\,\operatorname{diag}(C_{q_p}),
\]

where R has scalar rank 8 but its 112 source labels q_p are distinct.
A fixed scalar gather before the source-dependent native lines must
retain a row space containing every Fourier-character version of T.
Exact character isolation recovers each of the 112 source coordinate
rows from those versions. Therefore **such a scalar pregather needs all 112
source dimensions**, even if an arbitrary native operator follows it.

A concrete witness uses ports `0,7,27,57,76` with coefficients
`-1/2,1/2,-1/2,-1/2,1`. Its eight R queries vanish. After the actual native
lines, character1 produces

\[
(0,1-i,1-i,0,0,0,0).
\]

The exact Gaussian calculation checks all 512 coordinates of this witness.
An equal-label positive control verifies that a common native line does
commute with a scalar gather. A two-layer negative control also rejects
using the single-layer affine formula unchanged on a tensor cover.

This is an exact obstruction to a specified ordering of operations. It
does not establish a lower bound for routed native pregathers, different
source charts, interstage circuits or native child counts. Source:
[query envelope evidence](native-boundary/evidence/QUERY-ENVELOPE-RESULT.json).

Separately, all `4^9 = 262144` patterns of two specified binary D-controls
per call were tested for the common-involution scalar controller. None
cancels its residual. The independent review reconstructs the literal
template and repeats the complete census with unbounded Python integers.
This excludes only those two binary control choices per stage, not general
scalar controllers. Sources: [control census](control-search/CONTROLS.json)
and [review](review/REVIEW.json).

## 5. What is now excluded in the retained packing

Two exact, source-specific statements supplement the bounded packing
searches:

1. **No single two-helper owner swap improves the actual fill**, even if
   source clocks and physical-family restrictions are dropped. The checker
   recounts 11 width/remainder types and all 21 feasible relaxed type pairs.
   None makes the two remainders more unequal, so concavity cannot lower
   the recursive price. This is not a claim about multi-item exchanges.
2. **The tested fresh-slot one-unit path cannot continue past its first
   swap.** All 3271 starting call/width contexts and 8429 first donor rows
   are covered. Every first donor is full; all 21365 untouched donor slots
   have maximal width9. None can supply the next w-to-w+1 step. This
   excludes that precise single-token path family, not interacting tokens,
   other exchanges or changed clocks.

The floating-point LP and time-bounded searches remain discovery
observations. They are not global optimality certificates. No changed fill
is asserted. Exact evidence: [single swap](invoice-experiments/SINGLE-SWAP-BARRIER.json)
and [fresh-slot path](invoice-experiments/augmenting-path/RESULT.json).

## 6. Reproduction and review scope

From the repository root, choose a fresh output directory:

```sh
python3 -B research/kappa-boundary-continuation/verify.py \
  --work /absolute/path/to/new-boundary-replay
```

The replay authenticates every listed source and the entire frozen
predecessor, copies them to a fresh repository-shaped workspace, removes
every expected new generated artifact, and runs 15 ordered commands. It
then compares canonical JSON payloads with the authenticated deliverables.
Only the explicitly named `search_seconds` telemetry field of the exhausted
fresh-slot path run is omitted from payload equality; all of its proof
counts, source hashes and mathematical fields must agree.

Python and NumPy are required for the replay; exact rational prices use
the authenticated standard-library engine. SciPy is used only by optional
discovery scripts. No network is required. `MANIFEST.json` binds sources,
dependencies and regenerated artifacts; `VALIDATION.json` records the
environment, command statuses, hashes and scope of the delivered replay.

The unchanged predecessor's full replay receipt is retained. The default
new replay authenticates it without rerunning its older heavy checks.
Add `--replay-predecessor` to repeat those checks as well. This continuation
has no completed changed native supplier, so its full independent native
compiler and outer admission suite were not run for a new candidate.

The review independently reconstructs the scalar controls, affected helper
columns, both-provider combinations and exact price bindings. Its author
also implemented the native geometry generators; the package discloses
that relationship and does not describe it as an independent third-party
native compiler review. Review details and limitations are in
[review/README.md](review/README.md).

## Open next questions

The best next construction target is a **literal reduction of the paid
native child list while retaining the original 896-field endpoint contract**.
The exact prices in section1 specify useful minimum targets. One genuine
pair fusion per replica would improve the retained bound; two would pass
the previous ideal allocation target, provided all extra costs fit.

An acceptable next candidate should identify its exact stage or boundary,
the fields and owner charts it uses, the children removed, all replacement
children, and the arbitrary-helper release word. It must then pass native
phase/endpoint verification, a full physical allocation recount and the
inherited outer guards. A low-rank scalar factorization alone does not
meet that contract.

Routed native gathers, interstage sharing, different initial/terminal chart
families and more general owner exchanges remain open. This package gives
specific reasons to avoid repeating the rejected simple pregather,
specified common-chart family,31 release combinations and unit-token path.
It does not prove that the remaining fusion exists or that the desired
increase is close in construction complexity.
