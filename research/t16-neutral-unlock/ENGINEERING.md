# Verification and bounded engineering decisions

The acceptance predicate is an exact source-bound owner map with a lower
complete complex moment and a passing unchanged eleven-stage paid admission.
The local search stops at this witness and makes no exhaustion claim.

The new path is `check_sources -> predecessor -> construct -> prices ->
write_data -> replay.run -> result_record`. The swap and triple each end in a
complete independent owner audit. New loops iterate at most 69,120 rows,
512 patch entries, 100 source entries, 112 ports per window, or three nominated
roles. Each parsed JSON or gzip payload is at most 32 MiB. New code has no
recursion, hidden registration, shared mutable state or background child.
The largest new function is 56 physical lines in `replay.py`.

Failures propagate as exceptions. The CLI's explicit `--work` retains partial
outputs for diagnosis; the default temporary directory removes its own outputs
on every exit. Source and archive files use context managers. The strict child
is synchronous, uses a restricted environment and has a 300-second timeout.
No child survives successful completion. Runtime invariants use `need`, so the
new checks remain active under `-O`. Inherited assertion-based admission must
run without optimization and rejects an optimized caller.

Normal and optimized behavioral tests exercise partial/omitted/reversed moves,
physical family/width corruption, invalid index and five-role boundaries,
non-neutral first steps, corrupt predecessor preimages/digests, and changed
invoice values/types/keys/array order. Entire typed invoice comparison allows
only the three explicit source identifiers to change. The registered launcher
adds its private bytecode namespace. Direct replays should use a fresh output
directory and source-only imports as in the README.

The first strict replay rejected the inherited `actual_73column_sigmas=10008`
expectation. Its complete owner census found 10005. The candidate SPEC now
expects 10005; the unchanged compiler/auditor and all paid invoice fields remain
in force. This is a corrected output expectation, not a disabled guard.

## Power of Ten deviations

Rule: 3, fixed allocation after initialization.
Location: `verify.py`, `replay.py`, and CPython JSON/gzip/tar handling.
Reason: CPython and its standard library allocate decoded values and temporary
arrays during a finite proof replay; a preallocated allocator is not provided.
Scope: this single sequential replay with the fixed input capacities above.
Compensating control: byte/row caps, at most 500 source archive members and
128 MiB expanded source, scoped temporary directories and no parallel child.
Verification: normal registered replay, optimized behavior tests, exact
reconstruction and fresh Git-free committed export.
Follow-up: revisit capacities and allocation ownership before admitting a larger
source domain, archive or concurrent replay.

Rule: 8 and 9, dynamic module loading and indirect execution.
Location: `verify.py:load`, pinned moment engines and `replay.py:run`.
Reason: the retained admission and exact engines expose file-based modules and
an authenticated portable driver. Replacing their interface would change the
scientific verification boundary and expand this packing task.
Scope: fixed source-authenticated local paths and the single retained admission
command; there is no user-selected callback or registration catalogue.
Compensating control: source hashes before import, fixed target paths, strict
subprocess deadline, checked return values, and fresh bytecode namespace through
the registered launcher. Imported modules retain their existing assertions and
bounded numerical/source contracts; no predicate is weakened.
Verification: all eleven stages, their mutation controls and full source-closed
export run. No independent audit of all inherited implementation internals is
claimed.
Follow-up: any changed import target or compiler contract requires a separate
source-bound interface review and renewed replay controls.

Rule: 10, repository-wide recurring diagnostics.
Location: imported frozen admission and moment sources, shared CI configuration.
Reason: this isolated research contribution may not rewrite frozen source or
change shared build policy. Existing sources retain their original diagnostics.
Scope: only the new package's Python files are linted and formatted here.
Compensating control: installed Ruff 0.17.1 with the configured rule set,
no new suppressions, warnings-as-errors on all scientific commands, and an
opt-in `VERIFY.json` invoking full replay and both behavior-test modes.
Verification: Ruff check/format, package metadata, publication-byte/history
preflight and fresh committed export. Hosted CI remains a separate observation.
Follow-up: changes to the inherited compiler require its own diagnostics review;
this package does not authorize such changes.
