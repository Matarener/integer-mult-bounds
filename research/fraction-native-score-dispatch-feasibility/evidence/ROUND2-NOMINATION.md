## Exact supported boundary and implementation shape

1. Start from PR5864's frozen native source, Linux CPython 3.12 build envelope, exact source/ABI receipt, certified input domain, qualified pure miss callback, canonical owned Fraction slots and original cache limits. Accept direct dispatch only when the prior `runtime_binding.py` executable-shape checks succeed on the live runtime. Reuse its complete authenticated function/closure/global/MRO predicates and its pure, identity-based freshness token; never substitute a source-file hash alone. Pin any copied binder and expected shapes. Authenticate ordinary raw function/static/classmethod descriptors before accessing their payloads. Require the known defaults/keyword-defaults/closure state relevant to invoked functions, the captured `__add__` monomorphic operator to be this kernel, and absence of `__iadd__` throughout the MRO, including a present `None` value.
2. Check both the inherited slot token and the addition token at each trace entry. Qualification assumes runtime metadata remains unchanged during that trace, as in the existing bounded packet contract. It does not certify concurrent or callback-driven monkey-patching during execution. Unknown code shapes, drift after derivation, foreign descriptors or unsupported inputs select the existing PR5864 checked path; its own rejection/fallback policy still applies. Qualification itself must not invoke foreign descriptors.
3. Change only the three score additions in `Event.apply`, in their existing order. With an owned optional kernel and **both operands exactly the qualified Fraction class**, call `PyObject_Vectorcall(kernel, argv, 2, NULL)`. Otherwise call the existing `PyNumber_InPlaceAdd`. The integer rounded-injection site stays untouched. Keep the original Fraction arithmetic, returned objects, contribution callback, zero construction, key, FIFO, iteration, score stores and scientific oracle. The [CPython call API](https://docs.python.org/3.12/c-api/call.html#c.PyObject_Vectorcall) supports this two-object call without constructing an argument tuple.
4. The cache must own the optional kernel reference, visit/clear it during GC, and release it on every constructor/error path. Preserve the existing strong score/result references and list-store ownership. A direct-call exception propagates immediately; **never retry it through generic addition**. The raw API defaults to generic addition, type-checks any optional function packet, and remains memory-safe for malformed inputs. A caller-supplied function is not thereby semantically certified: scientific eligibility belongs to the checked wrapper. Generic score objects retain their existing `__iadd__` behavior rather than acquiring a new exact-Fraction rejection.

## Fixed screen and economic stop

Build an isolated feasibility copy only after the parent accepts this nomination. The smallest proposed micro contains the actual three-score C loop in two entry points: the unchanged generic loop, and the proposed guarded vectorcall loop. Both retain identical operand acquisition, strong references, list stores and error checks. Freeze sixteen exact-Fraction increment triples before timing, covering zero, signs, cancellation, common/coprime denominators and 128-bit numerators; their cycle should keep score size bounded. Verify all terminal scores and types outside timing.

Use **32,768 coefficient groups, 98,304 additions per arm, one B,C,C,B sequence**, with fresh scores each arm and no adaptive repetition or workload selection. Include both per-add type guards in C timing. This micro isolates dispatch; it supplies no actual-word receipt and no admitted full-trace projection. Record interpreter/compiler/source hashes, both CPU and wall times, build cost and every failed result.

Before any actual/full construction, measure the complete added union of finite controls, binding/freshness, initialization and cold compile/link/load cost against a fresh PR5864 process. Compiler-child CPU belongs in the bill. Reuse of one loaded module within a process is allowed; fresh complete processes each pay their own build. If either micro metric does not improve in both paired comparisons, or its conservative illustrative scaling to 7,739,250 sites cannot cover that measured incremental bill plus observed timing spread in **both** metrics, stop this candidate. Synthetic scaling is only a screen, never a claimed lower bound on the real trace saving.

Use the resulting measured actual saving and complete overhead bill to decide whether complete construction is justified. Final acceptance requires fresh complete measurements, a positive incremental saving beyond PR5864 repeat variability in both wall and total CPU after the new check/build bill, and preservation of at least 15% against PR5848. Preserve negative evidence if any gate fails; do not compensate by adding options (a) or (c) in this round.
