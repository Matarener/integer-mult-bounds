# Verification boundary

Separate Before Serializing Shared State keeps this result in one owned package,
branch and cache. The shared Git and claim transactions use the required OS lock.
No peer, selected-science or frozen predecessor file is changed.

Prove It Works requires matching the actual literal core and decoder word,
checking the selected idle split, running rejecting public CLI controls, and
executing committed bytes in an inode-disjoint read-only Git-free export.
An arithmetic success marker never admits the missing physical continuation.

Power of Ten review covers verify.py and test_verify.py. There is no new
recursion or generated-code execution. Functions fit within 60 physical lines.
Source inventories have exactly eight runtime inputs and two provenance entries.
Files are capped at 16 MB, source metadata at 16 KB, receipts at 100 KB and
expanded gzip at 12 MB. Each core has 25155 events, each of nine producer cases
has at most 600 outer events, each sweep body at most 2000 events, and each
flattened case at most 4000 events. There are 3823 decoder events and three
fixed endpoint profiles with at most 73 ranks each. Temporary exports copy at
most 20 package files and the eight declared inputs. CLI subprocesses are
synchronous, have 20-second timeouts and their return codes are checked.

Rule 3 deviation: CPython allocates managed integers, byte buffers, JSON objects,
Counters and dictionaries during this finite offline replay. Authenticated fixed
inputs and the explicit byte/event limits bound the live problem. Python and
library allocator overhead is not measured; no fixed-allocation implementation
or production service is claimed. A variable-size tool needs a separate memory
capacity review. Standard-library JSON/gzip internals retain their implementation
and recursion behavior; the checker does not interpret arbitrary source before
hash authentication. Receipt parsing failures fail closed.

Rules 8 and 9 deviation: the tests load the single explicit package verifier
module and unittest uses its normal test dispatch. There are three test methods;
no arbitrary plug-in or predecessor executable is loaded. The verifier itself
uses only standard-library code. All validation uses explicit exceptions and
survives optimization. No assertion is used to validate scientific input.

Warnings-as-errors, Ruff E/F/I/B/UP/C4/SIM and formatting checks cover both files.
The existing registered-package workflow runs the warning-strict replay and its
optimized controls. No additional installed dependency or repository-wide lint
policy is introduced. The prototype additive rejection is retained only in the
session cache and is explicitly withdrawn as an unconditional conclusion.
