# Paid SOURCE refinement and eight further protected-reader fusions

## Result

Eight more actual G20 windows admit a target-preserving change of paid profile `−H₁−H₃+H₄` each. Unlike an unsupported free intermediate SOURCE value, this construction explicitly pays to refine each SOURCE's old rank-3 transport into rank 1 followed by rank 2. Two snapshots per window preserve its intermediate and upper values. The helper's longer rank-1/rank-1/rank-2 prefix then fuses into one rank-4 request. The exact net improvement is positive for every exponent parameter `0<C<1`.

This supplements [bit.md](bit.md), using exactly the same retained G20 source revision and the same physical/ROW framework. It does not claim a complete multiplication κ above 0.0035. Its paid refinement is a new mechanism relative to the preceding seven-window construction.

## 1. Nested transports with an explicitly paid intermediate value

Let `L⊂P⊂U` be the actual nested source frames of dimensions 1, 2, and 4. Use the source's prescribed transports

`A : ground → L`, `B : L → P`, `D : P → U`, `C = DBA : ground → U`.

Their ranks are respectively 1, 1, 2, and 4. The old SOURCE transport `L→U` is the rank-3 composition `DB`. Refining it to the two requests `B` followed by `D` preserves the exact SOURCE value at both old endpoints. All actual pre-existing SOURCE observers are outside that single former instruction, so their values and order are unchanged. The intermediate SOURCE value at `P` is newly created and explicitly paid for.

The physical identity here is the source normal-form composition on nested concrete frames. It is not a free map between different charts. The rank-1 and rank-2 maps used in the refinement are the existing helper's actual second and third prefix transports, with the same concrete frames and supplied ordinary matchers. The rank-4 fusion uses the actual existing ground-to-`U` matcher. Both physical routing orientations, finite coefficients, owned copies and clearing are charged by the finite compiler.

Run the inverse refined word. Immediately before the SOURCE leaves `U`, save `x_U` in an owned frame-`U` array. After its paid rank-2 return to `P`, save `x_P` in a second owned frame-`P` array; then perform its paid rank-1 return to `L`. Thus

`x_P = B x_L`, `x_U = D x_P`.

The SOURCE has its exact old `L` value when its old instruction finishes. Both snapshots are retained until their respective helper and reader uses. No SOURCE instruction is hoisted across an old observer.

## 2. Cancellation with a recipient's independent injection

Suppose the forward helper has the prefix

`h ← A h; h += x_L; h ← B h; h ← D h`,

with one protected outgoing read after `B` and before `D`. Suppose that reader is a recipient `r` with a paired cold ground addition `r += h`. The recipient has its own unchanged transport from ground through its own line into `P`, and it may receive an independent SOURCE value along that route. Write its resulting value, excluding the helper contribution, as `E r₀ + w`, where `E` is the prescribed ground-to-`P` transport. Source path composition gives `E = BA`. The helper's protected value is `E h₀ + x_P`.

The pair of cold and proper additions therefore contributes

`E h₀ + (E h₀ + x_P) = x_P`.

Delete the cold helper addition and replace the proper helper addition by addition of the saved `x_P`. The recipient's own independent injection `w`, its existing queries, and all of its other readers are unchanged. In particular, it need not have been zero, and its own SOURCE need not equal the helper's SOURCE.

After this substitution, no external reader remains in the helper prefix. Its inverse can be replaced by

`h_U += x_U; h_U ← C⁻¹ h_U`,

because

`A⁻¹(B⁻¹D⁻¹h_U + x_L) = C⁻¹(h_U + x_U)`.

This deletes the old helper rank-2 return, old helper rank-1 return to `L`, old line injection, and old helper rank-1 return to ground, replacing all three requests by one rank-4 request. The arbitrary helper baseline and exact productive endpoint are preserved.

The two snapshots provide values at their actual common frames. At the proper reader, use the saved `x_P`; no retiming of the recipient is needed. All subsequent or earlier source observers see their exact old values. The word rejoins the former complete state at the cold-read boundary, so it composes with other proved windows.

## 4. Simultaneous physical construction and exact paid accounting

The helper and recipient pairs are distinct. SOURCE 46 is also a different recipient's independent SOURCE, and SOURCE 66 is the independent SOURCE of recipient 369; their old observations remain unchanged because the refinement changes only an atomic old rank-3 instruction's internal path. Thus these overlaps introduce no new dependency cycle. All eight new helper joins are exact before every old earlier reader, including ground compensation and COPY-capture readers.

Each row deletes two helper rank-1 jobs and one helper rank-2 job, and adds one helper rank-4 job. It deletes one SOURCE rank-3 job and adds one SOURCE rank-1 and one SOURCE rank-2 job. Hence its net paid change is exactly

`(−2 H₁−H₂+H₄) + (H₁+H₂−H₃) = −H₁−H₃+H₄`.

Every full helper target remains productive and arbitrary. No target is retired in these eight windows. Their snapshots are nonproductive owned fields, initialized and returned to zero. A conservative implementation keeps two distinct arrays per window, so it adds 16 local owned arrays. The earlier 24-array bank becomes 40. In particular, the intermediate SOURCE values are neither free nor hidden in an uncounted workspace.

Together with [bit.md](bit.md) and its preceding proofs, the complete 18-call profile becomes

`P_refined = P_5512 −378 H₁ −378 H₃ +306 H₄`,

`T_refined = T_5512 −72 H₄`.

The three changed paid coefficients are `P₁=24849`, `P₃=1008`, and `P₄=1026`; all other coefficients are unchanged. The original-field count remains 11166, with a conservative local owned bank of 40. The exact native controller improvement is

`F_refined(C) − F_5512(C) = 378[1+3^(1−C)−4^(1−C)]`.

It is strictly positive for every `0<C<1`, by the concavity proof in [bit.md](bit.md). This is a completely charged source construction, not a free helper-plane hypothesis.
