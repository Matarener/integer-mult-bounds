# P1 frozen-caller lease: implementation-ready review contract

This is a proposed **new scoped caller invariant**, not a consequence of the existing per-native-call no-mutation rule. It enables the private frozen complete CLI only. The ordinary method API keeps literal fallback behavior. Parent owns the executable issuance mechanism and its complete cost.

1. After authenticating frozen caller/source bytes, the candidate driver prepares a private lease owner, unavailable through scientific module globals or user arguments. It is closed by default. Parent observational constructor wrappers record the exact circuit identity after successful original `ComplexSideCircuit.__init__`, then the exact Checks identity after successful original `Checks.__init__`, verifying its circuit link. Record exactly one successful construction for this source-fixed CLI. Recording does not alter either constructor return.
2. While the parent executes the authenticated original CLI, it opens an allowance for the expected single `verify_map` phase. Source evidence is `complex_network.py:90-93`: local circuit, local Checks, compiled roles, then one map call. It is not inferred from a filename, caller-supplied bool, refcount, equality or arbitrary ownership callback.
3. The parent-owned map wrapper checks identities using anchored operations. Only the captured exact Checks/circuit in that active phase can reserve the one-use capability. Reserve at entry, before prefix execution, so nested/reentrant entry cannot obtain it. A missing, exhausted, wrong-object or already-active capability selects ordinary fallback. Do not execute arbitrary policy code supplied by the scientific caller. An opaque parent-owned token and private identity association are sufficient; no new public general-purpose API is needed.
4. The candidate executes the original prefix once. At the original tail boundary it verifies capability identity/state and performs the proposed exact post-prefix admission, including triples, local `got` keys/values, ordinary attribute dispatch, original builtin/Fraction environment and source binding. Prefix callbacks may have changed data: only this actual post-prefix state may be cached. Unsupported state executes the literal original tail without rerunning the prefix.
5. The admitted tail has no caller-defined iteration, hashing or equality: its participating containers, triples, integers and Fraction operations are authenticated exact ordinary objects. Sets remain local to the call. The source-fixed fresh process additionally promises no concurrent or reentrant mutator of this state during the tail. This promise is explicitly a supported-execution condition, not a generic alias detector or process-security claim. Parent should deny the allowance if its execution environment has active tracing/profiling or other known mutating instrumentation. Do not introduce GC tuning or experiments; only describe/validate the actual closed caller environment.
6. Expire the reservation in `finally` on success or failure. Do not store sets on Checks, circuit, backend or owner. A second direct invocation has no implicit lease and takes literal fallback; an explicitly separate supported invocation must acquire its own new capability and rebuild all sets.

Required controls are bounded and falsifiable: wrong Checks identity; wrong circuit link; no allowance; used capability; recursive entry from a prefix callback; prefix mutation; custom collision key retained in `got`; failing prefix; and independent later invocation with changed triples. Compare baseline fallback callback order and exact return/error outcome, and count original-prefix execution once. A valid original-caller fixture demonstrates the optimized tail and private cleanup. This cannot prove safety against arbitrary process-memory mutation and makes no such claim.

Reference independence remains mandatory. Generating a candidate function with new helper names must not mutate the globals of the untouched original reference. Parent may use a distinct candidate source-module instance and preserve the baseline in a distinct module/process. Authentication/generation, constructor observation, private owner setup, entry reservation, admission and expiry are all billed.
