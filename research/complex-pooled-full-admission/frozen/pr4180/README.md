# Four-provider ordinary admission for the retained PR4088 construction

This successor connects the exact retained PR4088 mixed construction to the
PR4085 ordinary/outer admission engine. It extends the provider registry and
actual call dispatch, recomputes the idle invoice from each selected helper
width, and preserves the inherited release checks. It does not construct a new
supplier, change the selected frontier, or prove the all-size multiplication
theorem.

The default full replay passed from an isolated committed export, including
ordinary, strict and outer release. [EVIDENCE.json](EVIDENCE.json) records its
actual receipts and [REPLAY.log](REPLAY.log) preserves the executed stdout
excerpts. These are author-produced finite evidence, pending independent
scientific review.

The question is the revision-7 `supplier-boundary-audit` card's concrete missing
replay. The scientific baseline is
`12fa8c5c844be21bfefb38a19503fbd867a11244`; the exact consumed Git objects and
SHA256 pins are in [SOURCES.json](SOURCES.json). The task is refined to this
specific integration, as recorded in [TASK.json](TASK.json).

## What changes

The source adapter makes checked, literal substitutions in a fresh copy of the
inherited engine. Every preimage must match; it records each changed file's
before/after hash and each substitution's count in `ADAPTATION.json`. Frozen
predecessors are read without modification.

* The registry contains `gauge44`, `extra`, `gauge44-four`, and `extra-four`,
  with both orientations. The original literal selector and all 3,240 calls
  remain bound to their actual native programs.
* The rebind gate checks all 1,321,920 owner rows against per-call widths and
  programs. It requires the exact compact residual prefixes, chronology,
  capacity and full provider set; it recomputes idle complements and the
  complete paid profile. It does not use an averaged width vector.
* All four native closures enter the inherited provider, emission, audit,
  invoice, assembly, independent, strict and outer paths. The coverage map is
  [COVERAGE.md](COVERAGE.md).
* Optional reuse authenticates the exact predecessor engine and all 95 retained
  non-source inputs, as well as its 676-file source inventory. Native reuse
  authenticates the compiler, word, five-stage coverage and 11 scientific
  output products per provider against [NATIVE-OUTPUTS.json](NATIVE-OUTPUTS.json).

## Native evidence and invalidation

Successful status flags and a source-word hash do not authenticate a native
output. During adversarial review of this draft, changing the first warp's
left phase modulo 4 while rebinding recipe references exposed that gap. The
original exact recipe checker rejects the changed operator; the final reuse
gate also rejects it against a fixed scientific product commitment. A missing
phase stage and a false private-work-erasure claim are rejected separately.

The commitments canonicalize JSON and decompressed gzip payloads. They omit
only the root elapsed-time `seconds` fields in `SCALAR-FRAME-AUDIT.json` and
`CLIFFORD-REVIEW.json`; those fields must still be finite nonnegative numbers.
References to compressed words/programs and serialized recipes are checked
against the actual referenced bytes before normalization. All other scientific
fields, missing/extra products, compiler changes and word changes invalidate
reuse. Reformatting or recompression with corresponding valid references is
allowed.

The FOUR products were executed afresh during this campaign. The unchanged
THREE products are authenticated retained PR4085 evidence. A run records
`executed_by_this_driver`, `explicitly_supplied_cache`, or `retained_PR4085`
for each provider. These labels distinguish fresh execution from reuse.

## Reproduce

From the repository root, the bounded standard-library regression is:

```sh
python3 -B scripts/research_package.py --package research/mixed-provider-admission
```

Its three registered commands can also be run directly:

```sh
python3 -B research/mixed-provider-admission/verify.py
python3 -O -B research/mixed-provider-admission/test_binding.py
python3 -B research/mixed-provider-admission/independent_ledger.py --controls
```

The first reports `PASS_FOUR_PROVIDER_BINDING_REGRESSION`, including the exact
source pins, semantic controls and all real owner rows. This bounded regression
does not run or claim the full admission.
The last reports `PASS_INDEPENDENT_MIXED_LEDGER`: a separate implementation
enumerates binary spans and reconstructs observation windows from schedule
events without importing the original owner walker or the new binder.

The full replay requires Python 3.12 and the pinned numerical environment
used by the inherited engine: NumPy 2.3.5, SciPy 1.17.0, SymPy 1.14.0 and
mpmath 1.3.0. The driver installs nothing. Use a new directory outside the
checkout:

```sh
python3 -B research/mixed-provider-admission/replay.py \
  --work /tmp/mixed-admission-fresh
```

The expected final status is
`PASS_REPLICA_ORDER_FILL_DERIVATIVE_COMPLETE_RELEASE`. The driver first runs
the three retained PR4088 word/owner/operator gates, reconstructs the exact
PR4085 source through its independent reviews, runs both FOUR native replays,
and invokes the extended inherited engine. The inherited engine requires
assertions; the full driver explicitly rejects optimized Python.

`--checked-preflight`, `--four-native-base`, and `--four-native-extra` accept
previous outputs only after the binding checks described above. They are useful
for continuing an interrupted replay, not an exemption from those checks.
`--prepare-only` deliberately reports a non-admitted preparation status.

After a full or prepared run, the actual cache/engine challenges can be run
without repeating expensive admission:

```sh
python3 -B research/mixed-provider-admission/challenge.py \
  --work /tmp/mixed-admission-fresh
python3 -O -B research/mixed-provider-admission/challenge.py \
  --work /tmp/mixed-admission-fresh
```

They report `PASS_ACTUAL_REPLAY_CHALLENGES` for 18 positive/negative cases.
Supply `--preflight PATH` if the replay used an external checked preflight.
Only temporary copies are mutated. The recorded environment is Linux; the driver
cleans its child process groups on POSIX. Windows execution is not claimed.

Actual executed commands, outcomes, environments and unrun checks are recorded
in [EVIDENCE.md](EVIDENCE.md). Source commitments bind inputs, not proof truth
or authorship.

## Scope and limitations

This is author-produced finite verification with separate AI adversarial checks.
A second context used an event-based scanner and explicit small binary spans
to check the mixed owner widths and invoice independently of the original
owner walk. That corroboration is neither independent human review nor formal
verification.

The inherited native and ordinary/outer predicates remain the acceptance
contract; this package does not replace them with a permissive new checker.
Their successful finite execution does not discharge uniform generation,
arbitrary-size lifting, conditioning/precision, fixed-tape realization, or the
complete analytic transfer theorem. It does not assess PR4100's separately
proposed written all-size argument. Archival source-retention merges and
author receipts are distinct from maintainer scientific review.
