## 2. The new word and why it saves

In the original borrowed-word numbering, write
`h = L544`, `u = L672`, and `v = L676`. Three literal native subspaces have
ranks 1, 2 and 4:

\[
P=\langle51\rangle,\quad
Q=\langle414,51\rangle,\quad
R=\langle413,72,48,3\rangle.
\]

They satisfy \(P\subset Q\subset R\): `51 = 48 XOR 3` and
`414 = 413 XOR 3`. Both receivers start at \(P\), while the helper is at
\(Q\). Replace the original consecutive events `B[692:694]` as follows:

| Original operations | New operations |
|---|---|
| `u += h/2` at Q | `u += v` at P |
| `v -= h/2` at Q | `v -= h/2` at Q |
| | `u -= v` at R |

For arbitrary initial receiver values, the new final value of `u` is
\((u+v)-(v-h/2)=u+h/2\), while `v` becomes \(v-h/2\).
Thus the identity works with arbitrary dirty helpers; it does not assume a
zero receiver. The physical lift from \(P\) through \(Q\) to \(R\) is
checked by the native phase and warp machinery as well as scalar algebra.

Neither receiver is observed or warped before its next original contact at
\(R\). Register 672 can therefore move directly from rank 1 to rank 4.
Its old positive climbs of ranks 1 and 2 become one climb of rank 3:

\[
\Delta=-H_1-H_2+H_3.
\]

The other register paths, all entry and exit spaces, and all ordered helper
widths remain the same. Cleanup is fully regenerated, and later warp positions
are shifted to match the added scalar event. One extra forward scalar operation
and one extra cleanup operation are counted in the emitted primitive bill.
For positive saving exponent \(a<1\),
\(3^{1-a}<1+2^{1-a}\), explaining the favorable recursive tariff.

The deterministic production applier is [construct.py](native-alternatives/construct.py).
The separate admission applier is [receiver_share.py](admission/receiver_share.py).
An independently implemented [receiver review](architecture/review_receiver.py)
checks the identity, observer-free interval, all frame paths, exact profile
change and cleanup. Its proof does not import the discovery or construction
helpers. The complete derivation and native details are in the
[native report](native-alternatives/README.md).

## 4. Which levers remain

**Another native word change is the leading next lever.** This experiment
shows that changing the scalar graph can remove a paid intermediate native
frame even after the fixed-graph frame optimizer has stopped improving.
The useful search unit is an actual receiver or source sharing identity,
its observer-free interval and the complete derived cleanup. The search
should include compositions across B/restore boundaries, provided arbitrary
helper restoration and exact native phases are retained.

The four positive variants found here overlap the same `B[692:694]` pair and
the same omitted rank-2 stop. They are alternative implementations of one
gain and cannot be added. Discovery coverage, stopped searches and the known
positive source-sharing control are recorded in
[DISCOVERY.json](native-alternatives/DISCOVERY.json).

The next larger complex-supplier target is the retained BIT cap. The remaining
gap from the new lower endpoint is `0.000002687259291486913130`. Under the
complete tariff model, a sharp threshold is 53,876 additional independent
`H1 + H2 -> H3` occurrences across the whole allocation. If a uniform number
must occur in every local call, **16 additional occurrences fail and 17 pass**.
That is 18 total per call including the one actually realized here. The
[exact remaining budget](global-budget/CURRENT-REMAINING-BUDGET.json)
certifies both signs, including the outer loss. These are hypothetical
additional native rewrites, with their extra costs still to be proved.
Reaching that target would make the BIT constraint binding; it would not
establish a κ beyond that constraint.

**A changed helper inventory or native template is also open.** The exact
[current-inventory screen](global-budget/current_inventory_screen.py) accepts
a compiled native word or a complete proposed local/width histogram. It
combines local cost with the fixed-bin dual before expensive placement work.
A positive lower bound excludes that proposal at the current upper endpoint
for every clock; an explicit `--endpoint` can select a different target.
A nonpositive result only means it is not excluded; it supplies neither a
native construction nor an attained fill. Its certified width alphabet is
4 through 9, and it deliberately rejects unsupported extrapolations.

For example, an 8-to-7 width reduction with the complete local staging change
`+3 H1 + H2 - 2 H3` is not excluded. At the current endpoint, its local saving
is approximately 0.99100024 rank-1 units, compared with a dual width price of
approximately 0.98773564. The narrow favorable difference is a reason to
investigate a literal staged native identity. It is not a completed helper
repair or a priced physical fill. The exact signature and limitations are
bound in the same remaining-budget receipt. Earlier partial releases can
lose even when their raw rank mass falls, so both sides of this comparison
must accompany any new width proposal.

**More clock or owner search on this exact supplier cannot clear the new
upper endpoint.** The
[new packing certificate](global-budget/RECEIVER-PACKING-CEILING.json)
checks all 2,551 admissible bin patterns with an exact dual at the new upper
endpoint. The actual allocation reaches that ceiling to the certified
24-decimal precision. This excludes a larger reported root from any clock,
replica count or owner rearrangement
with this fixed local profile, width inventory, idle template and remainder
rule. It does not exclude changed words, banks, endpoints or templates.

**Changing only the number of pairs in the same construction family also
fails.** The architecture work builds the literal three-pair, seven-call
geometry, then checks optimistic aggregate packing bounds for the entire
generalized pair-count family. With the new local word, the best three-pair
root is below `0.001718807452513541019460`; the five-pair root is below
`0.001695230571360293530659`. Two pairs lack helper capacity. An analytic
tail bound excludes all pair counts at least six, even with optimistic
remainder permissions. Four pairs reproduce the attained new profile as a
positive control. See [the exact family certificate](architecture/evidence/PAIR-COUNT-CERTIFICATE.json)
and [architecture report](architecture/README.md) for the precise geometry
and assumptions. This rules out one broad parameter family, not all
controllers or geometric constructions.

The earlier common-chart endpoint obstruction, 31 losing partial helper
release combinations and other scoped negative results remain documented
in the unchanged [previous continuation](../kappa-boundary-continuation/README.md).
The successful edit changes a component those exclusions kept fixed.

## 5. Release runtime and reproducibility

The original monolithic auditor was killed at the container's 8 GiB limit.
The recorded cgroup evidence includes an OOM kill and a peak at that limit;
an empty log or exit signal alone was not treated as a failed mathematical
check. The unsuccessful attempts are retained as unsuccessful attempts.

The replacement runtime wrapper in [runtime-repair](runtime-repair/) is
restricted to exact pinned source bytes. It discards only unused ancestral
helper-owner tails, streams the same decompressed-payload hash, and removes
a never-read bookkeeping accumulator. Mutation checks run serially in
isolated copy-on-write children. Only the original expected exception from
the auditor counts as rejection; accepted mutants, mutator errors, unexpected
exceptions and killed children all fail. The current construction's complete
owner lists and every scientific assertion remain checked. The exact source
extension and runtime proof are separately reviewable.

Both complete owner-audit passes in the final run finish successfully, each
with all 25 applicable asynchronous mutation controls. The ordinary strict
admission also checks 139 controls, while its BIT, independent-owner and
geometry checks retain 12, eight and six controls respectively. The actual
scalar prefix is 1,478 bits within the charged 2,048-bit bound. These final
counts and source bindings are checked in the independent final review.

A later release attempt exposed a missing exact outer dependency, SymPy
1.14.0. That failed attempt is retained as failed. The final entry point now
checks dependencies before the expensive work and installs the bundled,
hash-pinned SymPy 1.14.0 and mpmath 1.3.0 wheels into its fresh work directory
without network access. The complete original outer suite, including all 19
exact evidence replays, passes with those dependencies. See
[replay-support](replay-support/) for the exact dependency provenance and
native-cache authentication controls.

The full reproduction entry point is:

```sh
python3 -B research/kappa-adaptive-continuation/run_candidate_release.py \
  --work /absolute/path/to/fresh-receiver-release
```

By default it rebuilds both complete native providers. The optional
`--reuse-native-root` accepts the shipped `native-alternatives` directory
only after authenticating its complete fresh five-stage native receipts,
scientific source hashes and all cache artifacts. The replay extracts and
authenticates the pinned original source archive, appends the new word and
review to the reconstruction chain, checks the exact expanded source manifest,
and runs full ordinary admission. The older staged544 review continues to
check its byte-identical retained parent word.

The exact runner used for the completed release is retained as
[RUNNER-EXECUTED.py](evidence/full-release/RUNNER-EXECUTED.py). After that run,
the delivered reproduction entry received one guard change: it explicitly
rejects Python's `-O` mode before source checks or workspace creation. The
[guard review](evidence/RUNNER-GUARD-REVIEW.json) verifies the exact one-site
replacement, equality of every remaining AST node and the early rejection
control. The completed release stays attributed to its actual executed
source; this guard-only successor is not described as a repeated heavy run.

The bounded reproduction entry point is:

```sh
python3 -B research/kappa-adaptive-continuation/verify.py \
  --work /absolute/path/to/fresh-bounded-replay
```

It authenticates the delivered complete native and ordinary-release evidence,
then freshly reruns the listed independent identity, physical allocation,
exact invoice/dual, geometry, runtime-boundary and modern outer checks in an
isolated copy. Its manifest identifies every regenerated output and every
retained dependency. It does not describe authenticated heavy execution
receipts as heavy computations rerun by that bounded command.

Python 3.11 or later supports the bounded arithmetic path. The recorded full
run uses Python 3.12.14, NumPy 2.3.5 and zlib 1.3.2 on Linux. The full entry
point needs NumPy available to its Python interpreter and pip for its offline
wheel installation; [requirements-full.txt](replay-support/requirements-full.txt)
records the exact package versions. Gzip containers can differ
across runtime versions even when their decoded payloads agree. The bounded
constructor and geometry replay therefore write to fresh separate directories,
compare canonical decoded content, and preserve the original authenticated
compressed containers for native receipts. The portability review documents
the distinction between payload reproduction and exact container reproduction.
