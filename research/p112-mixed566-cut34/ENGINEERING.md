# Inspection and verification boundaries

Build the Lever produced the exact branch/model checker and a separate root
reconstruction rather than a prose-only numerical claim. Prove It Works requires
the registered commands on the actual committed bytes and a read-only Git-free
export. Test Behavior, Not Implementation shaped controls that reject corrupt
inputs, missing branch evidence and a cut with no strict certificate. Separate
Before Serializing Shared State kept outputs private and serialized only the
short shared Git and task-reservation mutations.

Power of Ten inspection covers verify.py, independent.py and test_verify.py.
The inherited geometry source is authenticated before execution, with its
existing source-model mathematics retained as a dependency.

* Control flow is structured and nonrecursive. Failures propagate as exceptions;
  TemporaryDirectory owns and removes each private control copy on every exit.
* Loops have fixed bounds: 120 roots, 14400 Gram entries, 7140 unordered root pairs
  with 3780 qualifying, 896 union 82 axes, 56/28 parabolic choices, eight axis
  assignments, 4693 support-size triples, six source rows and four live files.
  Each live input or JSON file is capped at 200000 bytes. Each control subprocess
  has a 20-second timeout; each registered command has a 60-second timeout.
* Functions are below 60 physical lines. No forwarding abstraction or persistent
  shared mutable object is introduced. Computation uses local tuples and maps.
* Runtime `require`/`check` contracts remain active under Python optimization.
  They check exact pins, dimensions, counts, strict inequalities and receipt
  JSON types. Boundary values use normal errors rather than disabled asserts.
* Returned subprocess statuses and errors are checked. Exact output serialization
  compares all result fields. The optional result path must be external; default
  replay never writes. No source, receipt or canonical input is regenerated by
  the direct default commands.
* There are no pointers, reflection-based dispatch or callback chains. Standard
  argparse and unittest dispatch have their normal fixed registered targets.
  All source-execution targets are explicit, as described below.
* Diagnostics use warning-as-error normal and optimized Python, syntax compilation
  and the recorded scoped lint check. The package replay runs all three commands.

## Managed allocation deviation

Rule 3 requires fixed storage after initialization. Python integers, tuples,
dictionaries, Fraction operations in the inherited geometry and the standard
library allocate dynamically. Fixed input sizes bound live collections to the
inventories above; there is no unbounded work queue, repeated service or solver.
Temporary resources use scoped cleanup. Direct static preallocation would require
a different runtime and would expand this finite research contribution. The
recorded replay exercises the maximum fixed model and both private failure paths.
If the model becomes input-configurable, add explicit dimension/capacity checks
before expanding its loops or replace it with bounded storage.

## Source execution deviation

Rule 8 restricts generated or dynamically evaluated code. verify.py compiles and
executes only the canonical geometry.py bytes after fixed SHA256 authentication;
it does not import a potentially stale pyc. test_verify.py similarly compiles this
package's single local verify.py so direct optimized tests exercise current source.
There are exactly these two explicit targets, with bounded file inputs. Separate
independent.py executes neither target. Replacing this source mechanism requires
an import path with equivalent source/bytecode binding; it is not justified to
weaken authentication. Actual corrupt-source and usage-reclassification controls
must continue to reject before execution.

The mathematical inherited premises are not consequences of these engineering
checks. No global census, selected cold replay, compiler, native implementation,
precision, hosting or outer theorem is certified by this package.
