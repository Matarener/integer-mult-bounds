# Verification and implementation limits

Actual environment is CPython 3.12.15 on macOS arm64. All new mathematical
checks use the standard library. Ruff 0.17.1 checks the three new Python files
with `--target-version py312 --select E,F,B,SIM,I,UP,PLW`; its formatter checks
those same files. The 20 retained PR3388 files stay byte-for-byte unchanged.

The registered replay runs primary reconstruction, independent event-level
verification and eight behavioral groups. It authenticates live input bytes,
reconstructs the predecessor and all sixteen PR3388 owner maps, checks complete
fixture equality, and proves the finite closure predicate. Five actual CLI
mutations fail for the intended reasons. All576 tiny three-bin/two-call
systems and their reachable permutation states satisfy the first-visit bound.
The behavior suite also runs under optimized Python; `need` and `require`
remain active. Maximum eligible width9 and the2,288-bundle histogram are exact
integer counts, not timing or performance measurements.

The primary result and independent check can run from a committed source
export without Git. Publication checks compare the working package and declared
inputs to its exact commit, including declared source-history availability.
The retained pending source head is provenance in RETAINED.json, not a runtime
Git object. The package contains its exact source bytes and reconstructs the
published canonical owner hash. Compressed fixture equality uses its decoded
JSON payload; container hashes authenticate immutable committed inputs only.

No new physical construction is produced, so full strict admission, both
supplier prices, outer inequalities and the selected cold multiplication replay
are not rerun. Source-map auditing is separate from those obligations. Hosted
CI, formal-kernel and independent human review are not claimed.

## Engineering decisions

Build the Lever changed the deliverable from a private failed search into a
rerunnable closure certificate. Prove It Works required actual source
reconstruction, a separate event implementation and CLI rejection controls.
Separate Before Serializing Shared State kept the proof and outputs in the
owned worker and serialized shared Git and reservations with process-held locks.
Power of Ten kept the new checking core bounded and documented the retained
source and managed-runtime limits below.

All new loops have finite input or code bounds. Source JSON is at most32 MiB,
retained inventory 20 files, live source inventory at most 100 rows, final roles
exactly 69,120, calls 144, replicas 16, ports 112, capacity 48 and rank16 bins 7,168.
The closure has at most7,168 iterations and stops at the first empty addition.
Its eligibility classes have at most 144 call bits. The independent queue has
at most7,168 distinct windows, with no duplicate pending windows. The tiny
history search has at most 6 states per each of 576 systems. Test children have
60-second timeouts and temporary directories close on every exit. The generic
registered command adds its process-group lifetime bound. No recursion or
background work is introduced.

Return values, child exit codes and exact result equality are checked. All
logical assertions use ordinary exceptions, including under `-O`. New functions
fit the 60-line review ceiling. The complete source audit precedes internal
bit-mask construction; it establishes unique per-call family occupancy, so the
sum of the call bits is a set mask. The separate checker uses sets directly.
No source filters, selected values, frozen archives or shared checkers change.

### Bounded deviations

Rule 3, fixed allocation. CPython allocates dictionaries, integers and lists
during replay. The three new Python files are bounded offline checkers, not
steady-state native routines. The declared 32 MiB input bound, exact source
inventory,69,120 roles and 7,168-bin domain bound live objects; one registered
job owns them and exits after verification. Native fixed allocation is not
claimed. Follow-up would be a fixed-buffer implementation only if a production
consumer actually needs it.

Rules 4 and8, retained source and authenticated imports. The unchanged
`source3388/` reconstruction and canonical owner auditor contain longer
functions and dynamic source loaders. Rewriting pinned predecessors would
invalidate the source comparison and expand this proof into a different audit.
The new code authenticates every loaded retained file and every declared live
input before import. Only the named retained reconstruction and its named
source dependencies are loaded. The separate checker imports none of them.
Follow-up is an independently reviewed reconstruction refactor in its own scope;
no behavior, checker condition or source file was weakened here.

Rule 9, controlled indirect calls. Standard importlib loader dispatch and
unittest test discovery are required by the Python module and test interfaces.
Targets are the authenticated named source files or eight local test methods.
The semantic computation otherwise uses direct functions and shallow rows.
Source and CLI mutations exercise those boundaries. A future standalone source
reader could remove retained dynamic imports, but must first reproduce the exact
published owner payload and all intermediate admissions.

Maximum diagnostics apply to all new checking code. Retained-source warnings
and style are preserved with their exact bytes. This is a scoped proof package,
not a repository-wide compliance or source-code review.
