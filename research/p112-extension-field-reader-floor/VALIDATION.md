# Verification boundary and code constraints

The written proof, not a finite search, establishes the all-field finite-list
result. Source authentication binds the concrete geometry. The primary code
uses exact rational coefficients and GF64. The separate code uses explicit
nine-coordinate labels and independently constructed GF16 logarithm tables.
Their fields are finite witnesses for the support-transfer argument, not a
universal bound on the number of query directions.

The registered commands in VERIFY.json passed under CPython 3.12.15. Direct
optimized CPython 3.15 replay and actual CLI controls passed. The primary receipt
is RESULT.json. It records 992 exact rational-to-extension fixtures, 8,432 class
bill comparisons, 444,416 operator coordinates and 50,176 expanded entries.
The separate checker reports 133,363 prime-field coefficient tuples, 6,074
successful pointwise transfers, 1,984 binary/extension rectangular rank checks,
256 rejected binary maps and twelve successful four-direction extension
requests. It also checks a binary triangle of rank two whose rank is three
in characteristic three. Characteristic must stay two in the tariff transfer. Three non-P112 geometries
on 2, 8 and 6 ports add 416 expanded entries. An odd group and a nonorthonormal
group fail their intended hypothesis gates. These controls corroborate the
stated conditions; the written proof supplies the all-partition quantifier.

Seven optimized CLI corruptions cover input and retained-fixture bytes, Git
blob binding, expected receipt, original operator coefficients, colliding
projective images and a reducible field modulus. Each must return nonzero and
name its failed gate. The same disposable copy must pass again after all
mutated bytes are restored. Test subprocesses use a fresh bytecode namespace,
wait synchronously and have a 45-second timeout. Tests honor external TMPDIR.

## Power-of-ten inspection

All three Python files are within this package's verification boundary.
They introduce no shared service or production configuration change.

1. Control flow is structured and nonrecursive. Test copies have scoped cleanup;
   each corruption restores its original bytes in a finally block. No child is
   detached or left running.
2. Loop bounds derive from authenticated inputs or fixed finite alphabets.
   There are 112 labels, sixteen groups, 32 indicators and 496 pairs. The primary
   fixture has at most thirteen queries and eleven classes. Its reusable helper
   boundary caps lists at 32 queries. Field multiplication uses six rounds and
   inversion 62 rounds. The separate tuple domain is at most 7^6; the binary
   image domain is 4^4. All three registered commands have 120-second limits.
3. CPython allocates during computation. This is a managed-runtime deviation,
   bounded here by input byte caps, fixed geometry, six-/four-bit field values
   and one fixture at a time. No unbounded candidate store or concurrent replay
   exists. The live JSON input is at most 1 MiB; metadata/fixture inputs are at
   most 32 KiB. The output receipt is capped at 1 MiB. Interpreter and JSON
   library allocation internals are not instrumented. A future service or
   unbounded-input port would need an explicit memory representation and budget.
4. Every function is below 60 physical lines in normal formatting. Functions
   separate authenticated loading, arithmetic, support transfer, operator checks,
   rank pricing and CLI mutation controls. No forwarding API layer is added.
5. Explicit need/require checks enforce source hashes, field invertibility,
   geometry, support containment, exact equations, rank comparisons and receipts.
   They remain active under -O; they do not rely on Python assert statements.
6. Constants are immutable field tables and path names. Mutable data is local
   to a fixture or test copy. The verifiers read their scientific inputs; only
   explicit verify.py --write regenerates the package-local receipt.
7. File contexts close streams. Subprocess return codes, stderr/stdout failure
   gates and timeouts are checked. Unexpected parse/arithmetic/file exceptions
   fail the CLI. TemporaryDirectory and finally blocks own disposable state.
8. No eval, generated executable source, reflection-based discovery or plugins
   are used. The corruption tests perform five bounded literal source/metadata
   substitutions in private copies to exercise the actual failure paths.
9. Python's standard import and method dispatch are unavoidable runtime
   indirection. This deviation is confined to standard-library calls and the
   three named standalone scripts. There is no plugin registry or callback
   graph. Nested source JSON is converted once into shallow label/group arrays;
   fixtures carry direct direction and reader arrays. A native port should use
   explicit direct calls and fixed buffers if that boundary changes.
10. Replay uses -I -Werror -B; controls also use -O and a fresh cache namespace.
    Ruff 0.17.1 checks E,F,B,UP,SIM,C4,PIE,RSE,RUF and formatting. Existing global
    lint/CI policy is unchanged. Compiler warnings and native static analysis are
    inapplicable to these standard-library Python files. No type checker is
    configured for this standalone package. A typed/native port would require
    its own strict diagnostics before adoption.

The allocation and runtime-dispatch deviations are language constraints, not
claims of strict embedded-C compliance. Exact arithmetic, finite domains,
authenticated bounded inputs and fail-closed checks compensate within this
scientific replay. No performance or wall-clock improvement is claimed.
