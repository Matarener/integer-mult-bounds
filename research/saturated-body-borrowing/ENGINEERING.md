# Engineering contract and inspection

Exit predicate: one independently reviewable setup refinement, with exact source
bytes, written bounds, literal Count execution and meaningful failure controls.
The reusable worker must be clean and released after publication. The session
uses engineering-mode's autonomous-run playbook without child agents. All
shared Git mutations and reservations use the authorized advisory locks.

The observable predicate is equality of the seven returned Count values and
fit flag with the least covering-constrained integer plan. A second predicate
bounds every trial's radix-power representation by its exact stock, while the
returned rows are the exact radix power. These were specified before coding.

Build the Lever led to a rerunnable literal verifier and a separate inverse-slab
checker. Prove It Works required the actual committed Git-free commands, source
history and unchanged-export identities. Test Behavior, Not Implementation led
to plan/value/preservation/cleanup checks and real bad-source CLI controls.
Separate Before Serializing Shared State kept this package and its session
outputs disjoint, with short OS locks for unavoidable shared Git writes.

## Power of Ten inspection

1. Control flow is structured and nonrecursive. The selector calls finite
   arithmetic helpers and scoped Owned inventories. Context managers restore
   borrowed heads, source paths and caches. Successful plans transfer ownership
   once; fallback returns a fresh sentinel. There is no recursive worklist or
   trial table. Failure evidence covers invalid public arguments and one error
   injected after a completed trial. Arbitrary interruption within inherited
   arithmetic has no new transactional guarantee.
2. A power scans at most its canonical exponent's bitlength. The depth loop
   contracts by r/m and has O(h) iterations. Bisection halves an interval no
   larger than e and has O(h) iterations. Arithmetic scans and division use
   finite operand lengths; stock products are O(wh) bits and capped products
   at most twice the cap's length. Compiled GL-order construction has m factors.
   The independent census has 1920 cases and the algebra check 131072 cases.
   Literal plans cover 900 fixed cases and powers 120. The seven CLI controls
   each have a 120-second child timeout. Source exports have at most 64 package
   entries and three inputs. The loader reads four bounded members, followed
   by the retained exact 84-file archive inventory. JSON files have a 4 MiB
   limit. No service or retry loop is introduced.
3. Direct fixed allocation is not a Python guarantee. The mathematical tape
   model uses a fixed inventory and O(wh) live cells; Python allocates temporary
   objects. The actual allocation observer covers both counts.Tape and
   cardinality.Tape and checks every closed tape's blank body and origin.
   The independent host oracle and source loader are checker overhead, outside
   the claimed setup model. They do not prove production physical allocation.
4. Every new or adapted Python function is at most 60 physical lines in the
   committed formatting. Responsibilities split into arithmetic, geometry,
   level construction, search, exact materialization, loading and evidence.
   The byte-exact comparison selector is historical, unexecuted source and
   is preserved without a style rewrite. Function lengths are retained in the
   session evidence.
5. Runtime guards enforce positive canonical Count inputs, distinct exponent
   tape, compiled integer parameters, contraction, valid width exponent,
   unused role names, binary exponent digits and exact final covering. Verifier
   require calls enforce complete output equality, input preservation, origin
   positions, erased work and typed receipt equality. They remain active under
   -O. More assertions would duplicate these contracts.
6. Count roles live only in a selector scope, trial, power or returned plan.
   Profile is immutable. Source-loader changes to sys.path and pycache_prefix
   are restored in finally. No parallel loading is supported in one process;
   registered commands and their contexts run sequentially. Fixed module names
   are rejected when preloaded. No shared runtime/configuration is modified.
7. Count multiplication results are owned or immediately transferred. A small
   division's discarded remainder intentionally implements floor in the depth
   recurrence and midpoint. Owned.put returns an alias already retained by its
   inventory. no_fit drops that inventory alias only after the result dictionary
   owns it. Count close/rewind methods return None. CLI child exits and timeout
   exceptions are checked. The private-copy writer checks a full write and
   compares source/export bytes and inode identities. Existing inherited
   arithmetic failure behavior is preserved, not upgraded by these checks.
8. The source loader executes only the four authenticated regular exports and
   their complete pinned 84-file closure. No eval, generated production code or
   runtime plugin discovery is added. importlib is required to load the existing
   immutable source entry point outside Git. Test mutations have fixed names
   and replacement strings and execute only inside private regular-file copies.
9. Python has no explicit pointer arithmetic here. Data access is a shallow
   named role dictionary. The candidate closure has the single visible trial
   target. Context managers, Count's retained class dispatch and temporary test
   observers are bounded substitutions, not an open callback registry.
10. Python 3.12 runs with -W error in normal and optimized registered modes.
    Ruff 0.14.0 checks E4,E7,E9,F,B,I,UP and format, with a private external cache.
    The check covers syntax/error, undefined/unused names, bugbear, import order
    and applicable modern-Python diagnostics. No diagnostic is suppressed.
    The repository's generic registered-package workflow supplies recurring
    behavioral replay. This scoped contribution does not impose a new shared
    lint/type policy or claim static type verification for inherited untyped
    tape modules. A later shared-policy change should add recurring lint there.

## Explicit deviations and compensating evidence

- Rule 3, selector/count_math and retained Count implementation. Managed Python
  allocates during operation. Scope is the scientific tape model and bounded
  checker, not a production allocator. The role/length proof and real observer
  bound its tape resources; valid, invalid and injected-failure cleanup is checked.
  A production fixed-role compiler requires a separate source refinement before
  adoption. Python object and standard-library allocator internals are unproved.
- Rules 7 and 9, inherited arithmetic and context managers. Allocation failures
  inside an inherited Count constructor can precede ownership registration;
  framework/context-manager dispatch is unavoidable in this execution vocabulary.
  We retain only successful-return and tested completed-trial failure guarantees.
  No arbitrary allocation-failure or asynchronous interruption recovery is claimed.
  A stronger caller must specify its transaction/lease contract before adding it.
- Rule 8, runtime.py. The unchanged predecessor requires importlib and a private
  source export. Inputs are SHA256-authenticated before import; bounded regular
  members, cold module names and private bytecode namespaces constrain loading.
  Replace this host loader only as part of an actual fixed-role source refinement.
- Rule 10, inherited dynamic Python and shared CI. Static typing and recurring
  Ruff are absent from this package's generic shared workflow. Scoped strict
  diagnostics, warnings-as-errors and normal/optimized replays compensate for
  the touched implementation. Their success does not prove untyped predecessor
  internals or introduce repository-wide policy changes.
