# Validation and implementation limits

Produced by Nick Petalas. Apache-2.0.

The scientific checker uses a written all-parameter optimality proof, an
independent finite permutation minimization and literal exact operator checks.
It does not import or re-verify the predecessor construction. JSON receipts are
generated on stdout and bind the current package files. No stored expected
receipt or equality to a hand-written answer substitutes for these checks.

The permutation oracle visits all permutations at sizes one through seven and
all source subsets, derives each target image, and records the two actual
minima. The constructor is compared with every nonempty equal-size pair.
The operator oracle compares each literal conjugated Gaussian basis column
with an independently assembled matrix-entry formula, including absolute phase.
A nonsymmetric four-entry block operator checks that whole neighborhoods and
all offsets are preserved. The full-row fixtures include correlated dirty data
and noncommuting surrounding diagonals. Capacity and semantic controls remain
active under optimized Python.

The encoded large fixture checks integer geometry, sparse maps and the retained
finite K and reservoir/suffix inequalities. It does not materialize the tensor,
export actual long-axis neighborhoods or prove a physical call. An initial
log2(p)=30 development fixture lacked the requested reservoir capacity and was
rejected. The final log2(p)=32 fixture satisfies the unchanged inequality; the
all-size optimization claim and small semantic domain were not narrowed.

## Local verification

Warning-strict normal and optimized direct replays pass in 1.550 and 1.558
seconds on macOS arm64, CPython 3.12.15. These establish the replay budget,
not a speed claim. Both emit the same mathematical counts and hash-bound
receipt. AST/syntax and JSON parsing pass; maximum function length is 33
lines. Ruff, mypy and pyright are unavailable in this environment. No shared
diagnostic configuration is changed. Registered and committed-byte/source-
history checks are separate publication gates.

## Power of Ten inspection

There is no recursion, dynamic code generation, network access, subprocess,
mutable cache or concurrent state in the new code. Every loop is bounded by
an explicit input cap or a fixed finite verifier domain. Constructor validation
rejects booleans, duplicate/out-of-range blocks, unequal counts and oversized
input. Gather values are immutable and treated as trusted constructor outputs.
The literal execution path separately checks its address/vector capacities.
No assertions carry externally visible rejection or scientific acceptance.

Functions remain below 60 physical lines. The oracle's largest subset table
has 128 entries and its largest pair-minimum table has 3432 entries. The planner
accepts at most 256 neighborhoods and 65536 selected bits, hence at most 131072
mapped positions. The finite vector interpreter accepts at most 16 address
bits; the largest committed dirty fixture uses 14. Normal and optimized
warning-strict execution and AST/syntax inspection are the applicable Python
checks. Registered CI runs both warning-strict modes.

Rule: 3, fix memory capacity before steady operation.
Location: gather.py and verify.py.
Reason: Python integers, Fraction values, tuples and dictionaries allocate at
runtime; this standard-library exact research checker is not a fixed-memory
physical machine.
Scope: the explicitly capped constructor, literal interpreter and fixed
permutation/operator verification domains.
Compensating control: finite caps above, no persistent caches, no retained child
processes and scoped temporary bytecode namespace cleanup. The receipt hashes
only the finite package inventory.
Verification: direct and registered normal/optimized replay, capacity exhaustion
controls and successful return from the literal semantic fixtures.
Follow-up: redesign the storage representation before increasing these caps or
using this reference as an implementation of a fixed-tape algorithm.

No shared repository code, selected record, frozen predecessor or pinned source
is edited. Full physical routing, rounded padding disposal, supplier/compiler,
stock generation, outer recovery and proof-kernel obligations remain unrun.
