# Verification boundaries and engineering decisions

The falsifiable predicate is agreement on the complete full-prefix congruence
matrix, its Gaussian quotient and source-bound separating/admitted inputs.
This is a finite interface result. No physical implementation or supplier bill
is accepted by this predicate.

Build the Lever changed a single additional-read failure into a rerunnable
maximal-module certificate. Prove It Works required the actual optimized
public commands, complete matrix agreement, small exhaustive ring oracles,
full physical-prefix fixture and committed Git-free export. Separate Before
Serializing Shared State kept this package and external outputs separate from
other research workers; shared Git and task reservations used OS advisory locks.

## Inspected code and state

engine.py adapts PR3449's Gaussian arithmetic and literal monomial parser.
Its compressed-input read now has a decompression cap before parsing, and
prepared wrapper permutations avoid repeated parsing. trace.py owns the
scaled replay and finite matrix. module.py owns Z/4 bit-plane elimination.
verify.py owns the complete receipt comparison. independent.py imports no

reachability, direct ideal butterflies and subgroup orders. fixtures.py runs
all 2,040 literal physical events. test_controls.py owns its temporary copies
and bounded CLI children. proof_inputs.py authenticates retained proof bytes.
No shared verifier, frozen source or selected-result file is edited.

## Power of Ten inspections

1. Control flow is structured and nonrecursive. Numerical code has no process
   or network calls. CLI control children return before their temporary
   directory is removed; failures and timeouts fail verification.
2. Science dimensions are fixed at 512 complex addresses, 358 public initial
   fields, 2,025 prefix events and 2,040 fixture events. The active projection
   is exactly 38 events, including 26 native occurrences and 12 quarter reads.
   Native ranks are at most nine, with 256 pairs per factor. Basis loops have
   exactly 512 columns. The primary retains at most 64 checkpoint blocks and
   32,768 working Gaussian rows, then at most 20,000 retained rows. Real
   elimination has at most 40,000 rows and 1,024 unit pivots; binary reduction
   uses at most 1,025 attempts per row. The independent forward action list
   is capped at 200, and its fixed source supplies fewer than 64 checkpoints.
   The independent bit widths are capped at 1,024. Small oracles have 256
   matrices and 256 pair residues. The CLI test has four children with
   180-second timeouts. VERIFY.json bounds each command at 180 seconds and
   their total at 900 seconds.
3. Rule 3 has a managed-runtime deviation in all Python files. Python integers,
   tuples, dictionaries, JSON and big-integer arithmetic allocate during
   operation. Fixed authenticated sources, finite dimensions and explicit
   matrix/field caps bound live collections. The primary matrix has at most
   32,768 rows of four 512-bit planes; the retained real rows have at most
   40,000 pairs of 1,024-bit planes. Temporary parsed data, transformed vectors,
   JSON overhead and interpreter allocations also exist; no fixed-allocation
   claim or profiled byte bound is made. Source files are capped at 4 MiB,
   decompression at 16 MiB, receipts/proofs at 1 MiB and proof origins at
   16 KiB. Runtime memory overhead is not profiled. A variable-size successor
   or production implementation must supply its own capacity/allocation review.
4. Every new or adapted function remains below 60 physical lines. Matrix
   construction, arithmetic and public CLI ownership have separate direct
   responsibilities, without forwarding layers.
5. need()/require() contracts remain active under -O. They check source hashes,
   occurrence bindings, frame chronology, quarter arithmetic, integral scaled
   factors, all three actual cancellation maps, endpoint zeros, capacity,
   full receipt equality and elementary-index identities. No assert carries
   a required check. The finite index is cross-checked by another elimination
   algorithm, an exact matrix reconstruction and exhaustive small oracles.
6. State is local to one replay. Persistent scientific inputs are read-only.
   Tests mutate only owned relocated copies. No global scientific cache or
   mutable registry is introduced.
7. File reads are bounded before parsing. Input hashes precede interpretation.
   The exact source determines the data shapes; public CLI arguments are
   checked. Child status and diagnostic size are checked. Context managers
   close files and remove temporary fixtures on both success and failure.
   Writes in --emit are stdout only. Source restoration in controls is explicit.
8. There is no eval, dynamic import, generated executable code, decorator or
   runtime registration in the package. JSON parsing and ordinary Python
   module loading use the standard runtime. Their platform allocation is
   covered by Rule 3's deviation. Retained proof sources are data, not code.
9. Arithmetic calls and data access are direct and shallow. The only process
   dispatch is the fixed test child verifier, with the current interpreter
   and fixed options. No user-supplied command is executed.
10. Validation uses Python 3.12 with -W error, both normal and optimized
    verification, plus scoped Ruff E,F,B,PLE,PLW,RUF at line length 100.
    The registered Python checks recur in the package workflow. Local Ruff
    is a separate validation command because the generic standard-library
    replay environment does not supply Ruff; changing the shared environment
    is outside this package. This is a Rule 10 deviation for recurring static
    lint, compensated by the exact local lint command and warning-as-error
    registered checks. A shared lint policy or a successor dependency change
    should add the pinned static checker to recurring CI. No static typing,
    fixed-allocation, formal-kernel or hosted-CI proof is claimed.

The complete primary and secondary source matrix equality is stronger than
agreement on four rank totals. The secondary deliberately uses a different
subgroup-order calculation. Its general Z/4 arithmetic and the primary's
unit/even elimination are separately checked against exhaustive kernel counts.
These controls address mathematical failure modes rather than code layout.

`/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12`. No interpreter,

and exact fixtures must not be relabelled as a complete multiplication theorem.
