# Verification boundaries

Playbook: performance issue. The measured question is complete construction
of the unchanged hybrid mixed-point fixture. A diagnostic profile identifies
large-support interning. One compact-key mechanism was tested, then frozen at
the first exact structural gain. Five alternating fresh-process pairs include
every sample, the unchanged full output check and complete structural hashing.
No predecessor mathematical audit or wider construction search is a deliverable.

Build the Lever shaped the result by retaining an opt-in builder, an exact
oracle and a reproducible benchmark instead of a timing-only note. Prove It
Works shaped the result by comparing full small DAGs and every large DAG field,
and by forcing key collisions. Explain the Number shaped the result by reporting
the whole process as well as construction, profiling outside measurements and
retaining memory costs and sample ranges.

The new interner is iterative. Its scans are bounded by the input/node caps;
the fixed verifier has 28 oracle cases, 16 builder pairs and eight controls.
CLI parameters, full-output size, subprocess timeouts and sample counts have
explicit bounds. Each sample waits for the complete child and checks its exit
status, stderr, output, work count and signature. Output files use exclusive
creation. Runtime errors propagate to a failing command; no retry hides them.

Python allocations are a managed-runtime deviation from fixed allocation.
Inputs and nodes have explicit caps; no constant-space claim is made. Peak RSS
is measured for each serial sample. No new function uses recursion, reflection,
dynamic source execution or generated executable code. Imports select two fixed
source directories. The verifier's string replacements only check the declared
adapter diff; they do not execute generated code. The original frozen builder
retains recursive summation and planning. This is an explicit inherited-code
deviation; the CLI bounds n by 50 and support count by 25,000, and no recursion
or algorithm in those sources is changed.

New functions use ordinary structured exits and remain within about one page.
The bucket invariant, complete-support match, first-decomposition oracle and
unchanged caller structure are executable checks. New overlap and boundary
guards remain enabled under optimized Python. Existing baseline assertions
are retained byte for byte; optimized replay does not claim they remain active.

Warning-strict normal and optimized runs cover the real artifact and all
registered checks. No project-wide analyzer configuration or shared code is
changed. Frozen source retains its existing formatting and diagnostics. This
is a scoped engineering result, not a claim that every historical source
complies with these implementation rules.
