# Exact P104 coordinate symmetry

**Finite certificate with a scoped counting proof. No new kappa.**
This contribution was produced by Nick Petalas.

The literal 104-port set has exactly two coordinate-permutation symmetries.
In zero-based coordinates the nonidentity symmetry is

    (0 3)(2 8)(4 7)(5 6),

with coordinate 1 fixed. Thus a search quotient using only coordinate
permutations preserving all ports has classes of size at most two. On the
43,435 binary planes in F2^9, the exact quotient has **21,915** elements.
This gives a sharp limit on that search-reduction method, rather than a
physical supplier or a claim about every symmetry of P104.

There are exactly 395 invariant planes. More generally, the invariant-frame
counts in dimensions zero through nine are

    1,31,395,1955,4371,4371,1955,395,31,1.

[PROOF.md](PROOF.md) gives an elementary section-counting formula for
square-zero linear maps and applies it to this involution. Gaussian subspace
counting and orbit counting are classical. The new result is the exact
coordinate group and its source-specific frame quotient. No general
mathematical priority is claimed for the counting tools.

The symmetry requirement permits proper shared frames. The line generated
by port 11 is fixed. The plane generated by masks 1 and 8 is fixed although
its two generating lines are exchanged. Symmetry alone therefore supplies
no full-dimension lower bound. A particular caller must still establish
productive capacity, chronological delivery and complete charges.

## Reproduce

From the repository root, with standard-library CPython 3.12:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -X dev -B research/p104-coordinate-symmetry/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -O -W error -X dev -B research/p104-coordinate-symmetry/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/p104-coordinate-symmetry
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/p104-coordinate-symmetry --check-source-history
```

Another CPython 3.12 path may replace the local interpreter prefix.
The direct verifier prints `PASS_P104_COORDINATE_SYMMETRY` in a generated
JSON receipt with zero errors, interpreter version and source/package hashes.
It writes no files and imports no predecessor code.

The checker visits all 362,880 coordinate permutations. Its weight-seven
filter leaves 960 candidates, and the weight-three filter leaves two.
It independently enumerates all 8,283,458 reduced binary frames across all
ten dimensions and tests invariance directly. The plane count is 43,435,
and exactly 395 are fixed. Sixteen small Jordan-type domains independently
check the counting formula on 12,668 frames. Seven rejection controls and
seven semantic controls include corrupt input bytes, invalid frame domains,
a false port symmetry, a moving line and an invariant plane with moving
lines. All conditions use exceptions and remain active under `-O`.

[SOURCES.json](SOURCES.json) pins the exact input, source base, original card
and selected record. The external port file is declared in [VERIFY.json](VERIFY.json)
for replay selection and export. The catalogue and selected record are
historical provenance. The finite coordinate-group certificate and the
written counting proof are different evidence types; the census corroborates
the latter and does not replace mathematical review.

## Scope and relevance

The coverage-law card is explicitly changed to a computational geometry side
result for the current helper-interface bottleneck. The source-binding first
example passes, and the selected record resolves to conditional kappa
`781451/250000000 = 0.003125804`. No selected file is changed.

The factor-two cap applies only to binary coordinate permutations preserving
the literal port set. Larger binary linear stabilizers, signed root actions
in other coordinates, changed label sets, and several frames permuted among
themselves are outside the result. A frozen scalar word or caller may admit
only the identity. The orbit counts do not assert a wall-time saving.

No predecessor theorem, invoice or numerical result is audited. No paid word,
helper restoration, native realization, precision/tape layout, stock,
compiler, supplier admission or complete multiplication theorem is supplied.
The selected cold replay, Lean, Docker, independent human review and formal
proof-kernel review are unrun. All five selected framework assumptions remain.

Live handoffs, active Discussions, open/account PRs, local reservations and
main/merged term searches were checked before reservation and publication.
The cached overlap search covered 338 open PRs and 5,947 Discussion records,
but only 87 of 8,623 local notes. Direct Git searches of main README contents

## Open next questions

Can non-coordinate binary linear symmetries give a larger useful quotient?
Start by computing the full GL9(F2) stabilizer from the port incidence structure,
then intersect it with the actual scalar/native caller constraints. A port-set
symmetry alone is not a legal source-word relabeling, and brute force over all
invertible matrices is not a proposed search method.

Can one of the proper invariant frames support a fully charged helper
interface? Start with one explicit frame and one causal cut, then prove
independent input/output delivery, restoration and the complete signed bill.
The present finite frame counts establish none of those obligations.
Structured questions are in [TASK.json](TASK.json).

## Verification design

Build the Lever led to a deterministic checker that covers the whole finite
domain. Prove It Works led to a separate literal invariance census rather
than accepting the counting formula alone. The Power of Ten inspection keeps
all functions below sixty lines, uses no recursion, dynamic code generation,
subprocesses or external solvers, and enforces n<=9. Every RREF assignment has
at most twenty binary parameters. Only one basis is retained during the full
frame census, and the coordinate-group list has two entries.

CPython integers, tuples and generators allocate during execution. This is a
managed-runtime deviation from allocation-free steady operation. The enforced
finite input domain bounds live state; no census-sized set is stored. The
receipt hashes at most the six explicit package files and the one bounded
source file. Warning-strict normal and optimized execution supply local
interpreted-code diagnostics. This is an exact finite verifier, not a physical
fixed-storage implementation.
