# Preparation composition and phase contract

This is a source-action theorem for successful valid inputs. It is not the
complete Pi term, a physical allocator tariff, or an exponent improvement.

## Interval

Borrow a canonical Program, old raw-directory tape, positive old-prefix Count,
encoded history depth, modulus and Ring. Their complete bytes, heads and live
numerical ownership are protected. Actively used Program/directory/Count tapes,
modulus, Ring operands, encoded depth and arena templates enter at their canonical
head1 positions; the runtime rewinds these inputs and does not promise restoration
of arbitrary active-input entry heads. Unused spectator Words may enter at other
valid heads (the fixtures use head2), and those heads are preserved.
Specifications are independently compiled
from the pinned pooled R437 catalogue. Create Context; create frame control
Words; produce the full next directory and prefix Count; read its first prefix,
run SelectedBinding.validate_residual, clear the prefix; read the first prefix
again, run SelectedBinding.child_program, clear the prefix; then clear both
returned tapes, close the returned Count and Context and release frame controls.
This is precisely the preparation sequence used by residual_begin and
prepare_child at these named component boundaries, with geometry, child_extents,
fixed handoff copies and payload roles explicitly factored out. It does not
execute the entire Machine methods or establish literal top-level reachability.

The Context constructor and final disposer are included. Input construction,
source/low-vocabulary compilation, Ring construction, old Program/directory
construction and later child consumption are outside this interval, and retain
separate charges. The frozen low specification is real; the admitted history is
a generic legal fallback history, not a projected good-class assertion.

## Two radix families

For dimension d, M=d², modulus q^w, both Context.high_count and directory.produce
invoke high_power. The original implementation repeats digit_suffix M times;
ToikY's #4025 adapter validates radix_power once and repeats the same ordered
M(w-1) Count multiplications by q. Its mathematical count is unchanged. Both
implementations exhaust the radix validator even when w=1. A complete traversal
has source-residue invoice rho; the saving is (M-1)rho per high_power.

This package applies the identical credited adapter at **both** original
bindings, including counts.high_power reached by Context.high_count. Therefore
the full interval saves exactly 2(M-1)rho source-residue actions. Count and record
actions, cardinality, output bytes/order and physical duplicate prefix
multiplicity are unchanged. It introduces no tape, numerical Word or extra
simultaneously live storage. Context still creates and later closes its high
Count and cap, and the producer retains its M-digit odometer. No Context charge
is silently borrowed from an already-live fixture.

## Chronological admission composition

The #4011 adapter changes only monotone Program/Fields admission. Both validation
and child creation construct one Callback over the same history and first
prefix. Each checks exactly the same chronological predicates and finishes with
the original random-access Program restored. The child extension's later access
and output copy are unchanged. Hence there are exactly two admission savings.

Let n=h+1, r=2I+L+5, c=Q+2I+90, F=Q+2+4096(L+1). For one admission, the removed
Program reads and moves are

    3r n + (3c-1)h n/2,       n(2r+2+ch).

The removed Fields reads and moves are

    (3F-1)n(n+1)/2 - 3nF + 3nQ + 6n,
    F n(n-1) + n(2Q+6).

Writes are unchanged. Twice their sum is the complete interval's record saving.
The source index-Word saving is separately metered; it is not inferred from
record actions. The adapter preserves residue actions and adds no live tape or
Word. Its AST guards fail on unreviewed admission shapes.

## Composition argument

Directory production returns byte-identical canonical prefixes under either
radix implementation; therefore both original and cursor Callback receive the
same bytes. Cursor admission returns the same accepted state and preserves
borrowed fields; therefore the subsequent extension and disposal are identical.
The two changes affect disjoint source-action lanes (residue versus record/index)
and restore the same protected boundary state. Sequential composition gives the
sum of savings without a cross term. The verifier executes all four combinations
and checks this equality in every action lane, and checks that phase invoices
partition the entire measured interval. It also checks identical created-tape
inventory, numerical peak and slot count; this is source runtime storage, not a
full physical backing/metadata tariff.

## Actual finite source boundary

The pinned #4010 replica catalogue independently resolves native IDLE896352,
rank14, and old common COPY1603, rank7, at low identity over q=3. Both low source
specifications are compiled by the actual Specifications path; the current
source is fallback. Its actual compiled plan begins with a UNIT child. Q=6512
includes the five-bit pooled source-code widening. At h=2 the old history uses
the distinct COPY and IDLE source codes, and every field belongs to its actual
compiled context. Roots are 2048*64^h, root unit2; admitted current width2048
extends to32. The tests cover h=0/B=1 and h=2/B=2, including duplicate physical
prefixes. They are complete dimension64 high cubes only at cap1 (modulus3);
no nontrivial 3^4096 cube is executed.

The universal source-code composition proof assumes every old/current context
is admitted, enough capacity, positive cardinalities and no concurrent mutation.
Malformed-input general rollback, selected source reachability, physical gather,
transport, geometry, coefficient evaluation, full CALL/RETURN, stock and kappa
remain separate obligations. This package cannot promote the low-level saving
to a complete recurrence.
