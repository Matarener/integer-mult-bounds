1. New code has structured exits and no recursive calls. Context managers and
   finally blocks restore factory specialization and close Count ownership.
2. The source inventory is bounded by 40 files, canonical files by 32 MB and
   retained members by 200 KB. The retained archive has exactly 28 members.
   CLI copies have at most 64 paths, three child commands and 30-second child
   timeouts. Fixtures have at most 8,192 columns and a fixed six-case schedule.
   The inherited strict Count adapter caps values at 4,096 bits. New test
   permutations loop over the checked finite payload length.
3. All physical banks and scratch roles are allocated before run(). Numerical
   width admission is inside the sealed outer pool. Fixture construction and
   source compilation are outside measured execution and charged separately.
4. Functions are checked against the repository's approximate 60-line page
   limit after formatting. Setup, final endpoint checking, input construction
   and completed-return controls have separate ownership responsibilities.
5. require/need enforce source identity, exact plan fields, stock quotient,
   alias/head/output contracts, independent columns and final erasure. These
   remain active under optimized Python. No assertion-only acceptance exists.
6. New state belongs to one engine, fixture, temporary directory or measurement
   scope. The inherited shared factory mutation is scoped and restored. Suites
   run serially; no concurrent artifact regeneration uses this checkout.
7. File writes and child exits are checked. Cleanup owns only returned outputs
   and allocated Counts. Return aliases fail before ownership is assigned.
8. New code has no eval, code generation or macro expansion. Authenticated
   module imports are finite source loading, not runtime numerical decoding.

   Observers check bytes and masks and do not choose executable instructions.
10. Scoped Ruff E4/E7/E9/F/B/I/UP, Ruff formatting, warnings-as-errors compilation,
    CPython 3.12 normal/optimized registered science and controls, final-HEAD

## Explicit deviations and inherited limits

Rule 3, fixed memory. CPython allocates managed containers, Count/Lease views,
imports and checker provenance masks. The physical theorem concerns fixed tape
roles, not Python heap. Enforced finite fixture and source bounds constrain this
checker; no Python heap or host allocation bound is claimed. The next selected
caller must supply its own physical compiler/refinement argument.

Rules 2, 8 and 9, inherited macros and specialization. Unchanged predecessor
arithmetic and completed macro loops use decreasing encoded counts and source
proof arguments rather than newly inserted host counters. The loader and
scratch pool use module specialization and bounded compiled callback targets.
Rewriting frozen sources would destroy the inspected source boundary. Archive
authentication, sealed constructors, exact endpoints and lease checks constrain
their use. A future independently checked source refinement must account for
every such path; these fixtures do not constitute that refinement.

Rule 2, new loader cleanup. runtime.installed enumerates the CPython module
namespace to close nested retained TemporaryDirectory owners before unloading
their modules. That namespace has no new enforced cardinality cap. This is a
platform-metadata deviation confined to fresh isolated CLI processes and the
authenticated finite import closure, not a physical execution loop. Registered
command timeouts bound the checker run. Reusable library support must replace
that enumeration with an explicitly owned, bounded loader-cleanup inventory;
arbitrary concurrent namespace mutation is outside this entry point.

Rules 1 and 7, failing inherited macros. The physical predecessor promises
successful admitted execution, not transactional interruption recovery. New
return-adapter rejection paths are checked, but arbitrary allocation failure or
interruption inside a root is unclaimed. The next caller cannot silently assume
stronger recovery. The original failed run is retained, rather than counted as
successful cleanup evidence.

Rule 9, observation. traffic.py temporarily wraps Tape operations to count
their invocations; the provenance observer wraps reads/writes to track affine
columns. Both scopes restore the original methods, and neither counter supplies
operands or selects branches. Final normal/optimized output equality checks
their deterministic evidence. These counts exclude finite compilation, host
control and observer state; they are not hardware or asymptotic speed claims.
