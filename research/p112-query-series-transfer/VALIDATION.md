# Validation contract and limits

## Mathematical and finite evidence

PROOF.md supplies the finite-induction closure argument. It applies to any
number of independent marks satisfying the stated transfer premise. Only
the two-mark non-Fano application is supplied here. Author-written proof
complete is distinct from human or formal acceptance. Independent human and
formal proof-kernel review are unclaimed.

verify.py uses rational Gaussian elimination and GF4 elimination on every
subset of each augmented configuration. independent.py imports no package
code: rational minors determine base predicates, the exact collapse law
determines old expanded predicates, and every GF4 linear functional determines
new predicates via a downward subset transform. It uses a fixed independent
multiplication table. Its witness tariff uses actual binary Gram entries and
bit elimination; the primary uses the identity-label intersection formula.

The finite suite contains 21 base cases, 210 one-step series/parallel cases,
and 24 two-step cases at the three representative marked pairs. Each ordered
case records both premise counts. RESULT.json freezes the combined hash and
counts, and WITNESS.json supplies all actual numeric factors and labels.
Neither checker imports Git or fetches mathematical data.

The real optimized CLI corruption harness runs six mutations: a wrong reader
coefficient, a wrong frozen count, a GF4 template reduced incorrectly to its
binary version with its source hash updated, a broken source hash, a missing
series direction in the primary implementation, and an incorrect OR collapse
for a series split in the second implementation. The four data mutations
run against both CLIs; each implementation mutation runs against its affected
CLI. Four positive runs before/after restoration surround ten rejecting runs.
All subprocesses have a 30-second bound. Private copies are owned regular
files on distinct inodes, and canonical file hashes must remain unchanged.
No file mode or shared runtime is changed.

A development control initially expected the final result-mismatch diagnostic
for the missing-direction mutant. The earlier explicit witness-binding gate
correctly rejected it instead. The harness now requires that earlier diagnostic.
This correction does not change the scientific condition or freeze a new result.

## Engineering inspections

Build the Lever required the two retained rerunnable checkers. Prove It Works
required actual optimized CLIs, corruptions, registered CPython3.12 replay,
committed-head source-history checking and Git-free replay of exported bytes.
The exact commands, environment, immutable per-file hashes and exit statuses
are retained in the publication session report; hosted CI is a separate check.

Power of Ten inspection covers these three new scripts only:

1. Control flow is structured and nonrecursive. Subprocess failure propagates;
   temporary-copy cleanup runs on success and exceptions.
2. Finite bounds are 7 base elements, 24 quadrangle automorphisms, 21 marked
   pairs, 255 cases, at most 7 queries/5 dimensions/512 augmented subsets,
   at most 4^5 functionals, and minors of size at most 4. The control inventory
   is at most 20 files of 65,536 bytes. Every wait is a bounded subprocess call.
3. Python and Fraction allocate during calculation. This is a managed-runtime
   deviation limited by the preceding capacities; there is no growing worklist
   or concurrency. A fixed-capacity native implementation is a separate task
   if this bounded replay ever needs one.
4. Every function is below 60 physical lines in the final normal formatting.
   The longest is the separate witness validation/Gram calculation.
5. Explicit executable `require`/`check` contracts stay active under `-O`.
   They validate fixture size/shape, field range, independent marks, all
   implications, literal coefficients, factor ranks and final evidence.
6. Mutable state is local; module constants are read-only. Checkers own no
   shared writable state. Only the fault harness writes private copies.
7. Subprocess return codes, output markers, diagnostics, timeout and copied
   byte counts are checked. Fixture parse failures propagate. The finite
   fixture objects are trusted published data after boundary checks, not an
   unbounded public-input interface.
8. No dynamic evaluation, code generation or runtime registration is used by
   scientific replay. The fault harness changes one exact source snippet in
   private files and requires a unique match before launching that CLI.
9. Data access is shallow and calls are direct. Dynamic subprocess dispatch is
   restricted to two explicitly named script paths under one private directory.
10. Optimized warning-as-error Python runs, Ruff correctness/import/modernization
    checks and formatter checks are recurring gates. A separate `--select ALL`
    diagnostic is retained, not reported as a passing gate. Its annotations,
    per-function docstrings, named-constant, namespace/copyright, CLI-output and
    collection-style policies exceed this standalone certificate's chosen
    repository convention. Literal mathematical sizes remain visible, and
    adding package wrappers or constants solely for those policies would add
    review burden. No diagnostic suppression was added. Future reuse as an
    importable library should add typed public interfaces and API documentation.

The maximum-diagnostic review also checked the single static subprocess call
and bounded mutable bit-row elimination. Neither launches external commands
from fixture text nor mutates caller-owned mathematical inputs. Ruff formatting
and import ordering fix the local style findings without changing evidence.

## Scope not verified

No selected cold replay, Lean, Docker, physical/native implementation,
complete consumer or outer multiplication proof was run. The value 14 is a
finite witness bill, not a minimum. This theorem excludes only the stated
query-rewrite family. It does not settle arbitrary six-term rank-(4,4)
configurations or split-target contracts. Selected-frontier files are unchanged.
