# Reuse checked ancestors within one complete replay plan

The opt-in planner reduces complete local planning time by **8.27%**, from
median **0.898166250 s** to **0.823856000 s** over nine alternating pairs.
All eighteen commands succeed and produce identical selection JSON and sparse
warnings for **3,788 packages**, including **3,759** manifests authenticated from
sparse HEAD. Before times range from 0.884204958 to 0.970985542 seconds; after
times range from 0.801496583 to 0.867351208 seconds.

This is a scoped equivalence proof with finite performance evidence, not a
mathematical bound or supplier-admission result. This contribution was
produced by Nick Petalas. The selected frontier is unchanged.

## The change

[JoyboyBrian's PR #6087](https://github.com/CrocSwap/integer-mult-bounds/pull/6087)
already avoids checking an identical full input path repeatedly within a plan.
Different inputs and manifests still share ancestors. The new [planner.py](planner.py)
checks each distinct existing ancestor once and reuses that result only within
the same invocation of `plan_details`.

```text
begin plan with an empty prefix table
for each canonical path:
    reuse already checked prefixes
    inspect new components for symlinks and junctions
    stop at a missing component or a regular-file ancestor
run the unchanged selection and manifest-hash logic
discard the table on success or failure
```

The command authenticates the exact shared runner against [SOURCES.json](SOURCES.json),
loads those bytes into a private module without consulting bytecode, and temporarily
replaces only that module's path guard during a synchronous plan. Its parser,
sparse-manifest authentication, Git environment, exact HEAD/diff spelling,
complete-input cache, selection, hashes and output logic remain in use. It does
not modify the shared runner or accelerate the default CI command. A changed
runner fails authentication until this package is deliberately updated.

## Scoped equivalence proof

The inherited contract requires the checkout to remain stable throughout one
plan. Each `lstat` therefore returns the same metadata or exception for a given
path during that plan. Every call first runs the original canonical-path validator.
The first uncached lookup performs the original symlink and junction tests.
Only a checked directory permits descent. A checked regular file permits the
same return as the original guard: a descendant would raise the suppressed
`NotADirectoryError`. A missing prefix similarly suppresses deeper lookups.
Thus the cached result reproduces every later decision under that prefix.
Permission and other unexpected errors propagate with their original type and
message and are not cached. Rejected symlinks and junctions are never cached.

Induct on the finite components of each path and then on the paths visited by
the unchanged planner. The replacement guard returns the same path or raises
the same error at each visit. Every manifest read, input-validation result,
selection cause and manifest hash is consequently unchanged. A table is created
inside each `plan_details` call and the guard is restored in `finally`; the next
plan must inspect the filesystem again. Concurrent filesystem mutation is
outside the inherited contract. The private module has one synchronous caller.

## Evidence and reproduction

[BENCHMARK.json](BENCHMARK.json) is generated by [benchmark.py](benchmark.py).
It binds implementation, harness, manifest and shared-source hashes, Git path
inventory and sparse configuration, interpreter, platform, all eighteen samples,
error count and stdout/stderr digests. Each timed command includes process
startup, candidate source authentication, all planning and captured output.
Every pair reverses which side runs first. No precomputed result is timed.

An untimed profile put repeated component traversal and `lstat` work in the
original guard at about one quarter of complete baseline planning time. The
measured end-to-end reduction is smaller; JSON, Git blob reads and timeout
supervision still run. The machine had 18 logical CPUs and load averages 2.92,
3.19 and 2.79 at the initial profile. Both sides use identical interpreter flags
and the existing caches. These are warm-filesystem macOS measurements on a
shared machine, not cold-cache or Linux/Windows speedup claims.

From the repository root, using the local interpreter:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/replay-planner-ancestor-cache/planner.py --changed-since origin/main
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/replay-planner-ancestor-cache/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -O -W error -B research/replay-planner-ancestor-cache/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/replay-planner-ancestor-cache
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/replay-planner-ancestor-cache --check-source-history --check-modes
```

Another standard-library CPython 3.12 executable may replace the absolute path.
The direct marker is `PASS_REPLAY_PLANNER_ANCESTOR_CACHE`; the registered marker
is `PASS_REGISTERED_RESEARCH_PACKAGE`. Each direct run generates a receipt bound
to every package file and writes no package files. Optional timing reproduction,
which CI does not run:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/replay-planner-ancestor-cache/benchmark.py --pairs 9 --output /absolute/scratch/benchmark.json
```

Future checkouts and hosts need not reproduce exact times or package counts.
Registered replay checks the committed measurement's bindings and arithmetic.
The direct verifier covers 18 path cases, four symlink/junction cases, two lookup
failure cases, eight complete fixture-plan cases, changed-source rejection and
measurement-receipt validation. It checks every fixture consumer, duplicate
inputs, component ordering, package changes, shared controls and manifest hashes.
Later calls reject a new alias and recover after its removal. Both successful
and failed calls restore the guard. Normal and optimized modes pass. Fixture
Git inventory is explicit; the real timed commands perform original Git and
sparse authentication.

## Resource and diagnostic limits

Added loops visit finite path components, manifest inputs or fixed test cases.
The cache stores at most one entry per distinct prefix encountered in one plan;
memory is proportional to the total stored prefix characters and is released
when that plan ends. Registered commands have 120-second timeouts. Each optional
benchmark subprocess has a 60-second timeout and the harness permits at most
twenty pairs.

Python's managed allocation is a Power-of-Ten rule 3 deviation limited to this
finite table. Its compensating controls are the finite prefix bound and release
at the end of the call; tests check reuse and next-plan invalidation. Heap peak
was not measured. Shared integration requiring a hard memory limit must first
measure and bound this table for its repository-size limit.

Executing the authenticated existing runner is a rule 8 deviation: the input is
one SHA256-pinned source, not generated code. A changed-source control rejects
before execution, and the namespace is private. This preserves inspectable
shared checks without duplicating them. Reassess this loader if the runner's
dependencies or execution model change.

Warning-strict normal/optimized and in-memory syntax checks are used. No Python
linter was installed locally. Native Windows junction execution, a fully
materialized checkout benchmark, CI timing, selected supplier replay, Lean,
Docker and complete multiplication obligations are unrun. Independent human
and formal proof-kernel review are unclaimed.

## Open next questions

Should this validator be incorporated into the shared planner? First exercise
real Windows junctions and measure complete plans in a fully materialized
checkout. Those platform and workload checks remain the blockers. The present
opt-in command provides a reviewable implementation and reproduction harness.
