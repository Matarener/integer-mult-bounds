# Actual verification keys and a negative conditional cost screen

This package preserves the complete PR5864 contribution-key corpus, exact ordered replay outputs, measured source context, and negative cost evidence. The requested **further 15% reduction in both complete frozen-qualifier wall time and CPU remains unmet**. The scoped audit is complete; that is not completion of the broader performance goal. No private integer owner, GMP integration, production cache replacement or GC-policy optimization is admitted.

The useful result is reproducible evidence about an actual workload, including an unsuccessful engineering nomination. It does not change a selected result, certify a κ, prove a multiplication theorem, establish a universal performance barrier, or supply an upper bound on actual complete-runtime savings.

## What was measured

The original complete qualifier ran with its original cache and a reversible diagnostic hook that retained every existing seven-PyLong key before lookup. Capture was enabled only during the source-bound actual invocation. Original Fraction arithmetic, miss callbacks, F(0), ordered score additions, source iteration, Observation, exact counters and full signed-witness comparisons remained intact. The qualifier retained 25,984 events, 799 coordinates, 120 finite fixtures and the frozen source result. Its actual output digest remained `954c7448ff74d78753828e9623ad44c46da9e5ce459420b6e50a5d47294250b9`.

All **2,579,750 keys** were captured, with 3,587 weight tokens. The resulting corpus was replayed separately through the unchanged finite key comparator: PyDict plus fresh seven-tuple/FIFO storage versus a private open-address table with full numeric equality, collision handling, tombstones, rehashing and owned references. Both timed loops used opaque miss IDs and omitted descriptors, Fraction arithmetic and callbacks. This isolates key handling; it does not establish literal Fraction-cache API or general GC compatibility.

One predeclared B,C,C,B sequence used fresh cache state in every arm, with no warmup or retry. Every ordered ID, hit/miss/eviction flag and 80-operation/final-partial prefix matched a separate literal Python dict/deque oracle. Each arm reproduced 2,252,966 hits, 326,784 misses, 310,400 evictions and 16,384 residents. Both custom runs paid for 23 natural rehashes.

The smaller paired difference was **0.160740552 wall / 0.160850468 CPU seconds**. It is measured on actual keys, without synthetic extrapolation, but is not a complete-verification gain. Adding that difference to the earlier diagnostic integer gross region gives **4.845453128 / 4.844279183 seconds**, even with zero retained integer runtime and zero new bill. Both values fall below the necessary **5.199267809 / 5.170500000-second** thresholds. The declared provisional 0.5-second reserve makes the failure larger.

That integer anchor comes from a different diagnostic run and includes clock overhead. The sum is a conditional screening calculation, not a same-run removable-cost bound or achieved saving. Real retained integer work and future construction/build/validation costs remain nonzero and unpriced. The result rejects this nomination without proving global impossibility.

The complete cold capture/replay command cost **42.639824143 seconds wall / 42.54 seconds CPU**, including both compilers, original qualification, capture, checks, serialization/readback and output persistence. Sampled peak process-group RSS was **437,825,536 bytes**. Source bytes/modes remained unchanged and stderr was empty. One post-qualifier cleanup collection was charged outside replay timings and changed no GC policy. Capture changes allocation and object lifetime; its whole-command timing is diagnostic, not a replacement baseline sample.

## Bounded verification

Use Linux 64-bit CPython 3.12 with an existing C compiler and Python headers. No Python dependencies or installation are requested. The registered commands are:

```sh
python3.12 -B research/verification-key-headroom/verify.py finite
python3.12 -B -O research/verification-key-headroom/verify.py finite
python3.12 -B research/verification-key-headroom/verify.py data
python3.12 -B research/verification-key-headroom/verify.py context
```

`finite` compiles fresh unchanged comparator code outside the package and runs all 82 controls, including equality, collision, FIFO, rejection and ownership/failure cases. Failed build/control evidence is retained at the reported external path. `data` authenticates immutable inputs before decoding, uses bounded plain protocol-5 objects with fresh memos, and streams every key through an independent literal oracle while comparing all canonical outputs. Pickle is accepted only from pinned own data; unsafe object-construction opcodes and trailing bytes are rejected. `context` reconstructs and checks all 164 baseline files and 177 measured stage files, exact C reversal and official PR5864 export equality, without scientific execution.

Code/data manifests are checked before execution. Direct source loading avoids stale bytecode, and deliberate `-O` propagates into loaded controls. Read-only Git-free exports are supported by restoring historical modes only in a fresh external reconstruction. The official PR5864 tar is the existing declared repository input, not another provenance copy. These commands do not rerun historical timings or capture.

An explicitly requested future reproduction may use `replay_capture.py --evidence NEW_EXTERNAL_DIRECTORY`. It invokes the reconstructed original guard once under 180 seconds and 1 GiB, retains failures, and compares every regenerated key value/order to the committed corpus. It is **not registered for publication or CI**. Its new timings cannot replace archived samples or reopen the failed gate. The original runtime/source constraints still apply. See [VERIFY.json](VERIFY.json) and [VALIDATION.json](VALIDATION.json) for registered scope and execution status.
