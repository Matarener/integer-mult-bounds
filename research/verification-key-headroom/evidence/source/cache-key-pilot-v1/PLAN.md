# Finite key-only source plan

Status: SOURCE PREPARATION ONLY; no compiler, scientific import or workload has been run by the author. Parent alone may freeze and run this one pilot. This is not a production Cache/Event replacement or complete performance claim.

The original reference is `../baseline-public/native_cache.c`, especially contribution lines 99–137. It constructs a fresh seven-PyLong tuple, looks it up in a Python dictionary, invokes the literal Fraction callback on misses, validates four Fraction results, then evicts FIFO and inserts. member() already uses direct tp_descr_get. No descriptor-call saving is claimed.

Both pilot arms accept pre-extracted exact seven-int tuples and return opaque monotone miss IDs. Their timed calls exclude Fraction construction, arithmetic, miss callback/result type checks, descriptor extraction, Event.apply, score additions, source iteration, and row updates. Both retain fresh key storage, numeric equality, hash collisions, FIFO capacity, result ownership and ordered hit/miss/eviction outputs. Both include identical input validation, output allocation and prefix counters. Private cache/key destruction is inside each timed C call; destruction of returned output packets occurs after the clock and is paid by the outer command. These omissions prevent full Cache/API compatibility and prevent applying the synthetic per-call difference as a measured PR5864 saving.

The baseline arm preserves the relevant tuple/dictionary/FIFO sequence, but uses opaque IDs instead of the actual four-Fraction callback. The custom arm stores seven owned exact PyLong references per resident entry, probes with a borrowed stack key, hashes every field using public PyObject_Hash, compares all seven fields with public numeric equality, resolves collisions by linear probing, retains tombstones, and performs paid same-size rehashes at 75% occupied-or-tomb occupancy. Table size is the smallest power of two at least twice capacity, with a minimum of eight. FIFO ring position is stable across rehashes; hits do not refresh FIFO. No private integer layout, GMP ABI, arbitrary callback, mutable stored value or general GC object is introduced.

Frozen proposal: one cold child, inner order B,C,C,B; no warmup, retries, calibration subtraction or favorable-repeat replacement. Each timed call has 32,768 event contexts, 80 lookups/context, 2,621,440 total lookups, 327,680 distinct miss keys, seven hits/miss and capacity 16,384. Each event uses one small q. Fields represent small normalized dyadics with at most 20-bit old numerators, powers-of-two denominators no larger than 4096, and tokens 0..3586. Two independently allocated equal key tuples alternate within repetitions, including non-interned equal PyLong values. This is deliberately synthetic, not an actual PR5864 trace. Full expected misses/hits/evictions are checked by a separate literal Python dict+deque oracle.

Broad untimed finite controls include 8192-bit signed values, zero, separately allocated equal integers, exact-PyLong/hash/table collisions, capacities 1/2/3/16/16384, FIFO turnover, no refresh on hit, tombstones and natural rehashes. Rejection controls cover bool, subclasses, foreign values, malformed rows and bounds. Declared failure points cover temporary lookup ownership, value creation, eviction, stored ownership, output ownership, explicit hit-result cleanup, and pre-publication custom rehash allocation failure; raw reference counts before/after must match. These hooks do not claim exhaustive allocator fault coverage.

Every full ordered output is retained as native-endian unsigned 64-bit result IDs, one flag byte per lookup (0=hit, 1=miss, 3=miss+eviction), and JSON prefix counters after each 80 operations/final partial context. B and C are compared exactly to the independent oracle, not only by digest. All four samples are kept. Byte order and item size are recorded.
