## Capture source and object ownership

The copied native_cache.c has three declared edits: separate capture state and
methods, one hook after the original seven-item key is fully constructed, and
exposure of the three capture methods. The hook retains that existing tuple;
it does not reconstruct, normalize, serialize or deduplicate its fields. All
original numeric operations, Fraction callback, F(0), score ordering, iteration,
row updates, FIFO operations and Cache.statistics remain in place.

An independent directory byte comparison found only native_cache.c and
NATIVE-SOURCE.json different from the original baseline tree. Independent

78ed2e240ee40ce4989a4718e77e8b3967b092d2bf8c900124a26942c98a14cb.
The runtime source check additionally requires the exact 164-file census, all
original/copy modes, all unchanged bytes, the capture C hash and its loader pin.

capture.inc owns a list reference while capture is active. Appending acquires a
reference to the original tuple; normal contribution cleanup retains its original
behavior. All tuple fields are the already-qualified exact PyLong objects, so
extending their lifetimes introduces no foreign finalizer/cyclic-value domain.
The fixed 2,579,750-call ceiling rejects an extra key before appending it.

Take requires exactly that count, converts only the outer list to a tuple, then
clears capture state and the list owner. It preserves every key and field object
identity. If conversion fails, the list remains owned until the finally-path
abort. Abort is idempotent and clears active state before releasing the list.
Allocation failure, incomplete capture or duplicate capture cannot become a
successful partial dataset. Retained-field lifetime and altered allocation/GC
costs remain real diagnostic costs; they are not performance improvements.

namespace seam in memory. The wrapper is installed only around the original
actual native_trace factory. It requires one factory and one invocation whose
word digest equals the source-bound expected-word digest; other words call the

The parent explicitly authorized one gc.collect after all original qualification

## Complete corpus retention and unchanged replay

actual_driver.py writes a versioned gzip/pickle-protocol-5 stream containing all
keys in original order. Blocks contain at most 4,096 keys; pickler and unpickler
memos are cleared at block boundaries. Streaming readback compares every block's
values/order against the captured tuple and rejects trailing objects. File
hashing is streamed. Arbitrary-width signed PyLong values are preserved without
fixed-width packing. The archive expressly does not promise cross-block object
identity; timed replay uses the original live captured objects, not readback
replacements. There is no second materialized full corpus or sampling fallback.

The approved keypilot.c, load_pilot.py and run_pilot.py hashes are unchanged.
The historical synthetic generator/entrypoint remains in that helper module but
is never invoked by this driver. Only its approved finite suite, literal Python
dict/deque oracle, full-output writer and comparison helper are reused.

The oracle must reproduce the actual source calls/hits/misses/evictions/residency
and capacity exactly. B1,C1,C2,B2 each use every captured key and fresh private
state. Every opaque miss ID, hit/miss/eviction flag, 80-operation/final-partial
prefix and core statistic must equal the oracle. Baseline rehash metadata must
be zero; each custom replay must exercise natural rehashing. The full corpus,
oracle, all four outputs, compiler receipts, finite controls and failed outputs
are retained. No timing sample can be discarded or replaced.

The capture cache uses the original -O2/-Wall/-Werror loader. The unchanged
key comparator uses shared -O3/-Wall/-Wextra/-Werror flags for both replay arms,
checks its compiler-input snapshot and rejects compiler output or failure.
Neither replay arm performs Fraction arithmetic, descriptor extraction, callback
validation, score updates or complete qualification. Actual values/order and
field identities are now observed, but replay still changes the working set and
arithmetic/allocation interleaving. A key-only delta is not a complete saving.
