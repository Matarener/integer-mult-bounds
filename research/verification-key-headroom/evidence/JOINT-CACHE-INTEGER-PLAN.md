## Candidate whose cost design this could inform

The joint hypothesis combines two distinct changes, neither implemented here:

- One private integer state per Engine invocation, removing repeated row
  validation/copying and per-event return packets while preserving exact
  arbitrary-width semantics, all byte streams and all required snapshots.
- A private native key representation or lookup table using stack probes and
  owned stored keys, avoiding fresh seven-tuples on hits and repeated hashing
  of event-constant q/token parts. Full seven-field integer equality, collision
  handling, original FIFO/counter behavior, same cached return identity,
  exactly one original Python callback per miss and original failure controls
  remain mandatory. No result/state/cache crosses a backend or invocation.

Key interning is metadata ownership, not arithmetic-result sharing. It must
preserve the existing canonical key domain and all negative/fallback controls.
Changing hashing does not authorize changing equality or omitting collision
checks. Moving insertion or eviction across the original callback is not
permitted merely to save time. Python Fraction arithmetic and score-update
order remain unchanged; this is not the stopped rational-arithmetic route.

A checked 128-bit integer fast lane is conceivable only as a private tagged
representation with a complete arbitrary-width Python-int fallback. Every
conversion and intermediate operation must detect overflow before undefined
signed C behavior. In particular multiplication before exact division,
`abs(INT128_MIN)`, signed shifts, large exponents, weighted score products,
and cancellation after a too-large intermediate require correct fallback.
A small final answer does not justify computing a too-large intermediate in
128 bits. Promotion must occur before performing the unsafe operation. All
external values/types remain the original exact Python integers/Fractions.

Scale 55 or small sampled outputs alone do not prove that the full workload
fits 128 bits. No width census or coverage assumption is supplied here. Public
CPython 3.12 conversion costs, tagged-state ownership, fallback frequency and
materialization must be paid. A future design must specify platform support
or use the unchanged arbitrary-width path when the compiler lacks the fast
lane; unknown platform behavior is not admissible. No fast lane is implemented.
GMP is not nominated in this round: local headers are absent and its dependency,
build, conversion and independent validation bill is unpriced. Nothing was
installed or fetched.

## Minimum future bill, if the envelope survives

Retain all original scientific/native/Observation/finite/custody obligations and
all signed/large-integer/formatting cases. Add new owner lifecycle, alias and
returned-mutation isolation, failed-run cleanup, reentry, buffer ownership and
allocation-overflow controls. Validate every newly moved branch, exact division,
peak/tie/Pareto and snapshot rule. For a fast lane, test below/at/above both signed
limits, all promotions, overflowing intermediates with small final results,
negative shifts/division cases, and large fallback-only values against the
unchanged Fraction oracle.

For new keys, retain all key-field, canonical equality, hash-collision, FIFO
wrap, exception-before-eviction, callback reentry, metadata mutation, source/
getter/callback drift and capacity/fallback controls. Add borrowed-probe versus
owned-key lifetime, q/token context identity, large-int key equality, collision
chains and insertion-failure cases. A new layout must not turn a stale slot
reference into a valid key. Price fresh source/runtime binding, cold compiler/
link/load, all added tests, full caller comparisons, snapshots, conversions,
memory and exact-source publication checks. The provisional 0.50 reserve does
not establish that this bill fits.

## Next gate: one cheap unprofiled custom-key corpus, before integer construction

The next permissible work is a **bounded custom-key feasibility design and
finite-corpus comparison**, not private integer state, a 128-bit lane, GMP or a
complete new caller. This appendix does not prepare or execute that prototype.
Its purpose is to reject an unhelpful key representation cheaply before paying
for the larger owner. The existing direct descriptor access is already native;
the actual target is temporary seven-tuple ownership/hash/lookup work.

Before its first build, freeze one key representation, source identity, ownership
contract, deterministic corpus, repetition/noise rule and command budget.
Do not select among multiple layouts or revise the corpus after timings. Use
one unchanged original-cache baseline and one candidate that changes only key
bookkeeping. Keep every original Python contribution callback and returned
Fraction value/type, cache hit identity, callback order, FIFO counters and
failure rules. Use separate fresh cache instances/processes; share no computed
results or PASS receipts between implementations.

The fixed corpus should exercise the existing public contribution interface,
with original callbacks on misses, and include:

- Each of the seven key fields varied; equal canonical q values in different
  Event instances; repeated hits; misses; capacity 1/2/16 and one bounded full
  16,384-entry FIFO wrap. No change to token equality or capacity semantics.
- Deliberate full-hash collisions and distinct keys, zero/negative values,
  large integer components beyond 128 bits and at least the existing 8,192-bit
  fallback cases. Stack probes must never escape; stored keys must own all
  required references, including q/token context data.
- Exact ordered result tuples and original statistics after every step, exact
  callback argument/call sequence, hit return identity, callback failure before
  eviction, reentry and input/metadata mutation controls. Preserve the original
  finite native suite; its apply/F(0)/score code remains unchanged.

Keep the corpus bounded and declared in advance, for example no more than
65,536 contribution calls per process, rather than extracting or replaying the
entire actual word to rescue a weak micro result. Do not turn the old 2.6-million
call count into a scaling multiplier for these synthetic timings.

A suitable bounded order is one finite correctness gate, then one fixed BCCB
corpus comparison in fresh processes, with no automatic retry and all four
samples retained. A total command allocation must be fixed by the parent from
the remaining shared ledger before starting. Both complete command costs
(including cold builds/new controls) and the unprofiled corpus wall/CPU times
must be retained. No per-lookup clocks belong in that comparison. Any correctness,
ownership, callback-order or statistics failure stops the key nomination. A
candidate that has no repeat-consistent positive corpus effect in both wall and
CPU under the predeclared rule also stops it; do not proceed to private integer
construction or search for a more favorable corpus.

If the key-only corpus passes, it establishes only that this exact key design
has a useful bounded effect on that corpus. It does not establish actual-word
savings, a scale factor, or enough complete gain. The next source-specific cost
plan must still debit nonzero integer retained work, nonzero key retained work,

It must not set the original 4.68-second integer region to zero or count the
