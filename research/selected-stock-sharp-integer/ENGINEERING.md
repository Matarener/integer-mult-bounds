## Power of Ten inspection

1. New code has no recursive call. Structured loops and explicit exceptions
   cover every exit; temporary CLI fixtures have scoped cleanup. Python's
   JSON implementation is a platform parsing dependency, not a new recursive
   scientific algorithm.
2. The maximum threshold level is 262144 and the maximum width encoding has
   200000 bits. Forward depth uses at most 400001 steps. The primary finite
   table has 131073 entries, 42 child tests per entry and 32 inverse boundaries.
   Independent loops have 262143 threshold steps and 400001 forward steps.
   Source inventories have at most 16 rows with 1 MiB file limits. The fixture
   enumerates at most 32 package entries and 5 declared inputs; 7 CLI calls
   have 60-second timeouts. Registered commands have explicit 90/120-second
   timeouts. Mathematical quantification is supplied by PROOF.md, not a
   claim that the replay accepts arbitrarily large encodings.
3. Python bigint and collection allocation is a managed-runtime deviation.
   The table, source size bounds and 200000-bit width limit bound scientific
   live data. At most one large threshold and one forward working integer
   coexist. The implementation never forms the enormous stock. A fixed-memory
   proof-kernel implementation would be a separate refinement. No interpreter,
   shared cache or predecessor mode is changed.
4. Every new function is below 60 physical lines. Helpers separate source
   authentication, exact integer certificates and external CLI behavior.
5. Explicit ValueError contracts remain active with -O. They check genuine
   source identity, inverse-depth agreement, contraction, strict inequalities,
   type identity, encoding limits and complete receipt equality. There is no
   assertion-only acceptance path.
6. Mathematical state is local. The independent path imports no primary
   module or receipt. Only package-local Python paths are added for -I;
   predecessor code is never imported or executed.
7. Filesystem and subprocess failures propagate. A nonzero negative-control
   result must contain an explicit ValueError, so a missing interpreter or
   import failure does not count as a scientific rejection. High-level copy
   and write return values in fixture setup are intentionally unused: those
   operations raise on failure, and the subsequent actual CLI checks every
   consumed byte. The subprocess return code and success marker are checked.
8. No eval, generated executable source or runtime code registration occurs
   in acceptance. A finite package-local import and JSON duplicate-key hook
   are ordinary Python mechanisms. Test-only source mutations are fixed text
   edits in disposable copied fixtures, followed by actual CLI execution.
9. Data access is shallow and direct. The JSON parser's fixed duplicate-key
   callback and subprocess executable boundary are explicit bounded targets.
   No scientific callback dispatch or nested mutable graph is introduced.
10. Validation uses warnings as errors in normal and optimized Python 3.12,
    plus scoped Ruff E,F,B,PLE,PLW,RUF at line length 100. The registered replay
    is the recurring CI hook. A global lint configuration change would widen
    this research package's scope, so recurring lint is recorded as an open
    workflow improvement rather than claimed to be installed here.

The source binding authenticates the exact five consumed files. It does not
replay their transitive historical suites or independently prove the full
caller. The source-byte gate and committed Git-free replay distinguish that
availability claim from the new arithmetic theorem. Fixed-tape allocation,
charged physical time and formal proof-kernel review remain separate.
