This continuation adds cheaper current-output query acquisition, complete
local native consumers, rational source codes, and a concrete future-code
routine. Its BIT follow-up proves large algebraic compression, implements
an early paired consumer and an isolated two-helper fragment, and gives
exact .004 acquisition budgets. **No new multiplication κ is admitted.**

Start with [REPORT.md](REPORT.md) for a programmer-oriented explanation of
the remaining gap and [LITERATURE.md](LITERATURE.md) for the ranked primary
sources and their actual use. Each component has a local proof, generator
and reproducible receipt. New work includes substantial OpenAI assistance;
independent agent checks are not independent human review or formal proof
verification.

## Reproduce

From the repository root, using Python 3.12, NumPy and Node.js:

```sh
python3 research/kappa-next-regime/validate.py --output /absolute/path/to/kappa-next-validation.json
```

The default run authenticates this package, regenerates its declared
results in a fresh relocated copy, compares exact proof-relevant JSON
including decompressed native words, and runs the retained predecessor's
scoped 21-stage replay. It does not fetch network data, edit frozen source,
run the historical selected multiplication release engine, or update a
selected result. Do not pass `-O`: one retained lifting probe uses assertions.

Use `--new-only` only when deliberately omitting the predecessor replay.
`REPLAY-PLAN.json` enumerates every regenerated result and its claim scope.
`INTEGRITY.json` covers source and reference files; `VALIDATION.json` records
the delivered fresh run. Gzip container hashes are not substituted for
comparisons of their complete decompressed mathematical payloads.
Every stage deletes its declared outputs before execution, compares the
fresh outputs, then restores their frozen bytes for downstream source
bindings. This avoids mistaking gzip container metadata or display-only
floating formatting for a change in a mathematical input.
