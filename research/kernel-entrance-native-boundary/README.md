# Kernel-entrance native boundary after XOR normalization

**A fresh finite native replay now covers PR #1179's nonzero helper entrance,
an active retained alias, and the binding from kernel selection to the actual
word.** The two positive fixtures pass the original native legality and
five-stage formal-column checkers with their correct COPY contracts. The
independent source-word model agrees with every local cost field.

The local replay on 2026-10-17 passed with CPython 3.12.14, GCC 13.3.0, Linux
x86-64, and genuine upstream Boost 1.85.0. [RECEIPT.json](RECEIPT.json) records
`PASS_KERNEL_ENTRANCE_NATIVE_COMPOSITION`. This completes a finite native
handoff from [PR #1179](https://github.com/CrocSwap/integer-mult-bounds/pull/1179),
whose native 5/9/11-stage replay was explicitly unrun. Native nine/eleven-stage
execution and physical supplier admission remain open. The selected frontier
and kappa are unchanged.

## Exact object and new evidence

Adam Gall's archived [kernel entrance](../bit-kernel-entrance-seed18/README.md)
changes the helper coordinates of the selected PR #589 word. Helper 444 starts
at frame 79, the line of label 77. Helper 470 receives a decoding shear at that
frame and its restoring shear at the full frame. Equal raw target-response
columns let the constructor remove 55 compensation reads of helper 444.
The predecessor already proves the resulting 53-ADD and one-unit local rank
saving, arbitrary-dirt restoration, and its restricted sparse-kernel census.
Those are credited inputs here.

Philipp (`mightyOil`)'s [PR #1253](https://github.com/CrocSwap/integer-mult-bounds/pull/1253)
subsequently completed the fixed-word common-entrance classification for all
binary support sizes. The same `444 + 470` direction is its unique survivor
under the fixed first-contact contract. This package does not repeat that
classification or search for additional supports.

This package combines three concrete methods: source-bound public
normalization, an independently reconstructed algebraic/rational-frame model,
and fresh execution of the original C++ consumers. Its useful additional
boundary is a **nonempty kernel declaration tied to the actual transformed
word**. Changing only the declared partner to helper 223 leaves the valid
record stream unchanged and is accepted by the original native legality
checker. The independent model rejects it and proves that it is not a kernel
pair: its raw target response differs on 53 rows. At target register 111,
helper 444 has coefficient 0 and helper 223 has coefficient 1.

That is a scoped separation between predicates. Original native legality
explicitly delegates kernel/bank obligations to other checks; this is not a
counterexample to a complete supplier or a failure of the selected word.
The new caller binds the declaration to the source-derived construction.

## The executed composition

[verify.py](verify.py) first runs the unchanged public
[PR #3273 boundary](https://github.com/CrocSwap/integer-mult-bounds/pull/3273) on a zero-entrance input.
It separately exports the exact normalized word that will reach the
constructor and requires **all three export artifacts to be byte-identical**
to the public CLI's artifacts. It then calls the authenticated PR #1179
`construct` function on that word, exports the candidate through the unchanged
original exporter, and invokes the original native consumers.

[independent_model.py](independent_model.py) imports no predecessor
implementation. It independently reconstructs normalization `N` and the fixed
gauge `G`, verifies complete-word equality `N(G(w)) = G(N(w))`, and binds the
candidate to `G` of the actual constructor input. The ordinary candidate's
canonical SHA256 must also equal the parsed predecessor certificate's
`candidate.payload_sha256`:

```text
9e3840f625233859f54e180dba17986a3b2a7b49fc1262c328623d1db16e0351
```

The two executed positive fixtures are:

| Fixture | Construction | Required native COPY count |
|---|---|---:|
| `kernel` | Public normalization of the frozen word, then the archived entrance gauge | 9 |
| `active_alias` | Append slot 9 naming helper 472; transfer target 113's slot-0 read to three slot-9 occurrences; normalize, then apply the same gauge | 10 |

After normalization, the active alias has 62 genuine uses of slot 0 and one
genuine use of slot 9. It preserves the helper-level target map and incurs a

A third public-boundary control appends two absent slot-0 occurrences to row
0. It produces the same three public exports and the exact same complete
candidate as `kernel`; the receipt explicitly reuses the corresponding native
evidence instead of claiming a third native execution.

### The original zero-entrance contract remains enforced

The changed candidate is also passed to the original public CLI, which
rejects and publishes no output. That CLI transports only the delegated

The new caller applies the public boundary before changing the entrance. It
does not alter or disable that guard, and it does not grant the candidate
selected H2 or unchanged H1-H5 admission.

## Reproduce and source closure

Use Python 3.12, a C++17 compiler, the official Boost 1.85.0 headers, and the
corresponding complete upstream archive. No third-party Python package is
required. From the repository root:

```sh
python3.12 -I -O -B research/kernel-entrance-native-boundary/verify.py \
  --boost-include /absolute/path/to/boost_1_85_0 \
  --boost-archive /absolute/path/to/boost_1_85_0.tar.bz2 \
  --workdir /tmp/kernel-entrance-new \
  --output /tmp/kernel-entrance-new.json
```

The work directory and output receipt must be new. `--compiler` selects an
alternative compiler command. For already-fetched Git objects, add
`--git-sources --source-root /absolute/path/to/checkout`; otherwise the source
files are read from the supplied/default repository root and authenticated
by their exact bytes. The runner writes a success receipt only after every
expected acceptance, expected rejection, invoice binding, and source check
passes. This is a dedicated native replay, not registered in the Python-only
package workflow. The inherited Python subprocesses are launched without
`-O` and retain their assertions.

[SOURCES.json](SOURCES.json) pins fourteen repository files by commit, Git
blob, SHA256, and byte count. They cover the frozen word, checker, exporter,
stager, C++ sources/header, normalizer, prior native harness, and archived
constructor/certificate/provenance. Each is copied into a private snapshot
and rechecked after execution. The three new executable files and source
manifest are also hashed before and after the replay. Frozen packages are
unchanged, and no support search is rerun.

The Boost archive is the
[official 1.85.0 source archive](https://archives.boost.io/release/1.85.0/source/boost_1_85_0.tar.bz2),
with SHA256
`7009fe1faa1697476bdc7027703a2badb84e849b7b0baad5086b087b971f8617`.
The exercised run authenticates all **182 compiler-observed Boost headers**
against that archive and checks a 779-bit unbounded-integer product. This
does not reuse the earlier checked-128-bit stand-in. Compiler, Python,
runtime, and standard-library headers are observed environment dependencies,
not a hermetic toolchain bootstrap. Native executables and temporary outputs
remain in the disposable work area.
