# Equivalence of the integer subset join

This contribution was produced by Nick Petalas. Apache-2.0.

## Predicate

Let L_0,...,L_5 and H_0,...,H_3 be rational triples. Let c_0,...,c_5 be
nonnegative integer multiplicities. The predicate required for each target H is

    H in {sum_i u_i L_i : 0 <= u_i <= c_i, u_i integer}.

This is membership in a set of possible exponents. It is not a count of
representations or a sum of coefficients modulo two. Repeated labels and
cancellation of different representations must preserve existential membership.
The predecessor uses precisely this predicate in its concrete regression.

The implementation accepts six labels, four targets, three coordinates,
sum c_i <= 8, and rational numerators and denominators of at most 256 bits.
The algebraic equivalence below holds without these finite resource bounds.

## Integer join

Take D to be the least common multiple of every denominator in the six labels
and four targets. In particular, target denominators participate. Multiplication
by the positive integer D is injective on rational triples and maps all ten
vectors to integer triples. Define

    O = {sum_(i=0..3) u_i D L_i : 0 <= u_i <= c_i},
    N = {sum_(i=4..5) u_i D L_i : 0 <= u_i <= c_i}.

The full scaled subset set is exactly O+N. Every six-tuple of multiplicities
splits into one four-tuple and one two-tuple, and every such pair recombines
into a legal six-tuple. Consequently

    H is in the original set  iff  some n in N has D H - n in O.

`integer_vectors`, `subset_sums` and `support_mask` implement these three
operations using exact Python integers. Sets remove duplicate values on both
sides of the equivalence. Negative coordinates, zero counts, repeated labels
and targets with denominators absent from the labels require no exceptions.
No parity reduction, rounding, probabilistic hash or numerical tolerance is used.

## Complete replay adapter

`run.py` authenticates the exact predecessor source and every declared external
input before compiling that source. A fresh module has the predecessor's actual
file path, so its own input authentication uses the original repository layout.
The baseline calls its unchanged `main`. The accelerated mode replaces only its
`direct_support_regression` function.

The replacement preserves the original outer profile order, the direction grid,
primitive-direction filter, sorted rational scale set, rank-one checks, target
conjunction, exact-lattice test for each support survivor, and returned counters.
`concrete_splits` copies the original inventory construction, credited to Josie
Elliston. Its only extracted responsibility is emitting the same concrete labels.
The proved join replaces the full rational subset-set expression. All other
functions, symbolic support classification, source checks, eight-call control,
target mutation and denominator control execute their original source bytes.
`source.TARGETS` is read at each predicate call; no result cache can retain an old
target or split. Unknown source revisions fail authentication.

Under successful execution and the authenticated source's stated domain, every
concrete support decision and every subsequent lattice call therefore agrees.
The complete output agrees as well. This is a scoped program-equivalence
argument. It neither reproves nor independently accepts the predecessor theorem.

## Finite corroboration and performance boundary

`verify.py` compares every four-bit support mask in the complete concrete
inventory with a separately written literal Fraction enumeration, then executes
the complete accelerated predecessor command. It also checks small rational
fixtures and input/source rejections. `RESULT.json` is generated by that command;
it binds the implementation and input manifest by SHA256. Default replay checks
the receipt and writes no files.

`benchmark.py` starts a fresh complete process for each side in five or more
alternating pairs. Timing includes source authentication, imports, every check,
captured output and process completion. Every return code, stderr and complete
stdout is checked. It records individual nanosecond timings, environment and
code hashes. It does not reuse subset results across processes. Profiling is a
separate diagnostic run, excluded from the reported timings. Hosted conformance
does not certify a local machine's performance percentage.

## Resource bounds and implementation constraints

The four old-label subset loops have at most 81 iterations, and the two added
loops at most 25, by the total-multiplicity bound of eight. Each target checks at
most 25 integer differences. Denominator clearing visits exactly 30 coordinates.
There are at most 442 profiles; each profile's scale generator has at most
sum_(m=2..40)(m-1)=780 iterations, or at most 17*9 direction candidates. The
generic conformance grid has 4^6 candidate multiplicities. Benchmarking permits
five through nine pairs, with a 300-second timeout per complete process.

New code has no recursion, persistent cache, network call or background process.
All new functions fit within 60 lines. Explicit exceptions retain checks under
optimized Python. Warning-strict normal and optimized execution and AST parsing
are the diagnostics; no separate static type analyzer is claimed.

Power-of-ten rule 3 deviation: CPython allocates integers, Fractions, sets and
modules dynamically. The new join has at most 106 stored subset triples, with
integer bit lengths below 8192 under its enforced generic input bound. The
concrete generator stores at most 780 splits at a time. Source files are capped
at one MiB each. Runtime allocation internals are not instrumented. A fixed
allocation implementation is required before using this reference in an
allocation-prohibited runtime.

Rules 8 and 9 deviation: the adapter executes one hash-authenticated predecessor
module and calls its fixed helper functions. This is required to run the actual
unchanged complete checker without editing frozen evidence. No CLI-supplied
code or module name is accepted. All external source paths are declared in
VERIFY.json and authenticated. A future different source requires a new pin and
equivalence assessment. The predecessor's preexisting lattice loops and long
`main` remain frozen; this package makes no new resource-compliance claim about
that retained implementation.

The verifier's complete reference enumeration intentionally uses Fractions to
avoid depending on the proposed denominator-clearing mechanism. It has at most
144 multiplicity tuples per concrete split under the source's total bound of
seven, and uses the same finite split inventory. This extra conformance work is
verification overhead; it is not included as part of the accelerated scientific
command being compared with the original scientific command.
