# Complete positive-frame replay in less time

This contribution was produced by Nick Petalas. Apache-2.0.

Claim type: **measured verifier improvement with a scoped equivalence proof
and finite conformance checks**. No new kappa is claimed.

An exact integer subset join reduces the complete PR #6111 command's local
median elapsed time from 29.031 s to 8.290 s, **71.4% less**.
All ten fresh commands emit the same 787 bytes, with zero errors. The frozen
predecessor checker and its mathematical result remain Josie Elliston's work.
This package contributes the accelerator, its equivalence proof and measurement.

| Complete command | Median | Range | Runs |
| --- | ---: | ---: | ---: |
| Original predicates | 29.031 s | 28.521–30.837 s | 5 |
| Integer subset join | 8.290 s | 8.190–8.394 s | 5 |

[BENCHMARK.json](BENCHMARK.json) is generated by five alternating baseline/fast
pairs on CPython 3.12.15, macOS arm64. Timing includes fresh process startup,
source authentication, all original checks and controls, output and exit.
Other processes were active on this 18-core host. This is a single-host result,
not a cross-platform performance guarantee or a new mathematical bound.

## What changes

The concrete scan originally constructs every rational six-label subset sum.
The new calculation clears all label **and target** denominators once, builds
integer subset sets for four old labels and two added labels, then tests
membership by subtraction. The inventory, rank-one checks, exact lattice
filters, source checks and remaining complete command execute unchanged.
A separate profile placed 84.219 of 102.461 instrumented seconds in the concrete
scan. The instrumented run is excluded from the benchmark. Repeated Fraction
multiplication and addition were the measured bottleneck.

[PROOF.md](PROOF.md) proves the membership equivalence, including repeated
labels, negative coordinates, zero multiplicities and different target
denominators. `run.py` authenticates the fixed external source bytes before
compiling them. It changes one function in a fresh module. No source file or
persistent cache is changed, and a changed input fails its source pin.

## Evidence

The generated [RESULT.json](RESULT.json) binds the new implementation and input
manifest. The verifier compares all four target decisions on **46,916 concrete
splits** against a separately written literal Fraction enumeration. Those are
conformance cases for the new implementation, not a new predecessor census.
It also checks 420 small rational cases and seven input/source rejections,
then runs the complete accelerated source checker and checks its full output.
Normal and optimized verification are registered in VERIFY.json.

The complete output SHA256 is
`429df60e41b623420af1af7119a0734a6686e3a0b4bd75e360317ea3b8efe15c`.
Every timed output has that hash. No non-success command is included as a fast
sample. The generator records every return code, stderr length and elapsed time.
The standard join technique itself is not claimed as a new algorithm.

## Reproduce

From the repository root, using CPython 3.12 and the standard library:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/positive-frame-subset-join/run.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/positive-frame-subset-join/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -O -W error -B research/positive-frame-subset-join/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/positive-frame-subset-join
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/positive-frame-subset-join --check-source-history
```

Another machine can substitute its CPython 3.12 path. Add `--baseline` to run.py
for the original predicates. To rerun the timing experiment, use `benchmark.py
--pairs 5 --output PATH` with a chosen output path outside the checkout. The
benchmark is opt-in; CI runs conformance rather than asserting a machine speed.
The standalone adapter and verifier also work in the official Git-free export
with the declared inputs. Receipt regeneration is explicit `verify.py --write
PATH`; default replay writes nothing.
