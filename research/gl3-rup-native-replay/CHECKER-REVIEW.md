## Flags and acceptance

`-U` sets rupOnly (main line1421). After a failed reverse-unit-propagation check, redundancyCheck returns FAILED before the RAT fallback (lines657-661). The default mode is backward UNSAT checking; it validates the dependency core needed for a detected contradiction and can skip unused proof additions. Thus the scoped statement is a successful RUP refutation-core check. Do not claim that every unused input proof line has independently passed a RUP check or that a second checker algorithm was used.

`-t N` assigns atoi(N) to timeout (line1405). The clock starts before parsing, but its test appears only in the backward verification loop (lines900-905), comparing integral wall-clock seconds with a strict greater-than test. Parsing and the initial forward pass are not independently deadline-polled. Native execution therefore needs an external process wall timeout as well as a positive internal limit. Do not pass proof optimization `-O`, which explicitly ignores the timeout while optimizing.

Require native exit0 AND an exact standalone `s VERIFIED` status line. Reject timeout, memory/parser error, NOT VERIFIED, DERIVATION, abnormal signal, missing status or incomplete wrapper result. Exit0 alone is insufficient: timeout, many allocation/parser failures and help all exit0. Conversely an input containing an explicit empty clause takes the parse-trivial path printing VERIFIED without assigning sts=UNSAT, so main returns1; do not use that case as the success control or relax the paired gate to accommodate it. Ordinary input-UP contradictions can also succeed without needing any proof; use a non-UP positive control.

Use argv order `checker CNF PROOF -U -t N`: main opens argv[1] and argv[2] rather than the current positional loop item. Keep native assertion checks enabled. A suitable portable MacClang build is `clang drat-trim.c -std=c99 -O2 -Dgetc_unlocked=getc -o checker`; retain source and compile logs, actual compiler/platform, argv, binary hash and exit. The alias changes byte-reading synchronization, not the intended parser byte values or proof logic. That assertion still needs ASCII and binary native controls. Do not use NDEBUG, source edits or architecture-specific optimization flags to obtain a result.

## Parser and EOF trust boundary

The checker is not a strict serialization validator. The ASCII parser can skip nonnumeric material; proof EOF ends parsing even with a partial final clause. A valid prefix that already produces a checked contradiction may be enough without a final explicit empty proof line. This behavior does not itself make an UNSAT refutation unsound, but it prevents a claim that successful status validates every trailing byte as a well-formed proof transcript.

The binary reader detects EOF before a new varint, but has no explicit continuation-length/overflow validation for an EOF partway through a varint (lines983-996). Malformed inputs can therefore reach unsafe integer/parse behavior. This source review does not establish memory safety or general hostile-input parsing correctness. Authenticate the exact expected proof bytes before execution; strictly validate the actual ASCII proof container independently (integer range, zero termination, deletion syntax, counts and no partial record), and use only tiny valid binary fixtures for binary calibration. Native ASCII scanning uses C `%i`, so the validator must require canonical decimal tokens (`0` or `-?[1-9][0-9]*`), excluding leading-zero/octal, hexadecimal and other spellings whose Python integer interpretation could differ. The original formula must likewise match exact regenerated/authenticated counts/hash and valid DIMACS before replay. A timeout or malformed-input crash is a failed control, never success evidence.

## Small controls that test the intended implication

1. **Nontrivial ASCII RUP positive.** Formula is all four sign combinations of the binary clause `(±1 ±2)`, header `p cnf 2 4`; proof is `1 0\n0\n`. The formula has no initial unit propagation, while the derived unit1 is RUP and yields a contradiction. Require the paired success gate with `-U`.
2. **Binary parser positive.** Same formula; proof bytes are `61 02 00 61 00` in hexadecimal (`a`, positive literal1 encoded2, zero, `a`, zero). Require the same paired gate under actual auto-detection (and optionally forced binary). This verifies the locked-getc portability path consumes the same bytes.
3. **Invalid proof.** On that non-UP formula, proof `0\n` alone must fail. The formula's semantic UNSAT is insufficient for this submitted RUP step. An empty/unterminated proof is another optional parser calibration, without requiring the checker to reject a valid contradiction prefix.
4. **Wrong formula.** Remove `(-1 -2)` from the binary square; the remaining three clauses are satisfied by1=2=true. The same claimed refutation must fail. Retain this explicit satisfying assignment to establish the negative expectation independently.
5. **Required RAT-only lemma.** Formula is every one of the eight `(±1 ±2 ±3)` clauses, header `p cnf 3 8`. Proof `1 0\n2 0\n0\n`: unit1 is RAT but not RUP, since assuming¬1 leaves the complete binary square with no UP conflict; its RAT resolvents are RUP. After unit1, unit2 is RUP and causes conflict. Full checker should succeed with at least one RAT lemma in its actual core, while `-U` must fail. This uses a required core lemma; an unused fresh-variable RAT addition could be skipped by backward checking and would be a weak discriminator.
