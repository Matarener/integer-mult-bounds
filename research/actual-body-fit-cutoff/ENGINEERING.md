# Scope and verification

The exit predicate is one published, independently replayable arithmetic result
with exact sources, a proof, meaningful rejection controls and a clean released
worker. No physical backend, frozen input or selected-frontier file changes.

Build the Lever made the exact certificate and separate census the reviewable
artifacts. Prove It Works requires execution of the actual committed Git-free
export in addition to registered verification and source-history checks. These
principle leaves and Power of Ten were read this session. No extra thread or
subagent was created. The source-level theorem is distinct from human or formal
acceptance, which remains unclaimed.

## Power of Ten inspection

1. All changed control flow is iterative. No recursive calls or callback cycles
   are introduced. CLI failure and timeout propagate through scoped temporary
   storage; byte restoration runs in finally.
2. Depth accepts n<=2^20 and permits at most 2*bit_length(n)+1 steps, at most
   43. The inverse staircase permits 64 steps and returns after crossing 2^20.
   Finite slab loops have at most 65 entries. The independent forward recurrence
   permits 44 steps, digit tables have 22*2*15 trials, and the census has exactly
   1048575 widths with two predicates each. JSON files are at most 256 KiB,
   inputs at most 1 MiB each, source rows at most 16, package members at most
   32, object keys at most 256 and every child CLI has a 30-second timeout.
   The registered controls have a 60-second timeout. A failure is not a pass.
3. Python allocation uses the explicit deviation below. Fixed input bounds
   limit live tables and counters; the census hashes rows as a stream instead
   of storing a million decisions. No GL64 payload, q^U or huge stock is
   materialized. The largest explicitly formed coefficient has d=22; the
   largest independent q power has exponent at most 15.
4. All 22 functions fit below 60 physical lines after formatting. The measured
   maximum is 33 lines. The external function-length receipt records each.
5. ValueError contracts enforce the actual theorem inequalities, interval
   coverage, primality witness, source hashes and complete typed receipt.
   Independent counts and its entire decision hash are also checked.
   These checks remain active with -O. No assertion supplies an acceptance gate.
6. State is local except for immutable constants and the standalone package
   path. The worker has an exclusive process-held advisory lock. Shared Git
   mutations and peer reservation writes have separate scoped advisory locks.
7. CLI exits, positive output, mutant changes, copy counts and restoring writes
   are checked. Source failures reject explicitly. Hash updates and print have
   no result to consume. Standard-library exceptions propagate. Files close
   through context managers. No repair or regeneration flag weakens acceptance.
8. There is no dynamic code generation, eval, runtime registration or hidden
   source import. JSON is data. The primary imports one fixed local module.
9. No dispatch registry or predecessor runtime is loaded. Direct functions and
   shallow row dictionaries expose all arithmetic state. The independent oracle
   imports neither primary code nor its receipt.
10. Validation uses Python warnings as errors, normal and optimized registered
    commands, scoped Ruff E,F,B,I,UP,PLE,PLW,RUF and formatting at line length
    100. E402 marks only the explicit isolated-mode local import. Compile
    diagnostics run without writing bytecode into the checkout.

## Explicit deviations

Rule: 3, fix memory capacity before steady operation.
Location: all four checker files and their standard-library calls.
Reason: CPython integers, JSON, lists, hashlib and tempfile allocate dynamically.
Scope: bounded host arithmetic replay, not an implementation of the tape caller.
Compensating control: the preceding file, integer, iteration and subprocess
limits; one synchronous temporary export and one child at a time; streaming
census digest; context-owned cleanup. Export copies are exclusive owned regular
byte copies with different device/inode pairs. No metadata/mode copying occurs.
Verification: registered normal/optimized commands, actual optimized CLI controls
and actual committed-export runs. Runtime identity is measured before and after.
Follow-up: a production fixed-role realization retains the existing Count-tape
selector and its separate full setup/refinement obligations. This checker is
not substituted for that implementation.

Rule: 10, enable maximum diagnostics on every build.
Location: scoped development lint and VERIFY.json.
Reason: the isolated package does not own the repository's global lint policy.
Scope: current package verification. Hosted CI acceptance remains unclaimed.
Compensating control: all registered Python commands use -W error; exact scoped
Ruff and formatting checks are retained externally, with actual committed-byte
and source-history checks before publication.
Verification: registered, lint, format, final-head and export receipts.
Follow-up: recurring repository-wide lint needs a separate impact review.

## Preserved diagnostics

digit thresholds agree at every depth. Its product-bound rejection was retained.
The corrected oracle encloses each predicate separately. Both censuses then
have 802809 fitted widths and final failure 245766. This correction does not
alter the depth-15 boundary proof. Original and corrected run receipts remain
in the external session directory; earlier failures supply no acceptance coverage.

The card's baseline command rejected an omitted selected complex package in
sparse checkout. That source-orientation limitation is retained; no selected
construction replay is claimed. The first expanded Ruff pass required explicit
check=False for intentionally inspected child exits and pairwise for adjacent
slabs. Both were fixed. No diagnostic suppression was added for either.
