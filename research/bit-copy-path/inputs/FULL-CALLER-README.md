# Full recursive BIT caller: the opportunity cost of a cheaper COPY

Apache-2.0. Substantial OpenAI Codex assistance.

The saved 100-job COPY consumer integrates into the complete nine-stage
Boolean caller, but it does **not** improve the complete recursive query
bill over the best ordinary caller constructed here. A stronger result
explains why: in a relaxation permitting every allocation of the fixed
whole-helper inventory, donating a rank-four helper to these COPY queries
strictly worsens the optimum for every exponent `0<b<1`.

This is a source-bound finite integration and a written allocation theorem.
It is not an installed all-size physical supplier, a formal-kernel proof,
an achieved multiplication exponent, or a global lower bound on BIT.

## What the complete integration changes

The actual retained R438 program has 433 full rank-eight helpers, five
rank-four helpers, nine native COPY episodes and a noncommuting internal
query word. The predecessor construction borrowed 100 partial helpers
across 32 calls to turn 100 actual rank-seven COPY completions into rank
three. Its closed stage-zero invoice was strictly cheaper.

The new schedules retain all nine stages: 288 local calls, 126,144 helper
roles and 71,040 idle endpoints. They postpone the predecessor's early
idle completions to the original public caller times and assign every
later helper on an explicit native mask. Internal noncommuting queries
remain in their literal order. Exact reverse helper entries, arbitrary
dirty values, COPY cleanup, bridges and final public exchanges are retained.

Let `r` be a displaced host's final ordinary remainder after **all** later
helper use. The complete per-job histogram change is

```text
e_(r+4) + e_3 - e_r - e_7, with e_0 omitted.
```

For the tariff `Phi_b(r)=r(64/r)^b`, it saves query cost exactly when
`r>3`. Filling that host completely gives `e_4+e_3-e_7`, a strict
increase for every `0<b<1`, and one additional recursive child.

| Later use of the displaced hosts | Exact 100-job change | Matched result |
|---|---|---|
| Unrestricted; final ordinary remainder 0 | `100(e4+e3-e7)` | Larger bill and 100 more children |
| At most 16 later coordinates; remainder 8 | `100(e12+e3-e8-e7)` | Smaller bill than its own restricted reference |
| No later use; remainder 24 | `100(e28+e3-e24-e7)` | Smaller bill than its own frozen reference |

The last two policies retain the local saving but lose better packing
elsewhere. Exact truncated-rank sums prove that **all three consumer
profiles have a larger complete recursive tariff than unrestricted
ordinary reuse, for every `0<b<1`**. This comparison includes the inherited
bad-residue surcharge. It is not a measured machine-runtime comparison.

See [the complete owner proof](schedule/PROOF.md),
[all six witnesses](schedule/WITNESS.json), and
[independently recounted invoices](bounds/INVOICES.json).

## A whole-inventory theorem

The unchanged public caller has 21,312 idle bins of rank 7 and 14,208 each
of ranks 14, 28 and 42. Across its 288 local calls it supplies 124,704
whole rank-eight helpers and 1,440 whole rank-four helpers.

Grant arbitrary reallocation, remove chronology and call conflicts,
allow fractional multiplicities of legal integer bin patterns, and make
all adapters, fallback, routing, precision and storage overhead free.
These concessions can only favor an upper ceiling on the attainable
query exponent.

If `k` rank-four helpers complete COPY7 queries to rank3, the exact optimal
relaxed full histogram is

```text
H*(k) = 288 Hlocal
        + 21312 e7 + 14208 e6 + 12768 e4
        + (67872/5) e2 + (3168/5) e42
        + k(e4+e3-e7),                 0 <= k <= 1440.
```

The proof gives matching primal and dual solutions. An exact reduction
of all 64 legal patterns to 13 hull vertices proves dual feasibility for
every `0<b<1`. Since `Phi_b(4)+Phi_b(3)>Phi_b(7)`, every donor strictly
increases this optimum. Keeping the helper to eliminate an entire
rank-four idle query is more valuable than reducing COPY7 to COPY3.

The same dual also proves this opportunity-cost result throughout a
resource regime: for bin counts `C7,C14,C28,C42`, full-helper inventory
`F` between `C14+3*C28` and `C14+3*C28+5*C42`, and partial inventory
`0<=D<=C28`. It is therefore not an isolated numerical property of the
288-call witness. Available distinct COPY jobs and the same whole-helper
and bin contracts remain premises.

The zero-donor relaxed exponent satisfies

```text
0.001743393260913 < b_relaxed < 0.001743393260914.
```

The fixed-stock ceiling remains valid after discounting every good-path
query cost by `1-10^-16` and granting all bad packets zero cost.
This additional check avoids treating rare fallback packets as though
they necessarily incur the full good-path tariff.

Exact point certificates extend the ceiling to additional full-progress
helper banks **under the explicit tariff premise that their completion
cost is at least the remaining rank**. No free-bad-packet discount is
applied to that bank premise. Independently useful partial outputs or
unconstrained physical bank implementations are outside this extension.

[The full proof](bounds/PROOF.md) includes the resource equations,
all-parameter inequalities, exact interval certificates and negative
controls. A separate [integer-root checker](independent/check_inventory.py)
derives the source inventory independently and verifies a weaker ceiling
at `b=1/573`, without the logarithm/exponential engine.

## Consequences for κ

The best constructed ordinary query profile has a charged exponent in
`(0.001742200652684,0.001742200652686)`. The consumer with unrestricted
reuse is lower, in `(0.001742059196608,0.001742059196610)`.
The protected-host consumer profiles are lower still.

The ordinary R438 profile improves the query screen over the selected
R439 BIT endpoint by about 0.506%. That comparison is conditional on
missing native implementation premises, and the new consumer is not
responsible for it.

The pinned selected assembly has
`kappa=0.001672660197076918` and binds on the complex supplier. Substitution
of any of these six BIT screens leaves that selected κ unchanged; all
47 retained outer inequalities are checked.

Even with an ample complex supplier, the necessary outer inequality
`kappa < b/(1+b)` and the optimistic ceiling above permit less than a
4.047382% gain over the pinned selected record. They exclude a 10% gain
for the **entire fixed mechanism**, before charging its missing
implementation costs. This is a ceiling, not an achieved improvement.

## Native costs and remaining physical boundary

The 100 rank-three complements have exact dyadic charts valid in every
odd prime-power ring. On its good branch, a positive rank-r child uses
the pinned generic adapter's `2[r(127-r)+4096] f` affine slots; a zero
remainder uses no child or adapter. Unrestricted host reuse therefore
adds **824,000 f** good-adapter slots as well as 100 recursive children.
The two protected
policies save 8,000 f and 33,600 f relative to their own references, but
their full query profiles already lose to ordinary reuse.

All six schedules retain 28,416 public families, the inherited nine-family
private reserve, 10,369,440 local ADDs, 63,936 bridge ADDs and 2,592
COPY/ERASE episodes per common cover class. The operation counts multiply
by the cover size; physical family stock does not. Complete packet
volume, spectators, held consumer packets, routing, descriptors, physical
head returns and parking remain charged.

An exact whole-caller signed scalar calculation gives the bound
`2^18 * 1874 * 1302^4 * 1446^4 < 2^113` for unit-bounded inputs at
completed primitives. This does **not** admit an overall 128-bit rounded
recursive implementation.

The existing physical Catalogue hardcodes the old word, private slot,
replica-symmetric owners and whole-call order. It has not been adapted
here. Its complete source/packet ABI, faster chart routing, rounded
precision and concrete tape/storage installation remain open.
The unfavorable necessary query ceiling does not require those
costs to be free in a real implementation: granting them for free only
makes the negative conclusion stronger.

See [the native proof and ledger](native/PROOF.md). A positive supplier
claim would require closing those implementation obligations.

## Open next questions

* Can an actual local query path be removed or shared, changing `Hlocal`?
  The first useful step is an exact arbitrary-dirty operator witness for
  one concrete COPY/ADD interval, including its source reads and inverse
  cleanup. The obstruction here applies while that complete local
  histogram remains fixed.
* Can a required partial-progress output absorb the exported helper's
  progress? Start with a caller that already demands that exact output
  projector, and price its entrance, terminal and later lifetime. An
  unused new output would not change the obstruction.
* Can the ordinary R438 query profile be installed as a native supplier
  for an independent reason? Adapt the concrete Catalogue and routing
  grammar first, then verify complete volume, rounded precision and
  parking. Its modest BIT improvement still needs an improved complex
  supplier before it can improve the selected κ.
