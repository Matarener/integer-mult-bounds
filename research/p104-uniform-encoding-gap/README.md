# Uniform completion against the physical P104 encoding

**Scoped commutation obstruction. No new κ and no selected-frontier change.**
Selected κ stays `0.001672660197076918`.

PR #3954 shows that a common address operator commutes with the scalar-bank
encoding `E0`, because that encoding's blocks are scalar matrices. The handoff
in discussion #1166 comment 19034066 records the consequence that was left
open: uniform completed transforms commute with scalar bank encodings, and
that fact alone does not give a matched physical caller. The requested
construction is an adjacent completed-call pair. This package does not build
that pair.

It separates the scalar encoding from the physical one. For

```
E0(r, w) = (D r + H w, w),    L(r, w) = (D r + H T w, w),
```

`U_C` commutes with `E0` for every address operator `C`, and commutes with `L`
exactly when `C` commutes with every active port chart `T_p`. The literal slot
swap `Pi` commutes with every `U_C`, so `Pi L` fails for the same operators as
`L`. On the four-point translation model, `Z_{e1}` commutes with `E0` and with
`C_{e2}`, and it fails for `C_{e1}` on both `L` and `Pi L`. The address
commutator entry is `2-2i`.

Charts generated by translations still commute with each other, so a uniform
completion that stays in that family is not blocked here. The written argument
is in [PROOF.md](PROOF.md).

## Reproduce

CPython 3.12, standard library, from the repository root:

```sh
python3.12 -B research/p104-uniform-encoding-gap/verify.py
python3.12 -B research/p104-uniform-encoding-gap/independent.py
python3.12 -B research/p104-uniform-encoding-gap/test_verify.py
python3.12 -B scripts/research_package.py --package research/p104-uniform-encoding-gap
```

`verify.py` multiplies the 16×16 Gaussian-integer matrices.
`independent.py` does not import it; it applies the same maps to vectors.
`test_verify.py` rejects an even-direction chart offered as an obstruction.

## Open next questions

1. Which operators does one actual completed P104 call apply uniformly? If
   they all lie in the translation algebra, this commutator does not block
   that call, and the adjacent-pair search has to move elsewhere. The first
   step is to read the retained caller at one completed role and name the
   operator. That caller text is not pinned in this package.
2. The adjacent completed-call pair from comment 19034066 is untouched. Its
   entrance and exit still have to match on every data and helper role, with
   a physical intertwiner and a full bill. This commutation gap does not
   supply that pair, and it does not prove that no such pair exists.
