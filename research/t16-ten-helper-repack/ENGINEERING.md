# Verification decisions

Build the Lever shaped the artifact: a deterministic generator and a separate
direct reconstruction replace reliance on a solver nomination. Prove It Works
required the actual eleven-stage strict admission and complete typed invoice,
which caught stale candidate chart metadata. The source predicate stayed fixed.

Power of Ten inspection covers the new generator, direct reconstruction and
behavioral controls. Loops range over at most 69,120 roles, 240 patch rows,
43 input pins, 112 ports, 16 replicas or eight fixed rotation roles. Input reads
are capped at 32 MiB. No recursive traversal is introduced. Source and result
invariants use active `need` checks, including under optimized Python. The strict
inherited admission requires assertions enabled. Functions are below 60 lines.
Imports target explicit authenticated local sources. Exceptions propagate.

Rule 3 deviation: Python allocates managed objects during reconstruction and
exact rational arithmetic. The fixed role/input dimensions and bounded reads
bound live collections; subprocess replay has a 300-second timeout and bounded
archive/member sizes. Read-only replay and rejected mutation controls exercise
cleanup. A fixed-allocation runtime would require a separate implementation.

Rule 8/9 deviation: the unchanged source loader uses Python importlib to load
three named, hash-authenticated moment/outer engines and the independent owner
checker. No input selects arbitrary code. Retained predecessor source is kept
byte-for-byte for attribution and audit; it is evidence rather than a second
live generator. Replacing this loader belongs to a separately reviewed replay
interface change.

Rule 10: run Python with `-Werror`, Ruff E/F/B/SIM on new live code, normal and
optimized behavioral controls, registered Python 3.12 replay and committed
source-byte/history preflight. Frozen inherited code retains its existing
style and checks. Hosted CI, full cold native reconstruction and formal-kernel
verification are not claimed.
