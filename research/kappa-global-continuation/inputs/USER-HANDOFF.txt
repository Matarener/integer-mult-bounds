## 2. The new mechanism uses the actual helper dependence

The most productive change was to stop treating the omitted core as depending only on \(Rx\).

Literal replay of the actual word gives a query of the form

\[
q=Rx+Hh,
\]

and an omitted-centre transfer

\[
y\longmapsto y+x-Kq.
\]

Here \(H\) depends on **106 actual helper roles**. Their native entrances and exits make it possible to use this dependence in a changed local contract. Those helpers are arbitrary state; they are not clean registers.

### A dyadic encoding with no target repairs

Write \(z=(x,h)\), let \(Ez=x\), and define

\[
Q=[R,H],
\qquad
K_e=\begin{pmatrix}K\\0\end{pmatrix}.
\]

There is a helper-supported dyadic right inverse \(P_e\) with

\[
QP_e=I.
\]

For the actual source, \(RK=14I\). Set

\[
D=I+(12P_e-K_e)Q.
\]

Then

\[
Q(12P_e-K_e)=-2I,
\]

so

\[
D^2=I.
\]

Because \(P_e\) is supported on helper coordinates,

\[
ED=E-KQ,
\qquad
(E-KQ)D=E.
\]

This gives the exact local pair

\[
F_D(z,y)=(Dz,\;y+EDz),
\]

\[
B_D(z,y)=(D^Tz-E^Ty,\;y)=F_D^{-T}(z,y).
\]

The existing helper contribution becomes part of an invertible encoding. Both literal programs remove all eight centres, with **no replacement native children** and no odd-denominator division.

Both providers pass all **632 input columns**. Each orientation has local rank mass **5070** and a charged scalar allowance of **168,592 real primitives**. The cost is a changed helper endpoint: the forward program changes eight helper roles, and the backward program changes 106. A complete supplier must account for those values through later uses and eventually restore the required outputs. The construction and checks are in README.md[controller/README.md](sandbox:/workspace/scratch/6176c9cb9609/live-source/research/kappa-consumer-followup/artifact/integer-mult-bounds/research/kappa-consumer-followup/controller/README.md).

### A stronger symmetric encoding on 128 ports

I then constructed a Gaussian dyadic helper normalization that puts the relevant query matrix into the form

\[
\widehat R=[R,\;4I_8,\;8iI_8].
\]

Using the **bilinear transpose**,

\[
\widehat R\widehat R^T
=56I_8+16I_8-64I_8
=8I_8.
\]

Consequently,

\[
D_{\mathrm{sym}}
=I-\frac14\widehat R^T\widehat R
\]

satisfies

\[
D_{\mathrm{sym}}^T=D_{\mathrm{sym}},
\qquad
D_{\mathrm{sym}}^2=I.
\]

All coefficients are Gaussian dyadic. No square roots or division by 13 are needed.

Promoting sixteen helper coordinates to the source bank and sixteen suitable kernel coordinates to the target bank produces these actual local endpoints:

\[
F(z,w)=
\bigl(D_{\mathrm{sym}}z,\;w+D_{\mathrm{sym}}z\bigr),
\]

\[
B(z,w)=
\bigl(z-w,\;D_{\mathrm{sym}}w\bigr),
\qquad z,w\in\mathbb C^{128}.
\]

Both directions pass on both actual providers, with:

- **128 source ports and 128 target ports**.
- **376 arbitrary helpers restored**.
- The same total of **632 independent input columns**.
- Local rank mass **5070** and no replacement children.
- Scalar allowances of **172,250 forward** and **181,578 backward**.
- Scalar prefix ceilings of **124 and 128 bits**, below the retained 192-bit scalar cap.

A separate review checked the newly added Gaussian operations against the literal native frame sequence and found no local algebra or placement defect. The complete emitted programs and receipts accompany symmetric_extended.py[symmetric_extended.py](sandbox:/workspace/scratch/6176c9cb9609/live-source/research/kappa-consumer-followup/artifact/integer-mult-bounds/research/kappa-consumer-followup/baseline/symmetric_extended.py).

Two distinctions matter for using this result.

First, the transpose is not the conjugate transpose. Indeed,

\[
\widehat R\widehat R^*=136I_8.
\]

The bilinear involution identity does not establish a unitary norm bound. The finite scalar bounds were checked separately.

Second, the sixteen additional port labels are **zero**. Their inherited helper paths have \(I\to\mathrm{FULL}\) frames. Ordinary norm-one data ports have different native entrance and exit contracts. Thus this is a concrete 128-port local component, but the existing 112-port controller cannot simply be relabelled to consume it. These points are explicit in SYMMETRIC-EXTENSION-REVIEW\.md[SYMMETRIC-EXTENSION-REVIEW.md](sandbox:/workspace/scratch/6176c9cb9609/live-source/research/kappa-consumer-followup/artifact/recovered-involutory/SYMMETRIC-EXTENSION-REVIEW.md).
